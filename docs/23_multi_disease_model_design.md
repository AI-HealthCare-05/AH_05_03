# 다질환 예측 모델 설계

> 작성일: 2026-08-21 (Sprint 2)
> 짝 문서: [14_multi_disease_datasets.md](14_multi_disease_datasets.md) — 이 설계의 근거가 된 데이터셋 조사
> 결정 대상: `../../docs/DESIGN.md` §17 **A3(대상 질환 2개 vs 6개)** · **A4(종합 건강 지수)** · **A5(예측 기간 5년)**

## 0. 세 문장 요약

"고혈압만 잘 동작한다"는 관찰은 성능 순위와 반대다 — 당뇨 모델이 모든 연령 구간에서 낫고, 정작 **고혈압 모델은 혈압을 입력으로 아예 받지 않는다.** 진짜 문제는 세 가지다: 질환 커버리지 구멍(규칙 4개 vs ML 2개 vs 시안 6개), 절대확률 표시, 그리고 코드 레벨 결함 4건. 그래서 설계는 **새 데이터를 기다리지 않고 규칙·ML·공개공식 세 엔진을 중재하는 계층**을 세워 9/14 배포 데드라인 안에 7개 영역을 화면에 올리는 쪽으로 잡았다.

## 1. 진단 — 왜 고혈압만 잘 동작하는 것처럼 보이는가

### 1.1 성능은 반대다

`modeling/artifacts/diagnose_targets.json`(2021–2023 주기 홀드아웃) 실측치.

| 구간 | 당뇨 | 고혈압 |
|---|---:|---:|
| 전체 | **0.810** | 0.796 |
| **미진단자만** | **0.776** | 0.727 |
| 19–40세 | **0.800** | 0.731 |
| 40–50세 | **0.804** | 0.688 |
| 50–60세 | **0.741** | 0.706 |
| 60–70세 | **0.775** | 0.676 |
| 70세+ | **0.711** | 0.629 |

모든 구간에서 당뇨가 낫다. 판별력을 기저율로 나눈 리프트로 보면 격차가 더 벌어진다 — 당뇨 AUPRC 0.442 / 기저율 0.174 = **2.54배**, 고혈압 0.699 / 0.419 = **1.67배**.

고혈압 70세+ 0.629는 동전 던지기에 가깝다. **개선이 필요한 쪽은 고혈압이고, 그중에서도 고령이다.**

### 1.2 정작 혈압을 무시하는 건 고혈압 모델이다

번들에서 직접 확인했다.

| | `risk_dm.json` | `risk_htn.json` |
|---|---|---|
| 필수 입력 | 나이·성별·BMI·주관적건강 | 같음 |
| 선택 입력 | 10개 — **`sbp`·`dbp` 포함** | 8개 — **`sbp`·`dbp` 없음** |

`train_risk.py:70`이 고혈압 타깃의 `blocked`에 `sbp`·`dbp`를 넣는다. 고혈압 라벨이 `SBP≥140 or DBP≥90`으로 정의되니 라벨 누출을 막는 정당한 조치다. 그런데 결과는 이렇다 — 54세 남성 기준으로 혈압을 미입력에서 118/74, 145/95, 175/110으로 바꿔도 **고혈압 확률이 49.25%에서 소수점까지 고정**이다.

사용자가 "고혈압이 잘 맞는다"고 느낀 그 카드가, 사용자의 혈압을 한 번도 읽지 않았다.

### 1.3 그럼 왜 그렇게 보이는가 — 표시 메커니즘 셋

**기저 유병률.** NHANES 고혈압 유병률이 41.9%, 당뇨가 17.4%다. 그래서 평범한 50대 남성이 고혈압 45.0% / 당뇨 18.5%를 받는다. 모델은 두 질환에 **같은 말**(둘 다 동년배 이하)을 하고 있는데, 45%는 사람 눈에 "반반, 경계선"으로 읽혀 규칙 엔진의 "전단계"와 맞아 보이고 18.5%는 "낮음"으로 읽혀 부딪힌다.

**동적 범위.** 필수 입력 4개를 300조합으로 스윕한 결과 — 당뇨 확률 폭 0.43~54.18%(53.8pp), 고혈압 3.49~90.08%(**86.6pp**). 고혈압 숫자가 1.6배 크게 움직여서 "반응하는 모델"로 읽힌다.

**확률과 배지의 모순.** 같은 스윕에서 **확률 50% 이상인데 배지가 "동년배 이하"인 조합이 고혈압에서 79/300 = 26.3%, 당뇨에서는 0건**이다. 70대 남성은 고혈압 확률 80%를 봐도 배지가 "동년배 이하"다 — 그 연령대의 상위 10% 경보 컷이 87.5%이기 때문이다.

### 1.4 진짜 원인은 커버리지 구멍이다

데모 화면이 실제로 보여주는 것.

| 질환 | 규칙 엔진 | 서빙 ML | BRFSS 11질환 | 화면 |
|---|---|---|---|---|
| 고혈압 | ✅ 대한고혈압학회 | ✅ 0.796 | ✗ **타깃 없음** | 확률 + 등급 |
| 당뇨 | ✅ 대한당뇨병학회 | ✅ 0.810 | ✅ 0.791 (미연결) | 확률 + 등급 |
| 이상지질혈증 | ✅ 한국지질·동맥경화학회 | ✗ | ✗ | **"모델 없음"** |
| 비만 | ✅ 대한비만학회 | ✗ | ✗ | **"모델 없음"** |
| 대사증후군 | ✗ | ✗ | ✗ | 카드 없음 |
| 지방간·신기능 | ✗ | ✗ | ✗ | 카드 없음 |
| 심근경색·뇌졸중·COPD 등 9개 | ✗ | ✗ | ✅ (미연결) | 카드 없음 |

**BRFSS 11질환 모델에는 고혈압 타깃 자체가 없다.** 사용자가 본 것은 데모 화면의 `risk_dm`/`risk_htn`이 맞다.

화면 절반이 "모델 없음"인데 고혈압·당뇨 두 칸만 숫자가 차 있고, 그중 하나가 규칙 엔진과 맞아 보인다. **"고혈압만 잘 동작한다"는 정확히 이 화면의 서술이다.** 모델 성능에 대한 서술이 아니었다.

## 2. 코드 레벨에서 확인된 결함 4건

전부 저장소에서 직접 재현했다. 새 데이터 없이 고칠 수 있다.

| # | 결함 | 위치 | 증상 |
|---|---|---|---|
| 1 | **당뇨 모델의 `dbp` 계수가 음수** | `risk_dm.json` `numeric__dbp = -0.1640` | 이완기 혈압을 올리면 당뇨 확률이 내려간다. 118/74 → 145/95에서 16.45% → **16.32%**. 2기 고혈압 입력이 당뇨 위험을 낮춘다 |
| 2 | **`veg_fruit_daily`가 유령 입력** | `app/dtos/predictions.py:39` | DTO는 받는데 두 모델 어디에도 없다. 예/아니오 모두 결과 변화 0.0pp |
| 3 | **참조표 설명이 낡았다** | `export_model.py:218` 하드코딩 | `reference_note`가 "NHANES 25,457명"인데 실제 `trained_rows`는 **40,926**이다. 이 문자열이 `/api/v1/predictions/model-info`로 사용자에게 나간다 |
| 4 | **연령 경계에서 백분위 절벽** | `app/services/risk.py:38` `PEER_AGE_EDGES` | 같은 사람이 59세 → 60세가 되면 고혈압 확률은 56.55% → 61.80%로 **오르는데** 백분위는 66.8 → **33.5로 떨어진다.** 참조 셀이 바뀌기 때문 |

부수적으로 하나 더. 참조표는 학습 행을 포함한 인샘플 분포다(`export_model.py:235` docstring이 그렇게 밝힌다). 백분위 문구를 손보는 김에 out-of-fold로 다시 만드는 게 맞다.

## 3. 설계 — 3엔진 + 중재 계층

```
[클라이언트] → POST /v1/assessments/summary   (신규, 단일 진입점)
                        │
              app/services/assessment.py  ← 중재자 (신규, 이 설계의 핵심)
                        │
        ┌───────────────┼───────────────────────────┐
     E1 규칙          E2 ML                       E3 공식
 chronic_disease_   app/services/risk.py     app/services/formula.py (신규)
   engine/          risk_dm·risk_htn.json      score_*.json + 상수 JSON
   (vendored,       순수 파이썬 내적           순수 파이썬
    수정 금지)
 고혈압·당뇨·       "검사받으면 기준을         대사증후군 카운트,
 이상지질혈증·비만   넘을 가능성"               eGFR(CKD-EPI 2021),
 국내 학회 지침      (발병 확률 아님)           HSI 지방간, 한국인
                                              당뇨 점수(Lee 2012)
```

### 3.1 왜 질환별 독립인가 — 멀티태스크를 쓰지 않는 이유

**라벨 누출 차단 집합이 질환마다 다르다.** 당뇨는 FPG·HbA1c를, 고혈압은 SBP·DBP를, 이상지질혈증은 지질 4종을 각각 막아야 한다. 멀티태스크로 묶으면 어느 한 타깃의 금지 피처가 다른 타깃에서는 허용되는 상황이 공유 표현 안에서 뭉개진다.

게다가 서빙이 JSON 계수 + 순수 파이썬 내적이다. 공유 은닉층을 파이썬으로 재현할 이유가 없다.

### 3.2 왜 종합 지수를 만들지 않는가

vendored 규칙 엔진이 "4개 영역을 하나의 종합 점수로 합치지 않는다"를 설계 원칙으로 못 박았다(`engine.py` docstring). **DESIGN.md §17 A4의 종합 건강 지수는 이 릴리스에서 보류로 확정하고**, 링 게이지는 "7개 영역 중 n개 판정 완료" 진행 표시로 대체한다.

### 3.3 중재 규칙 — 서버가 결정한다

지금은 이 판단을 데모 화면의 클라이언트 JS가 하고 있다. 서버로 올려 질환마다 `owner`(정본 엔진)와 `fallback`을 테이블로 못 박는다.

| 질환 | 검사값 있음 | 검사값 없음 |
|---|---|---|
| 고혈압 | **E1 규칙** (정본) | E2 ML (선별 안내) |
| 당뇨 | **E1 규칙** (정본) | E2 ML + **E3 한국인 점수** 2개 병기 |
| 이상지질혈증 | **E1 규칙** | E2 ML 선별 (P1) |
| 비만·복부비만 | **E1 규칙** | 키·몸무게만 있으면 항상 E1 |
| 대사증후군 | **E3** (5요소 카운트) | 부분 카운트만 표시 |
| 지방간 | **E3** (HSI) | 표시하지 않음 |
| 신기능 | **E3** (eGFR) | 표시하지 않음 |

응답에 질환마다 `engine`, `engine_reason`("혈압을 입력해 규칙 판정으로 대체함"), `superseded_by`를 싣는다. 지금 데모의 안내 로직을 안내가 아니라 **기본 표시 순서로 승격**시키는 것이다.

### 3.4 등급을 한 체계로 통일한다

ML은 3단계(low/moderate/high), 규칙은 5단계(NORMAL/CAUTION/HIGH/VERY_HIGH/INSUFFICIENT_DATA)를 쓰고, 두 체계에서 "주의"가 서로 다른 등급을 가리킨다. DESIGN.md §17 A1이 지적한 것과 같은 사고다.

중재 계층에서 **규칙의 5단계를 정본**으로 삼고 ML 백분위를 사상한다(≥90 → HIGH, 70~90 → CAUTION, 그 외 NORMAL, 참조표 없으면 INSUFFICIENT_DATA). vendored 코드는 건드리지 않고 어댑터에서만 변환한다.

### 3.5 문제를 다시 이름 붙인다 — 이 설계의 핵심 한 줄

라벨 누출 차단은 유지한다. 그러면 "검사값을 바꿔도 확률이 안 움직인다"는 필연이다.

**답은 라벨을 바꾸는 게 아니라 문제를 다시 정의하는 것이다.** ML 타깃을 "당신은 당뇨입니다"가 아니라

> **"지금 검사받으면 진단 기준을 넘을 가능성"**

으로 정의한다. 그러면 혈당을 입력에서 빼는 것이 누출 방지의 부작용이 아니라 **문제 정의 그 자체**가 된다. 코드는 한 줄도 안 바뀌고 라벨 정의도 그대로인데 `description` 문자열과 화면 문구만 바뀐다. 그리고 검사값이 들어온 순간 정본이 규칙 엔진으로 넘어가므로, ML이 혈당을 무시한다는 사실이 사용자 앞에 드러날 일 자체가 사라진다.

**남는 구멍은 정직하게 적어둔다.** 검사값을 0개 낸 사용자에게 ML 당뇨 확률은 여전히 혈당에 반응하지 않는다. 그 사람이 혈당을 입력하지 않았으니 문제가 드러나지 않을 뿐이다. 이 병리를 실제로 없애는 방법은 발병 라벨로 가는 것 하나뿐이고, 그건 §9의 C안이다.

## 4. 질환별 엔진 소유권 — DESIGN.md §17 A3 결정문 초안

| 질환 | 등급 | 엔진 | 라벨·기준 출처 | 근거 |
|---|---|---|---|---|
| 고혈압 | P0 | rule + ml | 대한고혈압학회 / NHANES `label_htn_prevalent` | 카드 문구를 "고혈압 위험도"에서 **"혈압을 재면 기준을 넘을 가능성"**으로 바꾼다. 화면 성능 수치는 미진단자 AUROC(0.727)를 쓴다 |
| 당뇨 | P0 | rule + ml + **score** | 대한당뇨병학회 / NHANES / **Lee 2012 (KNHANES 유래, 검증 AUC 0.73)** | 한국인 점수를 3번째로 붙인다. 입력 6개가 전부 검사값이 아니라 **검사값 없는 사용자에게 한국인 근거 숫자를 하나 더 준다** |
| 이상지질혈증 | P0 | rule | 한국지질·동맥경화학회 5판(2022): TC≥240 / LDL≥160 / TG≥200 / HDL<40 | 지질 4종을 입력하면 판정, 없으면 카드를 안 그린다 |
| 비만·복부비만 | P0 | rule | 대한비만학회 2022 8판. BMI 6단계, 허리 남≥90/여≥85 | **예측 대상이 아니다.** 측정값을 임계값과 비교하는 일이고 규칙 엔진이 이미 한다. 한국 기준(BMI 25부터 비만)을 화면에 병기 |
| **대사증후군** | **P0** | **rule/공식** | NCEP-ATP III 개정(2005) 5요소 + 허리둘레만 한국 기준 | **이 노선에서 가장 싼 확장이다.** 규칙 엔진이 5요소를 **이미 전부 받고 있어 신규 입력이 0개**다 |
| 지방간 (MASLD) | P1 | 공식 | **HSI** = 8×(ALT/AST) + BMI + 2(여성) + 2(당뇨). 한국인 10,724명, AUROC 0.812 | AST·ALT 2개만 추가. 둘 다 검진 결과지에 인쇄된다. **국내 유병률 47.2%라 경보가 아니라 지수 값으로만 표시** |
| 신기능 저하 의심 | P1 | 공식 | CKD-EPI 2021 race-free. 크레아티닌 1개 추가 | 라벨명은 `label_egfr_low_single_measure`, 화면은 **"신기능 확인 필요"**. KDIGO의 3개월 지속 요건을 단면으로 못 채우므로 "CKD"라 부르지 않는다 |
| 이상지질혈증 ML 선별 | P1 | ml | NHANES TCHOL(84.1%) + BPQ(지질강하제) | 라벨을 단일 이진이 아니라 **하위유형별**로 나눈다. 어느 지침도 "이상지질혈증" 단일 이진 라벨을 정의하지 않는다 |
| 심뇌혈관 10년 | **P2 보류** | — | KRPM(Jee 2015) 또는 PREVENT | **보류.** KRPM은 논문에 기저 생존율 S0가 없어 재현 불가이고, 대안 PCE는 한국 남성 위험을 56.5% 과대추정한다 |
| 우울 | **제외** | — | PHQ-9 | **예측 대상이 아니다.** 9문항을 물으면 그게 곧 답이다. 넣는다면 위험도 카드가 아니라 자가 체크 기능이고, 9번 문항(자살사고) 양성 시 위기상담 프로토콜이 반드시 따라와야 한다 |

## 6. 학습 계획

**새 데이터 취득 0. 새 승인 0.** 이미 받은 NHANES 8주기와 파일 한 줄 추가로 끝난다. 학습이 필요한 작업은 셋뿐이다.

**(1) 당뇨 모델 재학습 — `dbp` 제거.** 계수가 음수인 상태를 끝낸다. 대안은 맥압(SBP−DBP) 또는 평균동맥압 단일 항. `export_model.py` 한 번 실행. **판정 기준**: `dbp` 계수가 사라질 것, AUROC 변화 0.005 이내, 혈압을 올렸을 때 당뇨 확률이 더 이상 내려가지 않을 것.

**(2) 한국 유병률 재보정.** 학습이 아니라 사후 보정이다. 국민건강통계·KOSIS의 연령·성별 유병률 집계표를 받아 Platt 보정 뒤에 셀별 절편 오프셋을 하나 더 얹는다. `sigmoid(a·logit + b + kr_offset[cell])`. 단조 변환이므로 **AUROC와 백분위 순위는 변하지 않고 확률 수준만 한국 인구로 옮겨간다.**

> **주의 — 심판이 지적한 함정.** "12셀 예측 평균이 KOSIS와 ±5%p 안"이라는 합격 기준은 오프셋을 그 기준에 맞춰 적합시키므로 **구성상 항상 통과한다. 검증이 아니다.** 대신 리포트 첫 줄에 "재보정 전후 AUROC가 소수점 셋째 자리까지 같다"만 적는다. 재보정은 맞게 만드는 일이 아니라 **덜 틀리게 만드는 일**이다.
>
> 그리고 재보정이 성립하려면 참조 유병률의 라벨 정의가 `labels.py`(SBP≥140 or DBP≥90 or 진단 or 투약)와 같아야 한다. **다르면 재보정이 새 편향을 넣는다.** 착수 전에 대조한다.

**(3) 이상지질혈증 선별 모델 (P1).** 라벨은 TC≥240과 HDL<40 두 개를 따로. 차단 피처는 TC·HDL·진단·지질강하제. `BPQ` 파일 추가 필요.

**학습하지 않기로 하는 것 — 명시적으로 남긴다.**

| 항목 | 이유 |
|---|---|
| 대사증후군·지방간·eGFR ML | 라벨 정의 검사값을 다 빼면 **남는 피처가 인구통계뿐**이다. 규칙·공식으로 간다 |
| 심뇌혈관 10년 발생 | 단면 데이터에 10년 뒤 사건이 관측된 행이 한 줄도 없다 |
| 우울 | PHQ-9은 물으면 그게 답이다 |
| **합성·더미 데이터** | [14번](14_multi_disease_datasets.md) §8. 표본을 두 배 늘려도 AUROC가 0.002 움직였다. 천장은 표본이 아니라 정보량이다 |

**공개 공식(E3)에는 학습이 없다.** 대신 **우리 데이터에서 재현 검증은 한다** — Lee 2012 배점표를 NHANES에 적용해 AUROC를 재고, HSI를 NHANES에 적용해 `LUX`(FibroScan CAP) 기준 AUROC를 잰다. 원 논문 값과의 차이가 곧 **인구 이식 손실**이고, 그 숫자를 모델 카드에 적는다.

## 7. 서빙

**제약: sklearn·numpy·pandas 런타임 의존 없음. JSON 계수 + 순수 파이썬 내적. 무저장·무인증. 이 구조를 깨지 않는다.**

```
modeling/artifacts/models/
  risk_dm.json         기존 로지스틱 번들 (RiskModel)
  risk_htn.json
  risk_dlp.json        P1 신규 — 같은 포맷, 같은 클래스
  score_dm_kr.json     신규 — 점수표형 (ScoreModel, 신규 클래스 ~60줄)
  formula_consts.json  신규 — 임계값·계수 상수 (CKD-EPI, HSI, MetS)
  calibration_kr.json  신규 — 연령·성별 유병률 재보정 오프셋
```

**주의 하나.** `RiskModelRegistry._load()`는 `risk_*.json`만 글롭하고 `bundle['target']`을 키로 쓴다. `score_*.json`은 이 글롭에 안 걸리므로 **별도 로더 경로가 필요하다.** 지금 구조가 그대로 확장되지 않는다는 점을 착수 전에 알고 있어야 한다.

**번들 스키마 확장 (구 번들 호환).** `RiskModel`은 `platt`·`reference`를 `bundle.get()`으로 읽으므로 신규 optional 키는 기존 번들 로딩을 깨지 않는다. 다음을 추가한다.

```
population                 학습 인구 (예: "US NHANES 2005-2023 adults")
threshold_source           임계값 근거 학회·연도
label_definition_text      라벨 정의 원문
holdout.auroc_undiagnosed  미진단자 AUROC — 화면에 쓰는 값
reference_population_note  참조표 산출 표본 (하드코딩 제거)
horizon_years              현재 전부 null
label_kind                 "prevalent" | "incident"
```

마지막 둘은 지금 넣으면 비용이 0이고, 나중에 발병 라벨로 갈아탈 때 `probability`의 의미가 조용히 바뀌는 사고를 미리 막는다.

**API.**
- 신설 `POST /v1/assessments/summary` — 온보딩 입력 한 벌 → 질환별 통합 결과. **화면이 붙는 곳은 여기 하나다.**
- 유지 `/v1/predictions/risk`, `/v1/assessments/rules` — 디버깅·비교용
- `/model-info`의 쓰이지 않는 `bands` 필드를 "참조표 없을 때만 쓰는 대비값"으로 라벨링

**배포는 지금과 같다.** `export_model.py` 실행 → JSON 갱신 → 레지스트리가 mtime을 보고 다시 읽는다. 컨테이너 재시작이 필요 없다.

## 8. 평가 계획

AUROC 하나로 판단하지 않는다. 이 릴리스에서 고쳐야 할 것이 판별력이 아니라 보정과 표시이기 때문이다.

| # | 항목 | 기준 |
|---|---|---|
| 1 | 판별력 | 전체 AUROC와 **미진단자 AUROC를 항상 병기.** 화면에 찍는 수치는 미진단자 쪽 |
| 2 | **보정 (주 지표)** | 질환별 ECE(10분위)·보정 기울기·절편. 재보정 전/후를 나란히 저장 |
| 3 | 하위집단 | 연령 6구간 × 성별 2 = 12셀에서 AUROC·ECE·경보율. 70세+ 고혈압 0.629가 이미 알려진 구멍 |
| 4 | 운영점 | **Youden J를 쓰지 않는다.** 목표 PPV 0.30을 만족하는 최소 임계값, 상위 5%/10% 알림 예산에서의 PPV·민감도. 성별로 분리 |
| 5 | **엔진 간 일치도 (릴리스 판정 기준)** | 검사값이 모두 있는 NHANES 행에서 규칙 판정 × ML 등급 혼동행렬. **목표는 일치율이 아니라 불일치 유형의 파악이다** |
| 6 | 공식 엔진 검증 | Lee 2012·HSI를 NHANES에서 재현. eGFR은 단위·반올림 골든 케이스 20건 |
| 7 | **표시 회귀 테스트** | 아래 참조 |
| 8 | 실패 기준 | 공개 스코어의 한국인 이식 손실이 AUROC 0.65 아래면 그 스코어를 화면에서 뺀다 |

**7번이 이번 릴리스에서 가장 중요한 테스트다.** 사용자 불만에 대한 직접 계약이므로 골든 픽스처로 박는다.

- **FPG 88 → 150으로 바꾸면 `/v1/assessments/summary` 응답이 실제로 달라진다** (규칙이 정본으로 올라오므로)
- **SBP 120 → 155로 바꾸면 고혈압 결과가 달라진다**
- 59세 → 60세 경계에서 백분위 절벽이 없다 (인접 셀 차이 ≤ 5%p)
- 확률 45%인데 배지가 NORMAL인 경우 설명 문구가 함께 나온다
- 검사값을 전부 비웠을 때 카드 4개가 모두 회색이 되지 않는다

**계수 부호 검사를 CI에 넣는다.** 임상 상식과 반대 부호가 나오면 학습이 실패하게 한다. 지금 `risk_dm.json`의 `numeric__dbp = -0.164`를 실제로 잡는다.

**성공 판정 지표를 착수 전에 합의받는다.** 이 릴리스의 성공은 AUROC가 아니라 **① 엔진 간 일치도 ② 보정 ③ 표시 회귀 테스트 통과** 셋이다. 이걸 미리 못 박지 않으면 "AUROC가 안 올랐다"로 평가받는다.

게이트 셋: `dbp` 계수가 사라질 것, AUROC 변화 0.005 이내, 부호 검사 통과. **재보정 오프셋이 어느 셀에서든 미리 정한 크기를 넘으면 재보정을 넣지 말고 "미국 NHANES 기준" 표기를 붙인 원본을 그대로 배포한다** — 혼합물보다 정직한 원본이 낫다.

### 9/12~9/14 — 동결과 배포

4주차 항목(AST·ALT·γ-GTP·크레아티닌 입력 추가 → 지방간·신기능)은 **1~3주차가 일찍 끝났을 때만** 넣는다. 아니면 9/15~9/20 배포 후 개선으로 민다. 프런트 작업이 붙어 있어 리소스가 없으면 통째로 밀린다.

> **정직하게 적어둔다.** 이 계획은 4주짜리가 아니라 **3주짜리로 평가해야 한다.** 4주차는 데드라인 밖이다. 1~3주차만으로도 대사증후군까지는 화면에 올라간다.

## 10. 검토했다가 미룬 두 노선

세 안을 독립적으로 설계하고 채점했다.

| 안 | 실현성 | 정직성 | 제품 적합 | 부담 | 총점 |
|---|---:|---:|---:|---:|---:|
| **A — 3엔진 중재** (채택) | 9 | 9 | 9 | 4 | **23** |
| B — KNHANES 국내 기준 재정렬 | 5 | 9 | 7 | 8 | 13 |
| C — CHARLS 발병 예측 전환 | 3 | 9 | 5 | 10 | 7 |

### B — KNHANES 기반 국내 기준 재정렬

국내 학회 기준으로 라벨을 다시 정의하면 규칙 엔진과 ML의 판정 기준이 **처음으로 일치한다.** 지금은 미국 기준 라벨 vs 한국 지침이라 구조적으로 어긋나 있다. 정직성은 가장 높았다 — "AUROC는 안 오를 것이다, 성공 지표는 두 엔진 일치도와 보정이다"를 착수 전 합의사항으로 못 박은 것이 세 안 중 가장 성숙한 문장이었다.

미룬 이유는 일정과 미확인 변수명이다. `load_knhanes.py`가 없고 `HE_glu`·`HE_chol` 같은 이름이 하나도 검증되지 않았다. B 스스로 "잘못 매핑해도 코드는 정상 종료하고 라벨도 만들어진다, 유병률이 이상해질 때까지 아무도 모른다"고 적었는데, 그 단계가 임계 경로 한복판에 혼자 놓여 있다.

**다만 §1의 HN24 발견이 이 계산을 바꿀 수 있다.** 팀이 KNHANES 원시자료 전체를 이미 받았다면 신청·승인 단계가 통째로 사라지고 남는 것은 변수 매핑뿐이다. 그래서 8/21의 0번 작업이 중요하다.

**B에서 지금 가져오는 것**: 임계값 출처를 코드에 서명(`reviewed_by`), 번들에 인구·출처 메타 추가, "성공 지표는 AUROC가 아니다"라는 사전 합의, "한 번에 한 가지만 바꾼다" 규칙.

**킬 조건**: 9/1까지 KNHANES 검사값이 손에 없으면 이번 학기 추적을 끊고 NHIS 검진정보 CSV로 대체한다.

### C — CHARLS 발병 예측 전환

**문제의 뿌리를 유일하게 실제로 건드리는 안이다.** T0 혈당을 특징으로, T1 혈당을 라벨로 두면 누출 차단이 필요 없어진다 — §3.5가 "이름을 다시 붙여" 우회한 그 병리가 구조적으로 사라진다.

미룬 이유는 달력이다. 6~7주면 9/22 데모데이를 넘고 9/14는 한참 지난다. C 자신이 후퇴 조건을 "A안 단독 발표"로 달아 놨는데, 가장 그럴듯한 결말이 다른 안의 발표인 계획은 이번 학기의 노선이 아니라 연구 트랙이다.

그 밖에 — 계획 전체가 아직 재보지 않은 숫자 셋(계정 소요일, 2011∩2015 채혈 교집합, 사건 수) 위에 서 있고, 45세 이상 중국 코호트로 27·38세 페르소나를 덮을 수 없다. 다 잘돼도 §17 A5에 주는 답이 "4년, 중국 45세 이상 기준"이라 시안의 "5년"에는 여전히 못 미친다.

**C에서 지금 가져오는 것**: 표시 회귀 테스트를 수용 조건으로 승격(§8-7), 계수 부호 검사 CI, 응답에 `horizon_years`·`label_kind`, 참조표 out-of-fold 재생성.

**9/22까지 C는 코드를 쓰지 않는다.** 실사 숫자만 표로 남기고, 교집합이 4,000명을 넘으면 발표의 "다음 단계" 슬라이드로 올린다.

## 11. 위험과 한계

| 위험 | 대응 |
|---|---|
| **공개 스코어의 한국인 이식 손실 — 최대 리스크** | PCE는 한국 남성 위험을 56.5% 과대추정한다. 국내끼리도 깨진다 — Korean Diabetes Risk Score가 0.71/0.76 → **0.63/0.66**. ① 같은 질환에 한국인 개발 스코어가 있으면 그쪽(당뇨 Lee 2012, 지방간 HSI) ② 해외 스코어 단독 표시 금지 ③ 검증 인구와 원 논문 AUROC를 화면에 병기 |
| 재현성이 확인 안 된 스코어 | KRPM은 S0가 없고 SCORE2는 "code available on request"다. **심혈관은 P2 보류** |
| 라벨 누출이 네 곳에서 동시에 재현 | 이상지질혈증·대사증후군·CKD·지방간을 **ML로 학습하지 않는다.** 이 결정을 문서로 못 박지 않으면 다음 사람이 같은 함정에 다시 들어간다 |
| **MASLD 유병률 47.2%** | 절반이 양성인 라벨은 "당신은 위험합니다" 화면으로 못 쓴다. 고혈압 41.9%와 같은 구조. **지수 값 + 배제/의심 구간 표시로만** |
| 기준 충돌이 한 화면에서 모순으로 | 여성 HDL 45는 대사증후군 기준(50) 해당, 이상지질혈증 기준(40) 비해당. 카드마다 학회명 병기 + 픽스처로 회귀 테스트 |
| vendored 엔진 수정 금지 | 대사증후군·지방간·eGFR을 규칙 엔진에 못 넣는다. 어댑터는 **계산만** 하고 임계값 상수는 JSON 한 곳에. 어댑터가 규칙 결과를 재해석하지 않게 경계를 긋는다 |
| **재보정이 판별력 문제를 가리는 위장** | 절편을 옮겨도 70세+ 고혈압 0.629는 그대로다. 리포트 첫 줄에 "재보정 전후 AUROC 동일"을 적는다 |
| 엔진이 셋이면 사용자 혼란 | 카드에는 항상 **한 엔진 결과만 크게.** 나머지는 "다른 방식으로 보면" 접기 영역 |
| 화면 작업이 전부 데모 라우터 | `demo_routers.py`는 docstring이 스스로 "제품 화면이 아니다"라고 적어 뒀다. React 앱이 저장소에 없다. **엔진 셋 + 5단계 어댑터를 데모 한 장에 얹는 것이 한계에 가깝다** |
| KNHANES 비상업 라이선스 | 표시 보정에 쓰는 것과 학습 데이터를 갈아타는 것은 파급이 다르다. 상용 전환 시 재확인 |

**반드시 함께 말해야 하는 한계** — [21번](21_modeling_overview.md) §8을 승계하고 둘을 더한다.

1. 학습 데이터가 미국 인구다. 한국인 보정을 하지 않았다
2. 단면 데이터라 **발병 예측이 아니라 유병 선별**이다
3. 반사실 수치는 인과 효과가 아니다
4. 임계값이 임상 검토를 받지 않았다 (`reviewed_by`가 `None`이다)
5. 검사값이 있으면 ML 확률을 읽어서는 안 된다
6. **공개 스코어는 우리가 만든 모델이 아니다.** 화면에 출처와 검증 인구를 병기한다
7. **단면 1회 측정을 "만성"이라 부르지 않는다.** eGFR<60은 "신기능 확인 필요"이지 CKD가 아니다
