## 0. 세 문장 요약

미국 공개 데이터 3종을 합쳐 28만 행 통합 테이블을 만들고, 로지스틱 회귀로 당뇨·고혈압 유병 위험도를 산출했다. 홀드아웃 AUROC는 당뇨 0.841 / 고혈압 0.812이고 연령대 격차는 0.05 이내다. 사용자에게 물어야 할 항목은 **4개**이며, 위험도를 낮추는 신뢰할 만한 지렛대는 **체중 하나**다.

## 1. 왜 해외 데이터인가

국내 데이터를 먼저 조사했고 전부 막혔다. 기록을 남기는 이유는 나중에 다시 시도할 때 같은 벽을 다시 확인하지 않기 위해서다.

| 데이터 | 상태 | 막힌 이유 |
|---|---|---|
| KoGES (OPEN KoGES) | 신청 불가 | IRB 승인서 또는 심의 면제서 필수 |
| AI-Hub 당뇨병·합병증 추적관찰 | 신청 불가 | 안심존 + IRB 심의 결과 통지서 필수 |
| NHIS 건강검진정보 (공공데이터포털) | 미확보 | data.go.kr이 스크립트 접근 차단, 브라우저 수동 다운로드 필요 |
| KNHANES 국민건강영양조사 | 미확보 | 이용 신청서 제출 필요. **IRB는 아니다** — §7.4 참조 |
| 한국의료패널 | 미확보 | 회원가입 후 다운로드 필요 |
| NHIS 표본코호트 2.0 | 배제 | IRB 필수 |
| HIRA 환자표본자료 | 배제 | 심의 + 수수료, 게다가 매년 재표본이라 종단 분석 불가 |
| UK Biobank | 배제 | 신청부터 데이터 제공까지 평균 15주, 현재 신청 일시 중단 |

**IRB가 필요 없는 국내 3종(건강검진정보·KNHANES·한국의료패널)의 로더는 이미 만들어 뒀다.** 파일만 확보되면 바로 붙는다 — `data/load_nhis_checkup.py`, `data/load_khp.py`. 취득 절차는 `data/README.md`에 단계별로 적혀 있다.

## 2. 사용한 데이터셋 3종

### 2.1 NHANES (미국 국민건강영양조사) — 주 학습 데이터

| 항목 | 내용 |
|---|---|
| 출처 | CDC, `https://wwwn.cdc.gov/Nchs/Data/Nhanes/Public/` |
| 취득 | **스크립트 자동 다운로드.** 등록·신청·IRB 전부 불필요 |
| 주기 | 2005–2006 … 2011–2012, 2013–2014, 2015–2016, 2017–2018, 2021–2023 (**8개**) |
| 규모 | 성인 48,895명 (2005–2012 주기별 5,247 / 6,088 / 6,384 / 5,719, 2013–2023 주기별 5,922 / 5,854 / 5,712 / 7,969) |
| 원본 | 주기별 18~21개 `.xpt` 파일, 합계 334MB |
| 강점 | **검진 실측값** — 혈압·공복혈당·HbA1c·지질·크레아티닌. 자가보고가 아니다 |
| 약점 | 미국 인구. 고혈압 가족력 문항이 아예 없음 |

2019–2020 주기는 단독 공개본이 없다(CDC가 2017–March 2020 합본으로 냈다). 2017–2018과 함께 쓰면 같은 응답자가 중복되므로 의도적으로 제외했다.

**주기마다 조사 설계가 다르다.** 하드코딩하면 조용히 틀리므로 로더가 파일을 읽고 감지해서 분기한다.

| 항목 | 2005–2018 | 2021–2023 |
|---|---|---|
| 혈압 | `BPX` 청진식, 최대 4회 측정 | `BPXO` 오실로메트릭, 3회 |
| 고혈압 투약 | `BPQ040A` | `BPQ150` |
| 신체활동 | 긴 GPAQ 형식 (`PAQ650`/`PAQ665` 게이트) | 짧은 여가활동 형식 (`PAD790Q`) |
| 음주 | `ALQ120Q` + 단위 (2017–2018부터 `ALQ121`) | `ALQ121` 빈도 범주 |
| 가족력 | `MCQ300A`/`MCQ300C` 있음 | **없음** |
| 수면 | `SLD010H` → `SLD012` | `SLD012` |
| 보행 곤란 | `PFQ061B` 있음 | **없음** |

2003–2004 이전은 **의도적으로 뺐다.** `GLU`·`GHB`·`SLQ` 가 없거나 다른 이름을 쓴다
(혈당이 `L10AM_B` 같은 실험실 파일에 흩어져 있고 수면 문항은 2005년에 처음 들어왔다).
라벨을 만들 수 없는 주기를 넣으면 표본만 늘고 학습에는 쓰이지 않는다.

### 2.2 CDC Diabetes Health Indicators — 규모 보조

| 항목 | 내용 |
|---|---|
| 출처 | UCI ML Repository dataset 891, `https://archive.ics.uci.edu/static/public/891/data.csv` |
| 원자료 | BRFSS 2015 (미국 전화 설문) |
| 취득 | **스크립트 자동 다운로드** |
| 규모 | 253,680행 × 23변수, 13MB |
| 강점 | 규모가 NHANES의 10배. NHANES에 없는 **채소·과일 섭취**와 주관적 건강 지표 |
| 약점 | **전부 자가보고.** 혈압·혈당 실측값이 없어 측정 기준 라벨을 만들 수 없다 |

주의할 점 하나. 이 데이터의 `Diabetes_binary`는 **전당뇨와 당뇨를 한 양성 클래스로 합쳐 놨다.** NHANES의 측정 기준 라벨과 성질이 다르므로 구분 없이 섞으면 서로 다른 타깃을 동시에 학습한다.

### 2.3 Framingham teaching dataset — 발병 라벨 참고

| 항목 | 내용 |
|---|---|
| 출처 | GitHub 미러 (`GauravPadawe/Framingham-Heart-Study`) |
| 취득 | 스크립트 자동 다운로드 |
| 규모 | 4,240행 × 16변수, 188KB |
| 강점 | `TenYearCHD` — **전향적 10년 발병 라벨.** 즉시 확보 가능한 것 중 유일 |
| 약점 4개 | ① 3자 미러라 출처가 약하다 (정본은 NHLBI BioLINCC, 등록 필요) ② 1948년 미국 매사추세츠 주민 ③ 결과변수가 관상동맥질환이지 당뇨·고혈압이 아니다 ④ `glucose`가 공복 여부 불명 |

**발표·문서에서 "Framingham 코호트"라고 쓰지 말고 "교육용 추출본"이라고 써야 한다.**

### 2.4 통합 테이블

| 출처 | 행 | 라벨 성격 | 검사값 | 당뇨 유병 | 고혈압 유병 | 연령 |
|---|---:|---|---|---:|---:|---|
| NHANES 8주기 | 48,895 | 측정 기준 | 있음 | 17.0% | 41.3% | 19–85 |
| UCI 891 | 253,680 | 자가보고 | 없음 | 13.9% | 42.9% | 21–85 |
| Framingham | 4,240 | 측정 기준 | 없음 | 2.6% | 38.6% | 32–70 |
| **합계** | **306,815** | | | | | |

병합 규칙 세 가지.

1. **ID 중복 없음** — 모든 행이 `<source>:<원본 id>` 형태다. NHANES는 주기마다 SEQN이 재사용되고 나머지 둘은 0부터 시작하므로 원본 id를 그대로 쓰면 조용히 덮어써진다. 검증 결과 306,815건 전부 고유하다
2. **빈 칸은 null** — 어떤 데이터셋이 수집하지 않은 컬럼은 0이나 평균이 아니라 null이다. 대치는 학습 단계에서 기록과 함께 한다
3. **출처가 행마다 따라간다** — `source`, `cycle`, `labels_measured`, `has_labs` 네 컬럼으로 언제든 비교 가능한 부분집합으로 되돌릴 수 있다

62개 정규 컬럼 중 58개에 값이 있고, 세 출처 모두 값이 있는 컬럼은 13개다. 척도가 다른 항목은 공통 축으로 맞췄다.

| 항목 | NHANES | UCI 891 | 통합 방식 |
|---|---|---|---|
| 주관적 건강 | `HUQ010` 1~5 | `GenHlth` 1~5 | 척도가 같아 그대로 |
| 보행 곤란 | `PFQ061B` 1~4 | `DiffWalk` 0/1 | 2 이상 → True |
| 학력 | `DMDEDUC2` 1~5 | `Education` 1~6 | 1~5 서열로 축약 |
| 소득 | `INDFMPIR` 0~5 | `Income` 1~8 | **출처 내부 백분위(0~1)** |

## 3. 라벨 정의

`data/labels.py`의 `Thresholds` 한 곳에 모여 있다. **임계값은 통용 기준을 따랐을 뿐 임상 검토를 받지 않았다** — 화면에 숫자가 나가기 전에 `reviewed_by`를 채워야 한다.

| 라벨 | 정의 | 쓸 수 있는 데이터 |
|---|---|---|
| `label_dm_prevalent` | 공복혈당 ≥126 또는 HbA1c ≥6.5 또는 진단·투약 | 3종 전부 |
| `label_htn_prevalent` | 수축기 ≥140 또는 이완기 ≥90 또는 진단·투약 | 3종 전부 |
| `label_dm_undiagnosed` | 측정치는 기준 초과인데 진단·투약 없음 | NHANES, Framingham |
| `label_htn_undiagnosed` | 동일 | NHANES, Framingham |
| `label_prediabetes` | 공복혈당 100~125 또는 HbA1c 5.7~6.4 | NHANES |
| `label_chd_10yr` | 10년 내 관상동맥질환 발생 | Framingham |

**통합 테이블이 지원하는 라벨은 유병(prevalence)뿐이다.** UCI에 측정값이 없어 미진단 선별 라벨을 만들 수 없다.

라벨 정의에 쓰인 변수는 `features.py`가 입력에서 **기계적으로 제거**한다. 고혈압 모델에서 `sbp`/`dbp`를 빼지 않으면 AUROC가 1.0 근처로 나오고 아무 의미가 없다.

## 4. 작업 내역과 결론

시간 순으로 6단계를 거쳤다. 각 단계의 결론과 근거 파일을 함께 적는다.

### 4.1 데이터 취득·적재

`data/download_nhanes.py`로 8주기 자동 다운로드, `data/load_*.py`로 정규 스키마 변환, `data/build_unified.py`로 통합.

적재 중 잡은 버그 3개. 같은 함정을 다시 밟지 않도록 기록한다.

- **XPORT 0 인코딩** — "0회"가 부동소수 아티팩트(약 5.4e-79)로 저장돼 결측처럼 잡혔다. 신체활동 커버리지가 44%로 보였고, 스냅 처리 후 99%가 됐다
- **컬럼명 주기별 차이** — 중성지방이 옛 주기 `LBXTR`, 최신 `LBXTLG`. 후보 매칭으로 12%→41% 회복
- **이완기 혈압 0** — "청취 불가"를 뜻하므로 결측 처리. 0으로 두면 평균이 망가진다

### 4.2 베이스라인 (`train_baseline.py`)

미진단 선별 라벨로 LR과 XGBoost 비교. 결과는 `artifacts/BASELINE_REPORT.md`.

| 결론 | 내용 |
|---|---|
| 가족력은 값이 없다 | 홀드아웃 고정 비교에서 당뇨 +0.003, 전단계 −0.010, 고혈압 −0.016. 표본이 30% 줄고 최신 주기가 통째로 빠지는데 성능은 제자리다 |
| 예측을 끌고 가는 건 나이 | 표준화 계수에서 나이가 개선 가능한 변수의 2~4배 |
| 60대 이상에서 거의 작동 안 함 | AUROC 0.54~0.65. 주 사용자층인데 가장 약한 구간이었다 |

### 4.3 후속 실험 5건 (`experiments.py`, `compare_models.py`)

결과는 `artifacts/EXPERIMENTS_REPORT.md`.

| 실험 | 결론 |
|---|---|
| 연령 격차 대응 | 상호작용항도 연령대 전용 모델도 개선 없음(±0.015). **모델링 문제가 아니라 정보의 한계** |
| 보정 | 당뇨는 거의 완벽(기울기 1.08). 고혈압은 기울기 0.74로 **상위 구간 과대예측** |
| 운영점 | 당뇨·고혈압 모두 상위 10%가 최적. PPV 10.7% / 23.5% |
| 전단계 타깃 | 상위 5%를 골라도 lift 1.50. **모델이 더하는 값이 거의 없어 제외 권고** |
| LR vs XGB 튜닝 | 베이스라인의 "LR 압승"은 XGBoost 기본값 탓이었다. 얕은 트리로 바꾸니 역전되지만 부트스트랩 95% CI가 대부분 0을 지난다 → **실질 동등** |
| UCI 외부 대조 | NHANES 학습 → UCI 시험 AUROC 0.735 (UCI 내부 학습 0.747). **전이 손실 0.012** |
| TabPFN | 학습 데이터 1/4로 튜닝된 GBDT와 동등. 단 라이선스 게이트·CPU 3~4분·sklearn 충돌로 **서빙 후보 아님** |

### 4.4 통합 위험도 모델 (`train_risk.py`)

유병 라벨 + 통합 테이블 + 결측 지시자. 결과는 `artifacts/UNIFIED_RISK_REPORT.md`.

| 타깃 | NHANES 홀드아웃 | UCI | Framingham |
|---|---:|---:|---:|
| 당뇨 유병 | **0.841** | 0.820 | 0.911 |
| 고혈압 유병 | **0.812** | 0.798 | 0.738 |

**연령대 격차가 목표선 안으로 들어왔다** (당뇨 0.041 / 고혈압 0.049). 무엇이 격차를 닫았는지 변수 블록별로 분해했다.

| 입력 구성 | 변수 | 당뇨 60+ | 격차 |
|---|---:|---:|---:|
| 핵심만 (나이·성별·BMI·흡연) | 4 | 0.623 | 0.152 |
| + 생활습관·신체계측·검사값 | 34 | 0.730 | 0.105 |
| + 주관적 건강·보행 곤란 | 38 | 0.762 | 0.069 |
| + 동반질환 | 42 | 0.783 | 0.041 |

60대 안에서 사람을 가르는 건 나이가 아니라 **"스스로 건강을 어떻게 느끼는가, 걷는 데 불편이 있는가"** 였다.

동반질환 4개(고지혈증·뇌졸중·심질환 이력)는 +0.021을 더하지만 "이미 병원에 다니는 사람" 신호라 유병 라벨과 부분적으로 순환한다. **제외한 38변수 구성을 기본으로 권고한다.**

합치는 값어치는 성능 자체가 아니라 **전이**에 있다. 자기 데이터에서는 통합/단독 차이가 +0.006인데, UCI에서는 +0.038, Framingham에서는 +0.254다.

### 4.5 최소 입력 (`minimal_features.py`)

결과는 `artifacts/SERVING_INPUTS_REPORT.md`, 요약은 [20_prediction_inputs_and_levers.md](20_prediction_inputs_and_levers.md).

**나이 · 성별 · 키·몸무게 · 주관적 건강 4개로 전체 성능의 99.5%가 나온다.** 나머지 19개를 다 받아도 당뇨 +0.004, 고혈압 +0.002다. 가족력 +0.000, 생활습관 7문항 +0.015, 혈압 +0.001.

### 4.6 반사실 분석 (`counterfactual.py`)

**신뢰할 수 있는 지렛대는 체중(BMI) 하나다.** 체중 10% 감량이 당뇨 −3.13%p / 고혈압 −4.07%p, 상위 10% 경보 해제율 34~37%.

**당뇨 모델은 금연하면 위험이 4%p 오른다고 말한다.** 단면 데이터의 역인과·sick quitter 효과 때문이다. 따라서 **이 모델을 What-if 시뮬레이터로 쓰면 안 된다.**

### 4.7 표본을 두 배로 늘려 봤다 — 아무것도 안 변했다 (`diagnose_targets.py`)

2026-08-20. "당뇨 예측이 약해 보이니 데이터를 더 구해서 학습시키자"는 제안을 검증했다.
NHANES 2005–2012 4개 주기를 추가해 **25,457 → 48,895명**으로 늘리고 같은 파이프라인으로
재학습했다. 홀드아웃은 그대로 2021–2023 주기다.

| | 4주기 (25,457) | 8주기 (48,895) | 변화 |
|---|---:|---:|---:|
| 당뇨 전체 | 0.809 | 0.810 | **+0.002** |
| 당뇨 미진단 | 0.776 | 0.776 | −0.000 |
| 당뇨 70세+ | 0.711 | 0.711 | +0.001 |
| 고혈압 전체 | 0.797 | 0.796 | −0.001 |
| 고혈압 미진단 | 0.723 | 0.727 | **+0.004** |
| 고혈압 70세+ | 0.629 | 0.629 | −0.000 |

**학습 데이터를 두 배로 늘렸는데 AUROC 는 소수점 셋째 자리에서 움직였다.**
이 모델의 천장은 표본 크기가 아니라 **정보량**이다. 나이·성별·BMI·주관적 건강 네
문항이 말할 수 있는 것을 이미 다 뽑아냈고, 같은 종류의 데이터를 아무리 더 넣어도
같은 답이 나온다.

바뀐 것이 없지는 않다. 동년배 참조 분위표가 셀당 2배 표본으로 추정되어 **백분위 표시가
안정됐다**. AUROC 는 그대로여도 화면에 나가는 숫자의 신뢰도는 올라갔다.

### 4.8 당뇨가 고혈압보다 약한가 — 아니다

같은 진단에서 나온 결과다. 화면에서 당뇨만 규칙 엔진과 어긋나 보여 "당뇨 모델이 약한 것
아니냐"는 물음이 나왔는데, **모든 구간에서 당뇨 모델이 고혈압 모델보다 낫다.**

| 구간 | 당뇨 | 고혈압 |
|---|---:|---:|
| 전체 | **0.810** | 0.796 |
| 미진단자만 | **0.776** | 0.727 |
| 19–40세 | **0.800** | 0.731 |
| 40–50세 | **0.804** | 0.688 |
| 50–60세 | **0.741** | 0.706 |
| 60–70세 | **0.775** | 0.676 |
| 70세+ | **0.711** | 0.629 |

"미진단자만"은 이미 진단받은 양성을 빼고 다시 잰 값이다. 진단자는 주관적 건강이 나쁘고
동반질환이 있어 쉽게 잡히는데, 선별 제품이 실제로 찾아야 하는 사람은 자기가 병이 있는 줄
모르는 사람이다. 그 기준에서 격차가 가장 크다 — 당뇨 0.776 대 고혈압 0.727.

**개선이 필요한 쪽은 고혈압, 그중에서도 60세 이상이다.** 70세+ 0.629는 동전 던지기에
가깝다. 화면에서 당뇨가 어긋나 보인 이유는 성능이 아니라 표시 문제이며
[22번](22_two_engines_comparison.md) §2.5에 측정과 함께 정리했다.

## 6.5 서빙 — 도커로 예측 확인하기

```bash
cd project
```

`docker-compose.yml`은 `./modeling/artifacts/models`를 `/app/models`로 읽기 전용 마운트한다. 재학습해도 이미지를 다시 빌드할 필요가 없다.

**설계 결정 두 가지.**

- **무저장.** 요청 본문의 건강정보는 응답을 만든 뒤 버린다. DB·Redis·로그에 남기지 않는다. ADR-0002의 "건강정보를 서버에 저장하지 않는다"를 여기서는 무상태 계산으로 지킨다
- **무인증.** 저장이 없어 개인정보 위험은 낮지만 공개 엔드포인트라 **속도 제한이 필요하다.** `03_api_spec.md`에 아직 반영 전이며 검토가 필요한 결정이다

**절대 확률을 그대로 보여주면 안 된다.** 고혈압 유병률이 42%라 누구나 40~60%에 앉는다. 화면에서 "50.7% · 낮음"이 나온 적이 있는데, 등급은 맞았고 숫자가 오해를 부른 것이었다 — 50대 남성의 예측 중간값이 정확히 50.7%다. 그래서 모델 번들에 **연령대·성별 참조표**(성별×6구간, 각 21분위)를 넣고, 등급을 절대 확률이 아니라 **동년배 백분위**로 정한다.

| 화면 표기 | 의미 |
|---|---|
| `probability` | 측정 기준을 넘을 가능성 |
| `peer_percentile` | 같은 나이·성별에서의 위치 (0~100) |
| `peer_ratio` | 동년배 중간값 대비 배수 |
| `band` | 백분위 70 미만 low, 70~89 moderate, 90 이상 high |

**특징 확장으로 보정을 개선했다.** `refine.py`가 5개 구성을 비교했고 `+bins`(주관적 건강 더미 + 연령·BMI 구간)를 채택했다. AUROC는 거의 안 움직이지만 ECE가 절반 이하로 떨어진다 — 화면에 확률을 띄우려면 순위보다 확률의 정확도가 중요하다.

| 타깃 | AUROC | Brier | ECE (linear → +bins) | 보정 기울기 |
|---|---:|---:|---|---:|
| 당뇨 | **0.809** | 0.1172 | 0.0278 → **0.0088** | 1.05 |
| 고혈압 | **0.797** | 0.1820 | 0.0175 → 0.0335 (주기 이동, 위 참조) | 0.93 |

확장 함수 `expand_features`는 `app/services/risk.py`에 **한 벌만** 둔다. 학습(`export_model.py`)이 같은 함수를 호출하므로 두 벌이 갈라질 여지가 없다.

**서빙 모델은 NHANES 단독으로 학습한다.** 통합 테이블로 학습했을 때 심각한 문제가 드러났다. 출처마다 수집 변수가 달라서 **각 컬럼의 결측 패턴이 곧 출처 표시**가 된다.

| 변수 | UCI | Framingham | NHANES | 결측만으로 출처 맞히는 정확도 |
|---|---:|---:|---:|---:|
| `veg_fruit_daily` | 100% | 0% | 0% | **1.000** |
| `self_rated_health` | 100% | 0% | 99.9% | **1.000** |
| `moderate/vigorous/sedentary/sleep` | 0% | 0% | 99% | **1.000** |
| `waist_cm` | 0% | 0% | 84.8% | 0.986 |

그래서 **선택 항목에 답하는 행위 자체가 사용자를 다른 학습 하위집단으로 옮겼다.** 채소·과일에 답하면 "UCI 응답자(자가보고 라벨, 유병률 13.9%)", 안 답하면 "NHANES 수검자(측정 라벨, 18.3%)"로 읽혔다. 임상적 근거가 전혀 없는 이동이다.

`diagnose_serving.py`가 측정한 통합 학습 모델의 민감도:

| 변경 | 종류 | 고혈압 변화 |
|---|---|---:|
| 나이 54→64 | 필수 | +14.3%p |
| 걷는 데 불편 = 있음 | **선택** | **+11.0%p** |
| BMI 27.7→31 | 필수 | +10.5%p |
| 채소·과일 = 예 | **선택** | **−7.5%p** |

선택 항목 응답이 필수 입력 변화보다 예측을 더 흔들었다. NHANES 단독 학습으로 바꾸니 출처가 하나라 이 병리가 사라지고, 성능은 오히려 소폭 올랐다(당뇨 0.806 → 0.809).

**결측 지시자도 서빙 모델에서는 뺀다.** NHANES 단독으로 바꾼 뒤에도 지시자가 남아 있으면 "활동 문항을 건너뛴 희귀한 1%"라는 뜻이 되어 `vigorous_min` 응답이 고혈압을 −18.9%p 움직였다. 빈 칸은 "평균이라고 가정"이어야 하고, 지시자 없는 중앙값 대치가 정확히 그 뜻이다. 수정 후 선택 항목의 최대 변화는 3.6%p로 내려가고 필수 입력이 상위 3개를 차지한다.

**Platt 보정은 넣었지만 현재는 항등에 가깝다** (당뇨 a=0.994, 고혈압 a=0.997). 모델이 과신하지 않는다는 뜻이다. 고혈압 홀드아웃 ECE가 0.034인 것은 보정 문제가 아니라 **주기 간 라벨 이동**이다.

| 주기 | 측정 방식 | 수축기 ≥140 비율 |
|---|---|---:|
| 2013–2014 | BPX 청진식 | 0.147 |
| 2015–2016 | BPX 청진식 | 0.169 |
| 2017–2018 | BPX 청진식 | 0.194 |
| **2021–2023** | **BPXO 오실로메트릭** | **0.114** |

기기가 바뀌면서 라벨 자체가 바뀌었다. 학습(청진식)과 홀드아웃(오실로메트릭)의 라벨 정의가 다르므로 상위 구간에서 과대추정이 남는다. 제품이 가정용 혈압계(오실로메트릭)를 쓸 예정이라면 **2021–2023 라벨 규약으로 재학습하는 것이 맞다** — 다만 그러면 홀드아웃이 사라지므로 새 주기나 국내 자료가 들어올 때 처리한다.

**서빙 구조에서 잡은 버그 셋.**

1. **결측 지시자 표준화 누락.** `SimpleImputer(add_indicator=True)` 다음에 `StandardScaler`가 오면 지시자까지 표준화된다. 지시자를 원본 0/1로 뒀더니 확률이 조용히 어긋났다(0.0180 vs 0.0278). `test_pure_python_matches_sklearn`이 잡았다. **이 동등성 테스트를 지우면 안 된다** — AUROC로는 절대 안 잡히는 종류다
2. **주관적 건강 결측이 "매우 좋음"으로 학습됨.** 더미만 만들고 `srh_missing`을 빼먹으면 결측일 때 더미가 전부 0이 되어 최저 레벨과 구별이 사라진다. Framingham 4,240행에 이 값이 없어서, 같은 사람의 고혈압 확률이 75.4%로 부풀어 있었다. 수정 후 47.7%. `test_self_rated_health_moves_risk_monotonically`가 지킨다
3. **모델 파일이 import 시점에만 적재됨.** 재학습해도 컨테이너를 재시작하지 않으면 옛 계수로 계속 응답한다. 예측은 정상으로 보이니 발견이 어렵다. `RiskModelRegistry.refresh()`가 mtime을 보고 다시 읽는다

### 7.4 다음에 구할 데이터 — 무엇이 실제로 바뀌는가

§4.7이 "같은 종류를 더"는 효과가 없음을 보였으므로, **다른 종류**만 후보다.
지금 모델이 못 하는 것은 세 가지이고 각각을 푸는 데이터가 다르다.

| 못 하는 것 | 필요한 데이터의 성질 |
|---|---|
| **발병 예측** (지금은 유병 선별) | 같은 사람을 두 시점 이상 추적한 **종단** 자료 + 두 시점의 검사값 |
| **한국인 보정** | 한국 인구 대표 표본 |
| 검사값이 있을 때의 판정 | 없다. 라벨 정의 변수라 넣으면 누출이다 — 규칙 엔진의 몫 ([22번](22_two_engines_comparison.md) §2.5) |

후보를 취득 난이도 순으로 정리했다. 2026-08-20 확인.

| 데이터 | 무엇이 풀리는가 | 취득 | 난이도 |
|---|---|---|---|
| **CHARLS** (中 중고령자 패널) | **발병 라벨** — 2011·2015 두 시점 채혈(FPG·HbA1c·지질). 아시아 인구라 미국보다 가깝다 | `charls.pku.edu.cn` 온라인 신청 후 승인, 무료 | **낮음** |
| **KNHANES** 국민건강영양조사 | **한국인 보정** — 변수 구조가 NHANES와 거의 같아 기존 로더가 그대로 붙는다 | 회원가입 + 이용 신청. **IRB 아님.** 2024년 자료까지 공개 | **낮음** |
| **HRS** (미 고령자 패널) | 발병 라벨, 고령층 표본 보강 (70세+ 0.629 구간) | 등록 후 다운로드, 무료 | 낮음 |
| **NHIS 표본코호트 2.0** | 한국인 + 종단 + 건강검진 실측 FPG. **가장 값어치가 크다** | 자료제공 신청 + 심의 + 수수료 | 높음 |
| BioLINCC (ARIC·CARDIA·MESA) | 정통 코호트 발병 라벨 | DUA + IRB | 높음 |
| UK Biobank | 대규모 종단 + 유전 | 신청 + 비용, 평균 15주 | 높음 |

**권고 순서.** ① KNHANES로 한국인 보정을 먼저 한다 — 신청서 한 장이고 기존 코드가
그대로 돈다. ② CHARLS로 발병 라벨 파이프라인을 만든다 — 두 시점 검사값이 있어
"4년 내 발병" 라벨을 실제로 만들 수 있고, 이건 챌린지 서비스가 원래 물어야 하는 질문이다.
③ 그다음에 NHIS 표본코호트를 신청한다. 승인이 오래 걸리므로 ①②를 하는 동안 병행한다.

§1의 "국내 자료 전부 막힘" 표에서 **KNHANES는 IRB가 아니라 이용 신청서**다.
KoGES·AI-Hub와 같은 벽이 아니므로 다시 확인해 볼 값어치가 있다.

## 8. 반드시 함께 말해야 하는 한계

발표 자료와 모델 카드에 그대로 들어가야 한다. 숨기면 평가에서 더 크게 걸린다.

1. **세 데이터 모두 미국 인구다.** 한국인 대상 보정을 하지 않았다
2. **단면 데이터라 "발병 예측"이 아니다.** 측정 기준 유병 여부를 맞히는 선별 모델이다
3. **반사실 수치는 인과 효과가 아니다.** 방향과 순서는 쓸 수 있지만 챌린지의 약속으로 화면에 올려서는 안 된다
4. **일부 개입은 부호가 뒤집혀 있다.** 금연·음주·식단이 당뇨 위험을 올리는 것으로 나온다
5. **임계값이 임상 검토를 받지 않았다**
6. **Framingham은 3자 미러의 교육용 추출본이다**
7. **검사값이 있으면 이 확률을 읽어서는 안 된다.** 라벨을 정의하는 값(당뇨는 혈당,
   고혈압은 혈압)을 모델이 입력으로 받지 못한다. 마른 당뇨 환자에게 3.4%를 내놓는다.
   검사값이 있으면 규칙 엔진 판정을 쓴다 — [22번](22_two_engines_comparison.md) §2.5
