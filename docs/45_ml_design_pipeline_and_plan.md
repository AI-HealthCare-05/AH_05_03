## 0. 세 줄

- **모델은 둘이다.** 1차는 "지금 기준을 넘었는가"(단면, 번들 20개), 2차는 "앞으로 생길 확률"(궤적, 학습 아님). 2026-09-04 에 1차의 **상위 셋 선별 방식**을 규칙 엔진 중재에서 **ML 확률 단독**으로 바꿨고, 후보를 궤적이 가능한 비가역 3종으로 제한했다(§1.3).
- **"몇 년 안에" 를 관측으로 뒷받침하는 라벨은 사망 하나뿐이다.** 그래서 사망 위험 모델을 따로 학습했고 2026-09-10 에 **1·3·5년 셋**으로 늘렸다 — 5년 홀드아웃 AUROC 0.876(일반형) / 0.888(정밀형), **나이만 쓴 기준선 0.835 / 0.833** (§8). 지평을 셋으로 벌리면서 **단조 역전 11.1%** 가 드러났고 접는 비용은 AUROC −0.0013 이하다(§8.5). 질환 발병 시점 라벨은 여전히 저장소에 없다.
- **성능 수치 중 합성 데이터로 낸 것은 없다.** 전부 NHANES 실측 홀드아웃이고 독립 검증축이 셋 더 있다(사망연계·Framingham·BRFSS).

## 1. 두 모델의 분리

### 1.1 역할

| | **1차 모델** | **2차 모델** |
|---|---|---|
| 묻는 것 | 지금 기준을 넘을 가능성 | 앞으로 새로 생길 확률 |
| 실체 | XGBoost 3시드 + CatBoost 3시드 앙상블, isotonic 보정 | 인구 기준 위험표 × 개인 상대위험 |
| 학습 | NHANES 단면, 질환별 4,626~40,926행 | **학습하지 않는다** — 표를 유도 |
| 대상 | 10질환 × 2 tier = **번들 20개** | 비가역 3종 (당뇨·고혈압·신기능) |
| 출력 | `probability` + 5단계 등급 | 1~5년 누적 발병 확률 + 동년배 곡선 |
| 코드 | `app/services/risk.py` | `app/services/trajectory.py` |

2차는 1차의 출력을 입력으로 쓴다.

```
R(x) = ln(1−p) / ln(1−m)              p = 1차 확률, m = 동년배 기준 유병률, 상한 25
F(t) = 1 − exp( −R(x) · Λ0(a → a+t) )
```

### 1.2 요청 한 번의 흐름

```
입력 34칸 (필수 8 + 검사값)
   │
   ├─ score_conditions()   1차 · 10질환 × tier   ← 전부 돌린다
   │      tier = 검사값 하나라도 있으면 lab, 없으면 basic
   │
   ├─ arbitrate()          카드 13장의 정본을 정한다
   │      E1 규칙엔진 → E3 공개공식 → E2 ML   (먼저 답하는 쪽이 정본)
   │
   ├─ rank_and_attach()    상위 3개 선별        ← 여기가 2026-09-04 에 바뀌었다
   │
   └─ trajectory           2차 · 1~5년 곡선      ← 뽑힌 셋에만
```

**중재는 카드에 그대로 남는다.** 바뀐 것은 *선별*뿐이다.

### 1.3 상위 셋 선별 — 2026-09-04 변경

`app/services/suspects.py` 의 상수 둘로 갈아 끼운다.

```python
RANK_SOURCE = "ml_probability"  # 이전: "arbitrated"
RANK_POOL = "trajectory"  # 비가역 3종만
```

같은 프로필(52세 남성 · 134/86 · 공복혈당 112 · HbA1c 6.0 · HDL 41 · LDL 142 · TG 186)의 실측 전후다.

| 방식 | 상위 셋 | 발병 곡선이 붙은 카드 |
|---|---|---:|
| `arbitrated` (이전) | htn 2.400 · dm 2.250 · dlp 1.128 | 2 / 3 |
| `ml_probability` + `all` | dlp 0.636 · fatty_liver 0.583 · mets 0.452 | **0 / 3** |
| **`ml_probability` + `trajectory` (현행)** | **htn 0.408 · dm 0.120 · ckd 0.060** | **2 / 3** |

가운데 줄이 이 결정의 근거다. **확률만으로 열 질환을 세우면 유병률이 높은 축이 이기는데**(이상지질 47% · 지방간 · 대사증후군), 그 셋은 전부 발병 궤적이 없는 질환이라 2차가 통째로 빈다. 발병 궤적은 비가역 질환에만 정의돼 있다 — 이상지질은 지질강하제로 되돌아가므로 "언제 걸리나" 가 성립하지 않는다([41번](41_onset_trajectory.md) §2.3).

**대가를 적어 둔다.**

1. 후보가 셋이고 `TOP_N` 도 셋이라 **뽑히는 질환은 언제나 같고 순서만 바뀐다.** 선별의 성격이 옅어진다.
2. 확진 질환을 후보에서 빼던 필터(`KNOWN_LEVELS`)가 같이 꺼졌다. 이미 아는 병이 "의심" 으로 다시 올라올 수 있다.
3. 근거가중(`EVIDENCE`)과 동년배배수가 순위에서 빠졌다. 사망연계 C 가 0.51 인 축과 0.84 인 축이 같은 무게로 선다 — 다만 후보가 비가역 3종(C 0.75~0.84)뿐이라 지금은 실질 영향이 작다.

되돌리는 것은 상수 두 줄이다. 두 경로 모두 `app/tests/model/test_suspects.py` 가 계약을 들고 있다(중재 경로 24건 + 확률 경로 6건).

### 1.4 검토 중 — 가역 질환까지 궤적 확장

`RANK_POOL = "all"` 로 되돌리려면 발병 궤적이 가역 질환에서도 성립해야 한다. 정하지 않은 것이 셋이다.

- **"발병" 의 정의.** 지질은 기준을 넘었다 내려갔다 한다. 첫 초과인가, 투약 시작인가, 지속적 초과인가.
- **비가역 가정이 빠진 자리.** 현재 표는 유병률 단조 증가를 전제로 누적최댓값을 씌운다. 가역 질환에서는 그 전제가 틀리다.
- **표시할 값어치.** 이상지질 하위유형 셋은 사망연계 C 0.51~0.65 이고 65세 이상에서 방향이 뒤집힌다([42번](42_ml_evaluation_strategy.md) §3.1). 곡선을 붙여도 "위험" 프레임으로 못 띄운다.

## 2. 데이터셋

### 2.1 지금 쓰는 것

| 파일 | 규모 | 성격 | 쓰는 곳 |
|---|---:|---|---|
| `nhanes_pooled.csv` | 48,895행 × 86열 | 단면 · 검사값 실측 | **주 학습** |
| `mortality.csv` | 101,316행 (연계 59,064 · 사망 9,249) | **시간이 붙은 유일한 라벨** | 사망 위험 모델 · 근거가중 · δ 보정 |
| `framingham.csv` | 4,240행 | 베이스라인 1회 + 10년 CHD 이진 | 궤적 외부 대조 |
| `brfss_indicators.csv` | 253,680행 | 단면 자가보고 | 외부 인구 대조 |
| `unified.csv` | 306,815행 | 위 셋 통합 | 커버리지 점검 |

**주의할 기록 하나.** 문서 몇 곳에 "Framingham 3회 검진 · 24년 추적" 이라고 적혀 있지만 실제로 적재된 것은 **반복측정이 없는 교육용 추출본**이다. 로더가 스스로 밝혀 두었다 — `"the widely circulated teaching extract, mirrored on GitHub/Kaggle"`. `subject_id` 4,240명 × 1회, `survey_year` 전부 1956. 발표나 보고서에 "코호트 종단 데이터로 학습" 이라고 쓰면 안 된다.

### 2.2 왜 미국 데이터인가

국내 자료를 먼저 조사했고 당시 전부 신청 절차에 막혔다([21번](21_modeling_overview.md) §1). 로더는 미리 만들어 뒀다 — `data/load_nhis_checkup.py`, `data/load_khp.py`. NHANES 를 고른 이유는 셋이다.

1. 검사값이 **실측**이다(혈압·공복혈당·HbA1c·지질·크레아티닌). 자가보고가 아니다.
2. 주기가 2005 년부터 이어져 **조사 회차를 통째로 떼는 홀드아웃**이 가능하다.
3. 사망연계 파일이 따로 공개돼 있어 "이 위험도가 실제 결과와 이어지는가" 를 잴 축이 생긴다.

**학습 인구는 미국, 판정 임계값은 국내다.** 번들의 `threshold_source` 가 `대한고혈압학회 진료지침` 같은 값을 들고 있다. 규칙 엔진(E1)을 따로 둔 이유이기도 하다.

### 2.3 KNHANES 현황 — 기록보다 진전돼 있다

상위 폴더에 `docs/HN24_chronic_disease_데이터명세서.xlsx` 가 있다. KNHANES 제9기 3차년도(2024) 추출 명세이고 6,997행 × 31변수, 타깃 셋(`HE_HP` 고혈압 유병 · `DE1_dg` 당뇨 의사진단 · `DI2_pr` 이상지질 현재 유병). 팀 안에서 이미 이용신청을 통과했다는 뜻이다.

**다만 "한국인 보정 완료" 로 말하면 안 된다.**

- **검사값이 한 컬럼도 없다.** 공복혈당·HbA1c·지질·크레아티닌이 빠져 있어 측정 기준 라벨은 `HE_HP` 하나뿐이고 나머지 둘은 자가보고다. 지금 라벨 정의(공복혈당 ≥126 또는 HbA1c ≥6.5%)를 그대로 못 쓴다.
- 4세·6세 등 미성년이 섞여 있어 성인 필터가 안 걸린 상태다.
- 라이선스가 KOGL 제4유형 / CC BY-NC 로 **비상업**이다.
- `HN24_chronic_disease_raw.csv` 자체는 `project/` 안에 없다.

배포된 번들 20개는 전부 `train_source: nhanes_pooled` 다.

## 3. 피처와 라벨 누출 차단

### 3.1 특징 집합

```
일반형(basic)  수치 12 + 범주 2
  age · bmi · height_cm · waist_cm · self_rated_health · srh_missing
  alcohol_days_per_year · moderate_min_per_week · vigorous_min_per_week
  sedentary_min_per_day · sleep_hours · waist_height_ratio
  + sex · smoking_status

정밀형(lab)   수치 30 + 범주 2
  위 12개
  + fasting_glucose · hba1c · total_chol · hdl · ldl · triglyceride
  + ast · alt · ggt · uric_acid · creatinine · egfr · hemoglobin · albumin · urine_acr
  + 파생 4: tg_hdl_ratio · non_hdl · ast_alt_ratio · waist_height_ratio
```

파생 비율을 손으로 만드는 이유는 선형 모델이 곱·비를 스스로 만들지 못하기 때문이다. TG/HDL 은 인슐린 저항성 대리 지표이고, 허리/키는 같은 BMI 안에서 복부비만을 가른다. 정의는 `modeling/targets.py` 의 `DERIVED`, 계산은 `train_multi.build_frame` 한 곳이다.

`modeling/targets.py` 에는 임상 지수 여럿(TyG·FLI·LAP·VAI·CMI·METS-IR)이 더 정의돼 있지만 **기본은 꺼져 있다.** 성능에는 무용했고 방향 계약에만 쓴다.

### 3.2 라벨 누출 차단이 설계의 축이다

라벨 정의에 들어간 컬럼은 **기계적으로** 피처에서 제거된다. 고혈압 모델은 `sbp`/`dbp` 를 볼 수 없다 — 안 막으면 AUROC 가 1.0 에 가까워지고 아무 의미가 없다. 단일 진실 원천은 `modeling/targets.py` 이고, `test_label_defining_measurements_are_not_model_inputs` 가 고정한다.

이 차단이 화면에 남기는 자국이 하나 있다. `low_hdl` 모델은 HDL 을 못 보므로 **HDL 81 인 사람도 확률이 낮게 나오지 않는다.** 순위를 확률로 매길 때 조심해야 하는 지점이고 §1.3 의 대가 3 과 같은 이야기다.

### 3.3 기각한 피처 — 순환성 판정

[42번](42_ml_evaluation_strategy.md) §5 가 닫았다. 전체 홀드아웃과 **미진단자 부분집합**에서 같은 팔을 두 번 재는 방법이다.

| 피처 | 판정 | 근거 |
|---|---|---|
| 기왕력 4종 | **쓰지 않는다** | 미진단자 12칸 전부 음수(p=0.0005). 세 칸은 유의하게 악화 |
| 신장문진 | 당뇨·고혈압에 쓰지 않는다 | 미진단자 부호검정 p=0.688 |
| 보행곤란 | **뺐다** | 홀드아웃 주기 커버리지 0% |
| 체중변화 | 보류 | 미진단자 이득 근거 없음 |
| 가족력 | **당뇨 한정 후보** | 미진단자에서도 두 tier 양수. 팀 결정 대기 |

## 4. EDA

`modeling/eda.py` → `artifacts/eda.json` (48,895행 기준). 네 가지를 낸다.

1. **분포·이상값** — 진단 임계값이 아니라 *생리적으로 있을 수 없는 값*의 경계로 거른다. 좁게 잡으면 진짜 환자를 지운다. 단위 오류·센티널이 여기서 드러난다.
2. **결측 구조** — 결측은 무작위가 아니다. 실측 상관에서 `total_chol ↔ hdl` **r=1.0**, `creatinine ↔ egfr` **r=1.0**, `ggt ↔ uric_acid` **r=0.999**. **"검진을 받았는가" 가 한 덩어리로 움직인다**는 뜻이고, 이것이 tier 를 basic/lab 으로 가르는 근거다.
3. **동반이환** — 열 질환이 서로 얼마나 겹치는가. 카드 열 장을 한 번에 그리는 화면 설계와 직결된다.
4. **연관** — 타깃마다 어떤 입력이 실제로 갈리는가. 표준화 평균차로 잰다.

로더 버그 둘을 이 EDA 로 잡은 전례가 있다([27번](27_eda_new_data_and_synthetic.md) §1.1).

## 5. 전처리

`train_multi.make_pipeline` 한 곳이다. 튜닝 스크립트도 여기에 위임한다 — 예전에 `tune_lab.py` 가 전처리 블록을 복사해 갖고 있어서 "튜닝해서 고른 설정" 과 "실제 배포되는 파이프라인" 이 갈릴 뻔했다.

```
중앙값 대치 (add_indicator=False)  →  표준화  →  원핫(drop="first")  →  GBDT
```

**결측 지시자를 일부러 쓰지 않는다.** "이 질문을 건너뛰었다" 가 특징이 되면 사용자가 선택 항목 하나를 비우는 행위만으로 확률이 튄다. 빈칸은 "평균이라고 가정" 이라는 뜻이어야 한다.

**단조 제약을 건다.** 주관적 건강이 나빠지면 위험이 올라가야 한다 — 표본의 요철 때문에 역전이 학습되면 사용자가 설문에서 자기 건강을 더 좋게 답했을 때 숫자가 나빠진다. 실제로 트리 모델에서 그 역전이 나왔다. 나이·BMI 에는 걸지 않는다(타깃마다 방향이 다르다 — 빈혈은 BMI 가 높을수록 유병률이 낮다).

서빙 쪽 재현에는 함정이 하나 더 있다. XGBoost 는 내부에서 float32 로 비교하므로 **채점기도 float32 로 반올림한다**(`risk.to_float32`). 안 맞추면 경계에 걸린 행에서 트리 하나가 반대편 잎으로 가고 로그오즈가 0.27 어긋난다.

## 6. 학습·앙상블·파인튜닝

### 6.1 배포 구성

**XGBoost 3시드 + CatBoost 3시드 앙상블**, 각각 isotonic 보정. 번들 하나가 1.1~1.4MB 이고 20개 24MB 다.

앙상블을 쓰는 이유는 정확도가 아니라 **재현성**이다. 시드를 바꾸면 개인 확률이 흔들리는데, 같은 사람이 같은 값을 넣고 다른 숫자를 보는 것은 설명할 수 없는 동작이다. 정확도 이득은 [29번](29_seed_ensemble_model_comparison.md)에서 무효로 나왔다.

`XGBClassifier(n_estimators=200, max_depth=3, min_child_weight=50, learning_rate=0.05, subsample=0.8, colsample_bytree=0.8, reg_lambda=1.0)` — 기본값(depth 4, 400트리)은 이 표본 크기에 과하다.

### 6.2 하이퍼파라미터 재선택 — 실행했고 채택하지 않았다

**문제.** `tune_lab.py` 가 격자 24개를 **홀드아웃에서 전부 채점하고 최고를 골랐다.** 그렇게 고른 값은 배포 성능보다 높다 — 24번 고르면 우연히 좋아 보이는 설정이 하나쯤 나온다. 기록된 "여유"(빈혈 +0.0090, 당뇨 +0.0036)가 그 값이다.

**고침.** `--select validation` 을 기본으로 추가했다. 학습 주기의 마지막(2017_2018)을 검증으로 떼어 거기서 고르고 홀드아웃은 고른 뒤 한 번만 본다. 무작위 CV 가 아니라 시간 순인 이유는 배포가 그렇게 일어나기 때문이다.

**결과 (2026-09-03, 열 질환 × 두 tier).**

| 판정 | 칸 | 내용 |
|---|---:|---|
| 유의하게 개선 | 4 | 당뇨 lab +0.0024 · 고혈압 lab +0.0022 · 이상지질 lab +0.0035 · 대사증후군 basic +0.0033 |
| 유의하게 악화 | 1 | 낮은 HDL basic −0.0034 |
| 구분 안 됨 | 13 | — |

**채택하지 않았다.** ① 18칸 중 13칸이 구분 안 됨이고 최대 이득이 +0.0035 다. ② 이 튜닝은 단일 XGBoost 로 쟀는데 배포는 6모델 앙상블이라 앙상블이 이미 분산을 줄인다. ③ 유의하게 나빠지는 칸이 있는데, 칸마다 다른 설정을 두면 20개 번들이 20가지 설정을 갖게 된다.

**다시 시도할 조건**: 앙상블 조건에서 재는 하네스를 만들었을 때, 또는 특징 집합이 크게 바뀌었을 때. 산출물은 `artifacts/tune_validation.json`.

### 6.3 하지 않기로 한 것

- **합성 증강(SMOTE).** 8칸 전부 AUPRC 하락. 용량-반응까지 확인하고 기각([27번](27_eda_new_data_and_synthetic.md) §4).
- **TabPFN 서빙.** 라이선스 게이트·CPU 추론 3~4분·sklearn 충돌. **평가 도구로는 쓸 자리가 있다** — 성능 상한의 독립 추정과 라벨 잡음 탐지([42번](42_ml_evaluation_strategy.md) §4).

### 7.2 지표는 네 층으로 본다

AUROC 하나로 고르지 않는 이유가 저장소 안에 두 건 있다. AUROC 는 순위만 보므로 **확률을 전부 2배로 부풀려도 소수점 넷째 자리까지 같고**(고혈압 보정 기울기 0.74 를 그렇게 놓쳤다), 기저율에도 둔감하다(이상지질 49% 대 미진단 당뇨 3.5%).

```
순위   auroc · auprc · auprc_lift
확률   brier · brier_skill · ece · mce · 보정 기울기/절편 · 신뢰도 곡선
판정   운영점별 민감도 · 특이도 · PPV · NPV · F1 · MCC · 균형정확도 · 리프트
결정   net benefit — "이 모델을 쓰는 게 전원 검사보다 나은가"
```

마지막 층이 제품 질문에 가장 가깝다. 판별력이 좋아도 임계값을 잘못 잡으면 전원에게 "검사받으세요" 라고 하는 것보다 못할 수 있다.

## 8. 1·3·5년 사망 위험 모델 (2026-09-04 신규 · 2026-09-10 지평 셋으로)

### 8.1 왜 만들었나

번들 20개는 전부 단면 라벨이다. 2차 궤적도 학습이 아니라 단면 유병률을 뒤집은 표다. **관측된 사건과 그 시점이 같이 있는 자료는 NCHS 사망연계 하나뿐이므로**(`permth_int` = 조사 시점부터의 개월 수), "5년 안에" 를 유도가 아니라 관측으로 뒷받침할 수 있는 라벨도 그것 하나다.

**사건이 발병이 아니라 사망이다.** 이 모델은 "5년 안에 당뇨에 걸릴 확률" 이 아니라 "5년 안에 사망할 확률" 에 답한다. 질환별 사인도 같이 재지만 그건 "그 병으로 죽을 확률" 이지 "그 병에 걸릴 확률" 이 아니다. 화면에서 같은 말로 부르면 안 된다.

### 8.2 주기를 다섯 개만 쓰는 이유

사망연계 추적창이 2019 년쯤 끝난다. 실측:

| 주기 | n | 사망 | 추적개월 최대 | **60개월 도달** |
|---|---:|---:|---:|---:|
| 2005_2006 | 5,245 | 1,024 | 180 | 93.4% |
| 2007_2008 | 6,079 | 1,125 | 160 | 93.2% |
| 2009_2010 | 6,367 | 859 | 135 | 94.2% |
| 2011_2012 | 5,704 | 626 | 113 | 93.8% |
| 2013_2014 | 5,910 | 467 | 85 | 93.7% |
| 2015_2016 | 5,836 | 275 | 61 | **2.7%** ← 못 쓴다 |
| 2017_2018 | 5,667 | 145 | 37 | **0.0%** ← 못 쓴다 |

마지막 두 주기는 5 년을 채운 사람이 사실상 없다. 그대로 넣으면 검열된 생존자가 전부 빠지고 사망자만 남아 그 주기의 양성률이 100% 에 가까워진다. **주기째 뺀다.** NHANES 2021_2023 은 연계 파일 자체가 없다.

그래서 홀드아웃 주기가 번들 20개(2021_2023)와 다르다 — 여기서는 **2013_2014** 를 뗀다.

### 8.3 검열 처리

이산 시점 하나(60개월)만 보므로 생존 모형 대신 경계가 분명한 이진 라벨로 접는다.

- 양성 — 사망했고 `permth_int ≤ 60`
- 음성 — `permth_int ≥ 60` (60개월을 넘겨 살아 있었다)
- 버림 — 살아 있는데 추적이 60개월을 못 채운 행. 5년 안에 죽었는지 **모른다** (7행)

Harrell's C 는 5년 창으로 자르지 않은 전체 추적으로 따로 잰다 — 그쪽은 검열을 다룰 수 있다.

### 8.4 결과 — 공통 주기 (홀드아웃 2013_2014, 2026-09-10 실측)

세 지평이 **같은 주기·같은 홀드아웃**을 쓴다. 그래야 세 숫자를 한 표에 놓을 수 있다.

| 지평 | tier | 학습 행 | 홀드아웃 | 양성률 | **AUROC** | **나이만** | AUPRC | ECE | C(전체추적) |
|---|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 1년 | basic | 23,395 | 5,910 | 0.0096 | **0.8672** | 0.7942 | 0.1301 | 0.0021 | 0.8432 |
| 1년 | lab | 22,283 | 5,689 | 0.0084 | 0.8411 | 0.7840 | 0.0577 | 0.0016 | 0.8533 |
| 3년 | basic | 23,395 | 5,910 | 0.0355 | 0.8579 | 0.8101 | 0.2666 | 0.0060 | 0.8559 |
| 3년 | lab | 22,283 | 5,689 | 0.0343 | **0.8695** | 0.8058 | 0.2838 | 0.0038 | 0.8683 |
| 5년 | basic | 23,395 | 5,903 | 0.0632 | 0.8764 | 0.8354 | 0.4228 | 0.0071 | 0.8652 |
| 5년 | lab | 22,283 | 5,682 | 0.0607 | **0.8877** | 0.8329 | 0.4314 | 0.0064 | 0.8719 |

읽을 때 지켜야 하는 것 셋.

- **AUPRC 는 지평 사이에 비교하지 않는다.** 양성률이 0.96% 에서 6.3% 로 여섯 배 넘게 다르다. 1년 AUPRC 0.13 은 5년 0.42 보다 나쁜 모델이 아니라 **더 드문 사건**이다. AUROC 는 비교할 수 있다.
- **1년에서는 정밀형이 일반형에 진다**(0.8411 vs 0.8672). 홀드아웃 양성이 48명뿐이라 신뢰구간이 넓고, 정밀형은 검사값이 있는 사람만 봐서 표본이 더 줄어든다. 3·5년에서는 순서가 정상으로 돌아온다. §8.6 이 이걸 표본으로 푼다.
- **나이만 쓴 기준선을 같이 낸다.** 사망은 나이가 크게 끄는 사건이라 이걸 빼면 AUROC 0.888 이 "모델이 좋다" 인지 "나이가 좋다" 인지 구별되지 않는다. 나머지 특징이 더하는 것은 5년에서 basic +0.041 · lab +0.055 이고, **1년에서 더 크다**(basic +0.073). 짧은 지평일수록 나이 말고 다른 것이 일한다.

5년 행은 2026-09-04 단일 지평 실행과 같은 데이터·같은 분할이다(학습 23,395 · 홀드아웃 5,903 · 양성률 0.0632 전부 일치). AUROC 가 4째 자리에서 다른 것(0.8759 → 0.8764)은 XGBoost 의 다중 스레드 동률 처리가 실행마다 달라서고, 나이만 쓴 기준선은 0.8354 · 0.8329 로 **완전히 같다.**

사인별(사건 수가 적어 참고용. 짧은 지평은 `evaluate` 의 최소 양성 25 문턱에 걸려 대부분 비어 있고, 그건 결함이 아니라 그 문턱이 일한 결과다):

| 사인 | 5년 홀드아웃 사건 | 5년 AUROC (basic / lab) |
|---|---:|---:|
| 당뇨 기여 사망 | 36 / 33 | 0.837 / 0.874 |
| 고혈압 기여 사망 | 63 / 53 | 0.902 / 0.907 |

### 8.5 단조 역전 — 세 숫자를 나란히 적기 전에 봐야 하는 것

지평마다 모델을 따로 학습하므로 한 사람에게 F(1년) > F(3년) 이 나올 수 있다. **실제로 흔하다.**

| tier | 역전된 사람 | 비율 | 최악 낙폭 |
|---|---:|---:|---:|
| basic | 657 / 5,910 | **11.1%** | −0.050 |
| lab | 425 / 5,689 | **7.5%** | −0.076 |

사망은 흡수 상태다 — 1년 안에 죽은 사람은 3년 안에도 죽어 있다. 그러니 F(1) ≤ F(3) ≤ F(5) 는 취향이 아니라 **사건의 정의**이고, 역전은 임상이 아니라 인공물이다. 카드에 세 숫자를 나란히 적는 순간 사용자에게 바로 보인다.

**접는 비용이 사실상 0 이다.** 왼쪽부터 누적 최댓값으로 접고 다시 재면,

| tier | 1년 | 3년 | 5년 |
|---|---|---|---|
| basic | 0.8672 → 0.8672 | 0.8579 → 0.8566 | 0.8764 → 0.8763 |
| lab | 0.8411 → 0.8411 | 0.8695 → 0.8691 | 0.8877 → **0.8879** |

최대 손실이 −0.0013 이고 정밀형 5년은 오히려 올랐다. `trajectory.prevalence_curve` 가 비가역 질환에서 같은 이유로 같은 연산을 한다 — 저장소에 이미 있는 판단이다. **접고 쓰면 된다.**

왼쪽부터 접는 것 자체는 선택이다(오른쪽부터 최솟값, 등온 회귀도 후보다). 셋 중 어느 것이 맞다는 근거가 없어서 저장소가 이미 쓰는 방식에 맞췄고, 접기 전 역전 비율을 리포트에 남겨 나중에 다시 판단할 수 있게 했다.

### 8.6 짧은 지평은 데이터를 더 연다

60개월 창에서 통째로 버린 2015_2016·2017_2018 이 12·36개월 창에서는 살아난다. 지평마다 쓸 수 있는 주기를 다 쓴 두 번째 실행(`extended_cycles`) 결과다. **코호트가 달라 위 표와 비교할 수 없고**, 짧은 지평이 얼마나 더 여는지를 보는 자리다.

| 지평 | 주기 | 홀드아웃 | 라벨 행 | 양성 | basic AUROC | lab AUROC |
|---|---:|---|---:|---:|---:|---:|
| 1년 | 7개 | 2017_2018 | 40,808 | 459 | 0.8555 | **0.8716** |
| 3년 | 6개 | 2015_2016 | 35,138 | 1,297 | 0.8691 | **0.8823** |
| (5년) | 5개 | 2013_2014 | 29,298 | 1,888 | 0.8764 | 0.8877 |

라벨 행이 29,305 → 40,808 로 39% 늘고, 양성은 315 → 459 로 46% 늘었다. **그리고 §8.4 에서 뒤집혔던 1년 정밀형이 제자리로 돌아온다** — 0.8411 → 0.8716 이고 일반형(0.8555)을 앞선다. 즉 그 역전은 모델의 성질이 아니라 표본 부족이었다.

### 8.7 아직 안 한 것

**서빙에 붙이지 않았다.** 지금은 `modeling/train_mortality_risk.py` 와 `artifacts/mortality_risk.json` 까지다. 화면에 올리려면 넷을 정해야 한다.

1. **뭐라고 부를 것인가.** "5년 사망 위험" 을 그대로 띄우는 것은 제품 결정이다. 건강검진 서비스에서 사망 확률을 보여주는 것의 심리적 무게가 다르다. **이 항목이 나머지 셋을 막는다.**
2. **접어서 낸다.** §8.5 — 안 접으면 카드에서 역전이 보인다.
3. **번들 형식으로 export.** 서빙은 sklearn 의존이 0이라 JSON 번들이어야 한다(`bundle_io.py`). 지평이 셋이니 번들도 셋이거나 한 번들에 지평 세 벌이다.
4. **홀드아웃 주기가 다르다.** 번들 20개는 2021_2023, 이 모델은 2013_2014 다. 같은 화면에 두 숫자를 놓으면 "같은 조건에서 잰 것" 으로 읽힌다.
