# 공개 랜딩페이지 — 구조와 경계

> 최종 갱신: 2026-09-16
> 코드 위치: `frontend/src/features/landing/`
> 관련 문서: [DESIGN.md](../DESIGN.md) · [34번 규칙 문서](34_project_rules_and_workflow.md) · [17 Three.js 인체 컨텍스트](17_threejs_human_body_dashboard_context.md) · [38 챌린지 정원 구현](38_challenge_garden_implementation.md) · [43 챗봇 질문 설계](43_chatbot_question_design.md)

이 문서를 읽고 나면 **랜딩페이지가 무엇을 재사용하고 무엇을 새로 만들었는지**, 그리고 **왜 로그인 관문 밖에 서 있어도 되는지** 알 수 있다.

---

## 0. 세 문장 요약

`/landing` 은 스크롤만으로 서비스 전체 흐름(검진표 → 해석 → 몸의 기록 → 챌린지 → 변화 → 가족)을 보여 주는 공개 소개 화면이다. 앱의 기능을 흉내 낸 화면이 아니라 **앱의 자산을 그대로 쓰는 발표 계층**이다 — 3D 인체는 앱과 같은 Vanatome 아틀라스를, 정원은 `features/challenge/GardenArt` 를, 챗봇 런처는 `globalHealthAssistant.css` 를 쓴다. 기기·서버의 건강기록은 한 줄도 읽지 않으며, 그 경계는 테스트가 지킨다.

---

## 1. 주소와 관문

| 주소 | 로그인 | 화면 |
|---|---|---|
| `/landing` | 불필요 | 소개 페이지 |
| `/signup` | 불필요 | 가입 |
| `/` (로그아웃 상태) | — | `/landing` 으로 이동 |
| `/` (로그인 상태) | 필요 | 가족 홈 |
| 그 밖의 주소(로그아웃) | — | 그 자리에서 로그인 관문 |

`RootLayout` 의 관문은 **리다이렉트가 아니라 `Outlet` 자리를 대신 채우는 방식**이라, 로그인하면 원래 가려던 화면이 그대로 뜬다. 이 성질은 그대로 두고, **더 볼 것이 없는 `/` 하나만** 소개 페이지로 비킨다. 비밀번호 재설정 링크(`#reset_token`)로 들어왔거나 로그아웃 안내 문구가 있을 때는 비키지 않는다 — 그때는 사용자에게 할 말이 있다.

관문 밖 화면의 목록은 `app/router.test.tsx` 의 `OUTSIDE_THE_GATE` 하나로 관리한다.

## 2. 왜 관문 밖에 서도 되나

조건은 가입 화면과 같다: **기기 안·서버의 건강기록을 읽지 않을 것.**

`features/landing` 은 `useLocalDomain`·`localDomainContext`·`serverApiClient`·`shared/local/*`·`local-domain/*`·`react-query` 를 import 하지 않는다. 화면에 보이는 수치는 `landingStory.ts` 하나에 모아 둔 **예시 시나리오**다.

> 링크를 지우는 것으로는 막히지 않는다(주소는 살아 있다). 그래서 `LandingPage.test.tsx` 가 이 폴더의 원문을 훑어 금지된 import 를 찾는다 — 예전에 `/ui-preview` 가 관문 밖에서 기기 안 기록을 그대로 보여 주던 사고와 같은 종류다.

## 3. 무엇을 재사용했나

| 장면 | 재사용한 것 | 새로 만든 것 |
|---|---|---|
| 3D 인체 | `/vendor/vanatome` 아틀라스(GLB) · `anatomyAtlas`(매니페스트·메시 적응) · `anatomyResourceCache` · `holographicAnatomyStyle`(PBR 재질·통증 팔레트) | 스크롤 타임라인 장면 하나 (`scene/LandingBodyScene.tsx`) |
| 챌린지 정원 | `features/challenge/GardenArt` 의 `Tree` · `TreeKey` 계약 | — |
| 챗봇 | `globalHealthAssistant.css` 런처 스타일 · `bomi-chick.png` | 미리보기 패널(`LandingAssistant.tsx`) |
| 검진 항목 이름 | `shared/local/recordSummary.ts` 와 같은 필드명·한글 라벨 | 예시 값 |

### 3-1. `VanatomeBodyMap` 을 그대로 걸지 않은 이유

앱의 인체 뷰어는 **도구**다 — 계통 필터 툴바, 구조 검색, 치아 선택기, 깊이 피킹, 초점별 지연 로드(머리 확대 시 738개 구조 추가)가 한 몸이고 프로필·판정 위험도를 입력으로 받는다. 랜딩에는 그중 필요한 것이 없고, 오히려 "한 장면에 메시지 하나" 를 깨뜨린다. 그래서 **자산과 로더·재질은 공유하고 조작 UI 는 두지 않는** 발표용 장면을 따로 두었다. `features/home/` 쪽 파일은 한 줄도 고치지 않았다.

### 3-2. `GlobalHealthAssistant` 를 걸지 않은 이유

그 컴포넌트는 로컬 도메인 런타임과 활성 프로필이 없으면 스스로 `null` 을 반환한다(로그인 뒤에만 뜬다). 랜딩은 관문 밖이라 프로필이 없다. 런처의 생김새·마스코트·CSS 는 앱의 것을 그대로 쓰고, 내용만 미리 준비한 세 질문으로 둔다. 패널 머리에 "미리보기" 를 적어 실제 대화인 척하지 않는다.

## 4. 장면 구성

| # | 섹션 | 스크롤 | 장면 수 | 핵심 |
|---|---|---|---|---|
| 1 | Hero | 고정 1.9 화면 | — | 문장 하나 + 점이 선으로 모이는 그림 |
| 2 | 검진표·OCR | 고정 4 화면 | 연속 | 줄이 하나씩 짚이고 숫자가 종이를 떠나 데이터로 재배치 |
| 3 | 해석 | 일반 | — | 한 값을 크게(LDL 167), 나머지는 조용히 |

| 9 | 마지막 제안 | 일반 | — | 문장 하나와 버튼 하나 |

### 4-1. 3D 인체 다섯 장면

1. 인체가 떠오른다 — "몸이 기억하는 건강까지."
2. "요즘 오른쪽 무릎이 계속 아파요." → 무릎에 표식
3. "어제부터 어깨가 좀 뻐근해요." → 어깨에 표식 (**무릎은 남는다**)
4. 사용자가 복부를 고름 → 부위 정보 패널 (최근 불편 기록 2건)
5. 카메라가 물러서고 큰 카피 — "흩어진 건강 이야기를, 하나의 몸 위에 이어봅니다."

표식은 **한 번 드러나면 다시 사라지지 않는다.** 기록이 쌓인다는 것이 이 장면의 전부라서, 스크롤 도중 앞의 표식이 흐려지면 말이 뒤집힌다(`bodyScene.test.ts` 가 단조성을 지킨다).

## 5. 말의 선 — 진단하지 않는다

상태 표기는 `정상 / 주의 / 관리 필요` 셋뿐이고, 숫자 옆에는 항상 참고 기준을 적는다. "AI 진단"·"질환 확정"·"질병 예측"·"질환 발견" 은 쓰지 않으며, 그 금칙어는 `LandingPage.test.tsx` 가 렌더 결과에서 직접 찾는다. 3D 인체는 증상·불편·대화의 **기록** 도구이지 진단 도구가 아니다(docs/22 · docs/31 과 같은 선).

## 6. 스크롤 구현

- **스크롤 리스너는 페이지 전체에 하나다**(`scrollProgress.ts`). 구독자를 모아 rAF 한 프레임에 한 번만 돌린다. 섹션마다 리스너를 달면 스크롤 한 번에 `getBoundingClientRect()` 가 여덟 번 불려 매번 강제 리플로가 난다.
- **진행도는 state 가 아니라 CSS 변수로 나간다.** 섹션 요소에 `--ln-progress`(0~1)를 쓰고, 자식들이 `clamp()` 로 자기 구간만 떼어 쓴다. React state 는 장면 번호처럼 드물게 바뀌는 값만 들고 있는다.
- **3D 자산(7 MiB)은 섹션이 한 화면 앞에 올 때 받는다.** 첫 화면에서는 받지 않는다. 데이터 절약 모드(`navigator.connection.saveData`)에서는 버튼을 눌러야 받는다.
- rAF 렌더 루프는 섹션이 보이는 동안에만 돈다. 나가면 멈추고, 언마운트에서 지오메트리·재질·텍스처·렌더러를 모두 `dispose()` 한다. 실측(3초 유휴, 1440×900): **인체 섹션 305 프레임 → 푸터 3 프레임.**
- 화면 전체를 덮는 고정 요소(`.ln-nav`)와 3D 위에 얹히는 이름표에는 `backdrop-filter` 를 쓰지 않는다. 스크롤하는 동안 매 프레임 뷰포트를 블러 합성한다.

### 6-1. 밟은 함정

- **`overflow-x: hidden` 은 `position: sticky` 를 죽인다.** 루트에 걸어 두었더니 고정 구간이 통째로 안 먹어 장면들이 빈 화면으로 지나갔다. `overflow-x: clip` 은 스크롤 컨테이너를 만들지 않아 sticky 가 살아 있다.
- **배경색 전환은 글자가 없는 자리에서 한다.** 섹션 안에서 밝은색→검은색 그라데이션을 주었더니 목록 글자가 중간 밝기 위에 앉아 대비가 무너졌다. 전환 전용 빈 구간(`.ln-fade`)을 따로 둔다.
- **자동 회전은 각속도×시간이면 안 된다.** 스크롤을 멈추고 30초 읽는 동안 몸이 50° 돌아가 정면이 아니게 됐다. 지금은 ±8° 진자 운동이고, 표식이 붙는 장면에서는 멈춘다.
- **좁은 화면에서 종이와 데이터를 세로로 쌓으면 둘 다 화면 밖으로 나간다.** 375px 에서는 같은 자리에 겹쳐 두고 바꿔 끼운다. 단, **모션을 끄면 진행도가 0 에 머물러 둘 다 불투명해져 글자 위에 글자가 찍힌다** — 그때는 겹치기를 풀어 위아래로 놓는다.
- **"자산을 받기 시작할 조건" 과 "그릴 조건" 은 다른 값이다.** 로딩 트리거는 한 번 켜지면 안 꺼지게 두는데(두 번 받지 않으려고) 그것으로 렌더 루프까지 돌렸더니 인체 섹션을 지난 뒤에도 WebGL 이 계속 돌아 아래쪽 섹션 전체가 버벅였다.
- **모션을 끄면 장면이 바뀌지 않는다.** 활성 장면 하나만 그리던 코드는 그 상태에서 첫 장면 한 줄만 남기고 대화 두 줄과 마지막 카피를 통째로 삼켰다. 모션 축소에서는 다섯 장면을 전부 펼친다(`LandingPage.test.tsx` 가 지킨다).

## 7. 접근성·성능

- `prefers-reduced-motion: reduce` 에서는 고정이 풀리고 모든 장면이 위에서 아래로 한 번에 선다. 3D 인체는 회전만 멈춘 채 마지막 구도로 남는다. **기능을 빼지 않고 움직임만 뺀다.**
- 연출로만 전달되는 내용(OCR 이 읽은 값 8개, 몸에 쌓인 기록, 4주 추이)은 같은 내용의 글을 `.ln-sr-only` 로 함께 둔다.
- WebGL 이 없거나 자산을 못 받으면 정지 그림으로 대체하고, 무엇이 안 됐는지 화면에 적는다.
- 터치 타깃 44px, 목차 앵커에는 `scroll-margin-top`.
