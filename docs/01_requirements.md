# 요구사항 정의서

> 담당: 오성민(주도), 팀 전체 검토
> 관련 평가기준: 1-1, 1-2, 1-3, 3-1, 3-3, 3-4

## 1. 문제 정의 (평가기준 1-1)

**서비스**: 만성질환(고혈압·당뇨) 생활습관 챌린지 웹 서비스 — "이어봄"

**문제 상황**: 고혈압·당뇨 등 만성질환은 초기 자각 증상이 적어 진단 후에도 생활습관 관리가 지속되지 못하는 경우가 많다. 병원 진료는 간헐적(수개월 단위)인 반면, 실제 발병/악화에 영향을 주는 것은 매일의 생활습관(활동량, 식습관, 스트레스)이다. 즉 "진료와 진료 사이의 공백"을 메울 도구가 부족하다.

**근거(정량화 필요 — 팀 리서치로 보강)**:
- 국내 고혈압·당뇨 유병률 및 관리율 통계(질병관리청 국민건강영양조사 등) 인용 예정.
- 공개 데이터셋 규모로 문제의 데이터 기반 접근 가능성 입증: Kaggle "CDC Diabetes Health Indicators"(약 25만 건), AIHub 만성질환 관련 라이프로그/건강검진 데이터셋 등.

**서비스 컨셉**: "이어봄" = 건강 습관을 (매일) 이어가며, 그 변화를 (예측 모델로) 지켜본다. 진료 사이의 공백을 예측 대시보드와 챌린지로 연결한다.

**영향 범위**: 만성질환 위험군(전단계 포함) 성인, 1차적으로는 이미 진단받아 생활습관 관리가 필요한 사용자를 타깃으로 한다.

## 3. 사용자 시나리오 (예시)

1. 사용자가 회원가입 후 최초 건강 데이터(또는 설문)를 입력한다 → 만성질환 발병 가능성이 대시보드에 표시된다.
2. 사용자가 걷기 챌린지에 참여하고 매일 걸음 수를 기록한다 → 대시보드에서 예측 확률의 변화 추이를 확인한다.
3. 사용자가 LLM이 추천한 오늘의 예방 행동을 확인하고 "도움됨" 피드백을 남긴다.

## 4. AI 모델 실험 계획 (평가기준 3-1, 3-3, 3-4)

- **데이터 분리**: train/validation을 80/20(또는 k-fold)으로 분리, 테스트셋 유출(leakage) 방지.
- **평가 지표**: 최소 2개 지표 사용 — 예) Accuracy + F1-score(클래스 불균형 고려), 또는 AUROC + Recall(만성질환 특성상 위양성보다 위음성을 더 경계).
- **실험 비교**: 베이스라인(Logistic Regression) vs 개선 모델(RandomForest/XGBoost 등)을 비교하고 MLflow로 실험 기록.
- **결과 일관성(3-3)**: 랜덤 시드 고정, 동일 입력에 대해 N회(예: 10회) 반복 추론 후 결과 편차(표준편차)를 리포트.
- **피드백 반영 구조(3-4)**: REQ-06으로 수집한 피드백을 `feedback` 테이블에 저장 → 주기적으로(예: 주 1회) 배치로 집계해 재학습 데이터에 반영하는 파이프라인을 설계 문서화(구현은 Sprint 4~5).
