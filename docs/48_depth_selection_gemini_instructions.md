## Gemini에게 주는 실행 요청

구현 시작 지시를 받으면 아래 요구사항을 빠짐없이 구현·평가한다. 깊이 raycast만 추가하거나 검색창 하나로 전체 작업을 대신하지 않는다. 스마트폰에서 사용자가 의도한 치아·장기·통증 범위를 편하고 정확하게 선택하는 것이 목표다.

착수 전 AGENTS.md, docs/34, ADR 인덱스, frontend/README.md, docs/17, anatomyAtlas/VanatomeBodyMap의 실물 코드와 테스트를 읽는다. 저장 경로는 승인 ADR-011 및 47번 계약을 따른다. 채우는 칸은 의도 입력 → 후보 탐색 → 확인/피드백 → 모호함·미로드·취소 처리다. 변경 파일·테스트·되돌리는 방법을 선언한다.

## 1. 전체 범위와 사용자 맥락

피부/근막/근육/뼈/연골/겹친 장기를 관통하는 깊이 후보를 함께 찾되, 단일 치아나 장기를 고를 때는 원치 않는 구조를 선택하지 않도록 한다. 사용자는 Human Atlas를 iPhone 12 Pro Max에서 매끄럽게 사용했지만 인터페이스가 불편했다고 했다. 폭발 분해 효과를 그대로 복제하는 것이 아니라 **통증 기록에 맞는 선택 UX**를 만든다.

필수 기능은 다음 여덟 가지다:

1. 깊이 방향 다중 후보와 확정 선택.
2. 계통별 표시와 선택 허용 분리.
3. X-ray 투시 선택 모드.
4. 자동 확대·주변 구조 분리/복원.
5. 치아 전용 선택기.
6. 작은 구조의 터치 선택 허용 범위 확대.
7. 자연어/텍스트와 3D 선택 결합.
8. 검색 기반 역선택·카메라 이동.

기하 후보는 진단도 사용자의 통증 확정도 아니다. 최종 선택과 일기 저장은 사용자에게 명시적으로 보여준다.

## 2. 상태와 공통 UI 계약

- 모드: 표면 통증 칠하기, 구조 단일 선택, 깊이 후보 선택. 모드가 현재 무엇인지 표시한다.
- 상태: idle → preview → candidate choice → confirmed. cancel/undo/clear와 로딩/오류 경로를 포함한다.
- 구조별 rendered/loaded/selectable/selected를 분리한다. 숨김과 선택 금지, 미로드와 존재하지 않음을 혼동하지 않는다.
- 카메라/숨김 상태/계통 필터는 자동 탐색 전 snapshot을 저장하고 돌아오기 동작으로 복원한다.
- 후보 설명: 한글/영문명, 신체 기준 좌우, 계통, 깊이 상대 순서, 로딩·매핑 상태. 임상 확률처럼 보이는 점수 금지.
- 단일 선택 기본값에서 후보 여러 개를 자동 확정하지 않는다. 후보 preview와 최종 확인을 분리한다.
- 47번의 canonical registry/event를 소비한다. 46번 renderer가 바뀌어도 선택 로직이 특정 mesh 배열 순서에 의존하지 않게 한다.

## 3. D1 — 깊이 방향 선택

### 기하 계산

- 기존 raycast의 첫 hit만 쓰는 경로와 별도로 all-hit 경로를 만든다.
- 카메라 광선과 피부 표면 법선 안쪽 방향은 다르다. 곡면/측면에서 의도 차이를 설명하고 기본 모드를 정한다.
- 시작 표면을 결정한 뒤 방향·허용 영역·최대 깊이를 제한한다. 반대편 몸통이나 뒤에 겹친 다른 사지를 무제한 선택하지 않는다.
- '몸 중심에서 종료', '좌우가 바뀌면 종료' 같은 단순 규칙은 팔/몸통 중첩에서 틀리므로 단독 해법으로 쓰지 않는다.
- 영역별 clipping volume, 표면 shell 구간, 신체 segment와 광선 교차를 검토하고 golden fixture로 검증한다.
- 양면 교차/입구·출구 중복을 epsilon과 구조 ID로 정리한다. watertight가 아닌 mesh는 확실한 부피 진입/이탈을 주장하지 않는다.
- 각 구조의 가장 가까운 깊이와 유효 구간을 보존하고 다중 mesh/부모·자식 관계를 registry 기준으로 합친다.
- transformed/skinned mesh, 비균일 스케일 법선, 작은 빈틈, 접선 방향, 몸 밖 클릭을 처리한다.
- 모델 좌표 깊이를 환자의 실제 mm로 표시하지 않는다. 표면/얕음/중간/깊음 등의 상대 표시도 근거·한계를 밝힌다.

### 브러시와 후보

- 브러시 영역 여러 광선을 샘플링해 후보를 집계한다. 9~25개 광선/10~15Hz는 **실험 후보값**이지 확정 기준이 아니다. 낮은 비용부터 측정한다.
- preview는 제한 빈도로, pointer-up은 최종 집계로 처리한다. 입력 취소 시 결과를 확정하지 않는다.
- 표면 연결성 또는 지역 경계로 손가락 사이/팔과 몸통을 가로질러 칠해지는 문제를 막는다.
- hit 샘플 비율은 표면 coverage 근사치이며 실제 통증 확률이나 부피가 아니다.
- 후보 list와 3D 강조를 동기화하고 선택/해제/모두 지우기를 제공한다. 전체 선택에는 현재 후보 범위를 명시한다.
- 실제 자산에 근막·연골·장기가 없으면 미지원으로 표시한다. 자동으로 가상의 층을 만들지 않는다.
- 계층 미로드 시 partial 결과임을 알리고 필요한 자산을 요청한다. abort/retry와 선택 상태 보존을 구현한다.

## 4. D2 — 계통 필터와 X-ray

- 뼈/근육/장기/치아 등 계통별 선택 범위를 제공한다. 계통 preset과 개별 구조 토글이 충돌할 때 우선순위를 명시한다.
- 시각적으로 보이는 구조와 raycast 가능한 구조를 별도로 관리한다.
- 장기 모드에서 투명한 피부가 클릭을 가로채지 않게 한다. X-ray는 투시 UI이며 의료 영상이 아니다.
- 투명도만 낮추는 것으로 해결하지 말고 pickable 집합과 후보 순서를 변경한다.
- 투명 ordering/z-fighting/overdraw는 46번과 측정한다. 지원되지 않는 투시 방식은 단순 윤곽/분리 뷰로 대체할 수 있다.
- 모드 전환이 기존 선택을 조용히 다른 구조로 바꾸지 않게 한다. 숨겨진 선택 항목도 목록에서 확인/해제할 수 있어야 한다.

## 5. D3 — 자동 확대와 주변 구조 분리

- 선택 구조의 실제 bounds와 하단 시트/상단 UI를 제외한 가용 viewport로 카메라를 맞춘다.
- 앞/뒤/옆 기본 보기, 장기 중심 보기, 치아 교합면 보기를 지원한다. 과도한 확대·near plane 잘림을 막는다.
- 주변 구조를 fade/hide/부분 분리하는 수단을 비교한다. 분리는 표시 변환이며 원본 해부학 좌표와 이벤트 좌표를 변경하지 않는다.
- auto focus 중 사용자 drag가 시작되면 카메라 애니메이션을 중단한다. reduced-motion에서는 즉시 이동 등 접근 가능한 대안을 둔다.
- 원위치/이전 보기 복원을 한 번에 제공한다. 검색 전후의 필터·선택을 예상 가능하게 유지한다.

## 6. D4 — 치아 전용 선택기

- 작은 3D 치아만 직접 누르게 하지 않고 2D 치열도 + 3D 동시 강조를 제공한다.
- 성인/유치, 위/아래, 환자 좌/우, 치아 번호와 한글명을 표시한다. FDI 등 번호 체계는 1차 자료와 실제 자산 매핑을 확인한 뒤 확정한다.
- mesh 배열 순서나 이름 숫자만으로 치아 번호를 추정하지 않는다. 개별 치아가 합쳐진 mesh면 치아별 정확 선택 지원 여부를 분명히 한다.
- 누락 치아·사랑니·미매핑은 상태로 표시한다. '뒤에서 두 번째'를 사랑니 유무 확인 없이 특정 번호로 확정하지 않는다.
- 2D 선택 → 해당 치아를 잘 보이는 카메라 → 3D preview → 확정 흐름과 반대 방향 동기화를 구현한다.
- 치아 하나와 잇몸/치열 영역 선택을 구분한다. 실제 환자 결손 상태를 atlas에서 추론하지 않는다.

## 7. D5 — 터치 허용 범위 확대

- 작은 구조에 화면 공간 후보 반경을 주되 geometry 자체를 확대하지 않는다.
- broad phase의 sphere/AABB/proxy는 후보 생성용이다. 실제 교차/화면 거리/활성 계통 등으로 재평가한다.
- 20~28 CSS px 후보 반경은 실험값이며 버튼 44px 접근성 목표와 다른 개념이다. DPR 픽셀과 CSS 픽셀을 혼동하지 않는다.
- 겹치는 구조는 top-K 후보를 제시하고 나머지도 펼칠 수 있게 한다. 확대된 터치 영역이 엉뚱한 장기를 조용히 선택하지 않게 한다.
- 거리/coverage/깊이/가시성 점수의 가중치는 평가로 정한다. 예전 수치 예시는 확정값도 의학적 confidence도 아니다.
- 최근 선택 이력으로 의도를 조용히 덮어쓰지 않는다. 손가락 가림을 줄이는 offset preview/돋보기도 비교 실험한다.

## 8. D6 — 텍스트와 3D 결합

- 예: '오른쪽 아래 어금니' → 신체 오른쪽/아래턱/어금니 후보 필터. 단일 치아 번호 확정과 구별한다.
- 한글/영문/일상어 동의어를 registry와 연결하고 deterministic 파싱으로 가능한 범위를 먼저 처리한다.
- '오른쪽이 아니라 왼쪽', 여러 부위, 불명확한 깊이, 텍스트와 클릭 충돌을 테스트한다.
- 모호한 경우 후보와 확인 질문을 보여준다. 텍스트가 기존 3D 선택을 자동 저장/삭제하지 않는다.
- 선택된 목록의 이름·좌우 수정이 3D에 반영되고 3D 선택도 텍스트 chip에 반영된다.
- 선택적 LLM 파서는 허용 ID/enum만 반환하게 하고 서버 검증한다. 단순 검색에는 LLM 호출이 필요하지 않다.

## 9. D7 — 검색 기반 역선택

- 한글/영문명, 동의어, 검증된 source ID 검색 → 후보 선택 → 해당 구조 로드 → 카메라 이동 → 강조 → 확인.
- 하나의 개념이 여러 mesh에 해당하면 함께 표시하되 확정 이벤트의 의미 단위를 47번과 맞춘다.
- 현재 숨김/미로드 구조도 검색 가능하게 한다. 자동 필터 변경 내용을 사용자에게 보여주고 복원 가능하게 한다.
- 로드 중 새 검색/취소/이탈 시 stale 응답이 이전 구조를 다시 선택하지 않도록 한다.
- 빈 결과/오타/한영 혼합/지원하지 않는 구조를 처리한다. 검색명에 있다고 자산에 있는 것은 아니다.

## 10. D8 — 모바일 입력과 접근성 통합

- single tap과 회전 drag, pinch를 pointer 상태로 구분한다. multi-touch 진입 시 진행 중 단일 선택을 취소한다.
- 탭 이동 임계값은 기기별 실험한다. Human Atlas의 터치 허용 방식을 참고하되 그대로 정답으로 복사하지 않는다.
- pointercancel/lost capture/화면 회전/바깥 클릭/모달 열림에서 상태를 정리한다.
- 바닥 시트가 모델을 가리지 않도록 safe area와 실제 viewport를 반영한다.
- 키보드와 스크린리더용 구조 목록/검색/확정·취소를 제공한다. 색만으로 선택 상태를 표현하지 않는다.
- 세로/가로, 작은 화면, 확대된 글자에서 후보·확정 버튼에 접근할 수 있어야 한다.

## 11. 구현 단계와 검증

1. registry 기반 단일 선택 상태 머신 + 후보 목록 + 취소/확정부터 완성한다.
2. 깊이 all-hit과 영역 제한을 순수 기하 fixture로 검증한 뒤 UI 연결한다.
3. 계통/X-ray와 검색/auto-focus를 연결한다.
4. 치아 선택기, 넓은 터치, 텍스트 상호작용을 연결한다.
5. brush 깊이 집계와 47번 저장/재생, 46번 renderer를 통합한다.

필수 자동 fixture: 회전한 몸, 팔과 몸통 겹침, 앞/뒤 반대편 구조, 열린 shell, 중복 입출구, 미로드 계통, 작은 치아, 투명 피부 앞 장기, skinned mesh, 좌우 반전, 검색 중 취소, pinch 이후 pointer-up.

실사용 평가 과제: 특정 아래 어금니 1개, 숨은 장기 1개, 피부 영역만, 피부 아래 근육 후보, 겹친 팔만 선택, 검색 후 원래 보기 복귀. 참가자에게 정답 선택을 유도하지 말고 과제 성공률/오선택률/확정까지 시간/탭 수/취소·복구 성공을 기록한다. 표본 수와 기기 조건을 공개하고 소표본 결과를 일반화하지 않는다.

초기 제안 목표(미측정): 대표 단일 선택 과제 성공률 95% 이상, 선택 피드백 p95 100ms 이내. 안전성 fixture의 반대편 오선택·pinch 오확정·좌우 오류는 0건을 필수로 한다. 성능 기준은 46번과 같은 환경으로 측정한다. 실기기 없이 모바일 평가 완료로 표시하지 않는다.

## 12. 통합 경계·롤백·완료 조건

이 브랜치는 후보 계산/선택 상태/UX를 소유한다. 47번 registry/event를 복제 정의하지 않고, 46번 렌더러를 독자적으로 전면 교체하지 않는다. 제안 모듈은 depthPicker, selectionState, dentalPicker, anatomySearch이며 기존 구조를 확인한 후 파일명을 정한다.

기능 플래그로 구 단일 선택에 돌아갈 수 있게 하되 새로 저장한 기록은 47번 호환 reader로 계속 읽을 수 있어야 한다. 정적 자산/기존 일기 삭제 금지. 다른 작업 폴더 수정과 커밋·병합·푸시·배포는 별도 요청 없이 하지 않는다.

- [ ] 여덟 기능 각각 성공·실패·취소 경로가 구현되어 있다.
- [ ] 후보와 사용자의 확정 선택이 분리되어 저장된다.
- [ ] 미지원/미로드/불명확한 깊이를 사실대로 표시한다.
- [ ] 치아 매핑 출처와 누락 목록이 있다.
- [ ] 모바일 실기기와 접근성 평가 증거가 있다.
- [ ] 46/47번과 실제 통합했다. mock만으로는 이 항목을 완료하지 않는다.

frontend에서 lint/typecheck/test/build/e2e를 실행하고 자산 변경 시 verify:anatomy-assets를 추가한다. 서버 수정이 필요하면 47번과 경계를 먼저 조율하고 docs/34 검증 순서를 따른다. 최종 보고에는 각 기능의 구현 파일·테스트·전후 수치·실패 사례·미완료·롤백 방법을 적는다.
