# 44. 기술 선택 근거 — 문서 인식과 이미지 저장

> 작성일: 2026-09-03
> 근거: 2026-08-28 멘토링 — "Gemini 멀티모달로 시작하는 건 좋지만 한글 인식률이 부족하면 OCR API → text → query building → LLM 흐름도 비교해보기(이미 하셨으면 기록!!)", "이미지 S3 저장과 pre-signed URL, 키워드 검색 결정"
> 짝 문서: [43 챗봇](43_chatbot_question_design.md)(SSE·대화 저장) · [ADR-008](adr/0008-temporary-cloud-ocr-baseline.md) · [ADR-010](adr/0010-checkup-document-ocr-path.md)

## 0. 세 줄

- **비교는 했다. 다만 표본이 문서 1건이다.** Gemini 와 OpenAI 멀티모달을 같은 이미지로 3회씩 돌려 검사명·참고치까지 대조했고 그 표가 §1 에 있다. 전용 OCR API 와의 비교는 **아직 안 했고 그럴 채점 데이터셋이 0건**이다.
- 인식률 부족은 **모델을 바꿔서가 아니라 받는 쪽에 방어선을 세워서** 막았다. 검사명 오독은 여전히 나지만 수치 매핑 관문 셋이 그것을 통과시키지 않는다.
- **S3 저장은 요구사항을 바꾸는 결정이다.** NFR-01 이 원본 서류를 서버에 두지 말라고 했다. 저장한다면 클라이언트 암호화가 유일하게 양립하는 형태이고, 그러면 서버는 키워드 검색을 할 수 없다.

## 1. 문서 인식 — 무엇을 비교했고 무엇을 아직 안 했나

### 1.1 지금 돌고 있는 것

**멀티모달 직송이다.** 이미지·PDF 를 모델에 그대로 넣고 구조화 JSON 을 받는다. 전용 OCR 을 앞에 두지 않는다.

| 항목 | 값 |
|---|---|
| 모델 | `openai:gpt-4o-mini` 단독 (`DEV_OCR_MODELS`) |
| 입력 | JPEG·PNG·PDF. PDF 는 base64 `file` 파트로 직접 |
| 해상도 | `detail: high` 고정. 기본 `auto` 는 이미지를 줄여서 본다 |
| 경로 | nginx → FastAPI → Redis Stream → ai-worker → Redis 청크 → SSE |
| 예비 | **없다.** `gpt-4o-mini` 가 막히면 인식 전체가 멈춘다 |

### 1.2 실측 비교 — Gemini vs OpenAI

`sample.jpeg` 3회 반복, 정답은 원본 이미지를 직접 확인.

| | 값 6개 | 검사명 | 참고치 | 속도 |
|---|---|---|---|---|
| Gemini 3.5-flash-lite | 6/6 | **6/6** | **6/6** | 첫 청크 2.8s |
| gpt-4o-mini, 프롬프트 수정 전 | 6/6 | 2~4개 오류·매회 다름 | 지어냄 | — |
| gpt-4o-mini, 수정 후 | 6/6 | 5/6 (`크레아티닌`→`크레아틴`) | 계속 어긋남 | 첫 청크 2.5s |

**가장 위험했던 오독**: 프롬프트 수정 전 `요소질소`(BUN 12.0)가 `요산` 으로 읽혀 **`요산` 행이 둘** 나왔다. 그대로 매핑되면 요산 6.1(정상)인 사람이 12.0 으로 잡혀 중증 고요산혈증이 된다.

**진짜 지렛대는 모델이 아니라 프롬프트였다.** 기존 프롬프트가 "보기 쉽고 명확하게 정형화" 하라고 하고 예시도 표준 검사명이라, 못 읽은 칸을 그럴듯한 표준명과 교과서 참고치로 채우도록 유도하고 있었다. 전사 충실도 규칙(적힌 그대로 · 참고치는 인쇄된 것만 · 불확실하면 빈 문자열 · 같은 검사명이 두 번 나오면 오독)을 넣자 중복이 사라졌다.

### 1.3 그런데도 OpenAI 로 간 이유

2026-08-27 에 정확도 때문에 Gemini 로 되돌렸다가 2026-08-28 에 팀 결정으로 다시 OpenAI 단독이다. **오독이 사라져서가 아니라 받는 쪽에 방어선을 세웠기 때문**이다.

`ocr_measurements.py` 가 인식 결과를 수치로 옮길 때 **이름을 믿지 않는 관문 셋**을 통과시킨다. 검사명이 틀려도 값의 단위·범위·중복이 맞지 않으면 매핑하지 않는다. 그래서 `크레아틴` 오독이 확률에 닿지 않는다.

**참고치 열은 아예 쓰지 않는다.** 원본에서 이름 열과 세로로 어긋나 있어 모델이 자주 밀리고, 판정은 `chronic_disease_engine` 의 자체 기준을 쓰므로 의존할 이유가 없다.

### 1.4 아직 안 한 비교 — 멘토가 물은 그 흐름

멘토가 물은 것은 `전용 OCR API → text → query building → LLM` 이다. **안 했다.** 이유를 정확히 적는다.

| 막는 것 | 상태 |
|---|---|
| 채점 데이터셋 | ~~**0건**~~ → **2026-09-03 에 24장 구축.** 아래 §1.6 |
| Naver CLOVA 키 | 발급 주체·월 비용 한도 미정 |
| 비교 기준 | 16번 문서 §6 에 축은 있다 — 정확도·지연·비용·외부 전송 여부·처리량 |

**표본이 1건이라는 사실이 위 §1.2 표의 한계다.** "Gemini 가 검사명 6/6" 은 그 이미지에서 그랬다는 뜻이지 일반화할 수 없다. 발표에서 이 표를 쓸 때 반드시 같이 말해야 한다.

### 1.5 결정과 다음 단계

| # | 항목 | 결정 |
|---|---|---|
| 1 | 이번 릴리스 경로 | 멀티모달 직송 유지 (`openai:gpt-4o-mini`) |
| 2 | 인식률 대응 | 모델 교체가 아니라 **매핑 관문**으로 막는다 (이미 적용) |
| 3 | 전용 OCR 비교 | ~~채점 데이터셋을 먼저 만든다~~ → **세트가 생겼다(§1.6).** 이제 Naver 키만 있으면 같은 명령으로 비교된다 |
| 4 | 예비 경로 | `gpt-4o-mini` 단일 실패점이다. Gemini 항목을 목록 뒤에 되살릴지 결정 필요 |

3번이 선행이었다. 데이터셋은 합성 검진표로 만들 수 있고([27번](27_eda_new_data_and_synthetic.md) §4.2 가 서빙 픽스처에 같은 방식을 썼다), 개인정보가 없어 공유도 된다.

### 1.6 채점 데이터셋 v0.1 — 24장

```bash
uv run python modeling/data/make_ocr_eval_set.py --count 24   # 이미지 + 정답
uv run python scripts/score_ocr.py --report modeling/artifacts/ocr_score.json
```

정답을 **값에서 그림 쪽으로** 만든다 — 값을 먼저 뽑고 그 값으로 이미지를 그린다.
16번 문서 §11.2 의 *"엔진 출력을 정답으로 복사하지 않는다"* 가 구조적으로 지켜진다.
개인정보 0건이라 저장소에 넣고 공유한다.

흔드는 축은 넷이다. **이름**(검사 하나에 별칭 2~3개), **판형**(표 4 · 두 칸 13 ·
한 줄 7), **참고치 인쇄 여부**(65%), **잡음**(JPEG 품질·미세 회전·얼룩).
사전에 없는 항목(`총단백`·`총빌리루빈`·`BUN`)을 일부러 섞어 **오배정**을 잰다.

세 숫자를 따로 센다. 합치면 성격이 다른 실패가 서로를 가린다.

| | 뜻 | 왜 따로 |
|---|---|---|
| 재현율 | 정답 수치 중 몇 개를 꺼냈나 | 못 꺼낸 값은 화면이 "안 넣음" 으로 표시하고 사용자가 채운다 |
| 정확도 | 꺼낸 것 중 몇 개가 맞나 | |
| **오배정** | **다른 칸에** 넣었나 | 틀린 채로 판정까지 간다. 가장 비싼 실패 |

**기준선 (2026-09-03 · `openai:gpt-4o-mini` · 24장 223수치)** — 재현율 94.2%
(210/223) · 정확도 99.5% · **오배정 0** · 장당 중앙값 4.2초.

세트를 만들자마자 **사전 구멍 셋**이 나왔고 고쳤다. 재현율 91.9% → 94.2%.

| 무엇 | 왜 못 잡았나 |
|---|---|
| `트리글리세리드` | 실제로 쓰이는 표기인데 사전에 `트리글리세라이드` 만 있었다 |
| `요알부민/크레아티닌비` | 정규화가 단위(`mg/dL`) 때문에 `/` 를 남긴다. 검사명에서는 그게 사전과 어긋난다 |
| `γ-GTP` | `_KEEP` 이 그리스 문자를 지워 `gtp` 만 남았다. 이름(`gammagtp`)으로 펴서 해결 |

**남은 약점은 사전이 아니라 행 파싱이다.** `urine_acr` 이 3/10 인데 이름은 이제 다 잡는다.

- `synth-007`(표 판형): 인식 결과가 `검사항목명: 알부민크레아티닌비` 로 나온다.
  표 머리글이 이름에 붙어 사전과 안 맞는다.
- `synth-001`(한 줄 판형): `UACR 247` 인데 **옆 행의 값 93** 이 들어왔다. 세트에서
  유일한 "값이 틀림" 1건이고 관문이 못 잡는 종류다 — 둘 다 DTO 범위 안이다.

둘 다 재현 가능하다. 모델을 바꿀 자리가 아니라 파싱을 고칠 자리다.

## 2. 이미지 저장 — S3 를 쓸 것인가

### 2.1 지금 상태

**원본 이미지를 어디에도 저장하지 않는다.**

| 단계 | 어디 | 얼마나 |
|---|---|---|
| 업로드 | nginx → FastAPI 메모리 | 요청 수명 |
| 큐 전달 | Redis Stream payload | **TTL 10분**, 워커가 처리하면 즉시 삭제 |
| 인식 결과 | 클라이언트로 반환 | 서버 저장 없음 |
| 보관 | 사용자 기기 로컬 보관함 | 계정별 암호화 |

nginx `client_max_body_size 64m`, 앱 상한은 파일당 20MB·합계 30MB 다.

### 2.2 S3 는 요구사항을 바꾸는 결정이다

NFR-01: **"서버는 건강정보 원문, 원본 건강서류, OCR 결과와 예측 결과를 저장하지 않아야 한다."**

S3 는 서버 저장이다. 그래서 "S3 를 쓸까" 는 기술 선택이 아니라 **요구사항 변경 제안**이고, 세 갈래뿐이다.

| 안 | 형태 | NFR-01 | 키워드 검색 | 판정 |
|---|---|---|---|---|
| A | 저장하지 않음 (현행) | 지킨다 | 검색할 대상이 없다 | **이번 릴리스 채택** |
| B | 클라이언트 암호화 후 S3 | 지킨다(서버가 못 연다) | **서버는 못 한다.** 로컬 인덱스가 한다 | 다음 후보 |
| C | 평문 S3 | **위반** | 서버가 할 수 있다 | 기각 |

C 를 고르면 ADR-007(계정별 암호화 로컬 보관함)과 ADR-001(로컬 우선)이 함께 무너진다. 그 둘을 뒤집는 ADR 을 새로 써야 하는 일이고 이번 일정 안에서 할 결정이 아니다.

### 2.3 B 안을 고른다면 — 구체 형태

지금 채택하지는 않지만, 물었을 때 답할 수 있게 형태를 적어 둔다.

```
업로드   클라이언트가 AES-GCM 으로 암호화
         → POST /documents/upload-url 로 presigned PUT URL 요청 (서버는 키를 모른다)
         → S3 에 직접 PUT (서버를 거치지 않는다 = 대역폭·메모리 절약)
         → 객체 키와 IV 를 로컬 보관함에 기록

내려받기 GET /documents/{id}/download-url → presigned GET (5분)
         → 클라이언트가 받아서 복호화

검색     서버가 못 한다(암호문이다). 로컬 보관함의 인덱스가 한다 —
         검진일·검사명·수치 범위. 43번 문서 §3 의 "도구 호출" 과 같은 구조다.
```

**presigned URL 의 값어치는 서버를 거치지 않는 것**이다. 20MB 이미지가 FastAPI 메모리를 지나가지 않고, 지금 `client_max_body_size 64m` 로 열어 둔 구멍도 좁힐 수 있다.

**유효기간은 짧게.** 업로드 10분, 다운로드 5분. 링크가 로그·기록에 남으면 그 시간만큼 노출된다.

### 2.4 결정

| # | 항목 | 결정 |
|---|---|---|
| 1 | 이번 릴리스 | **저장하지 않는다.** Redis TTL 10분 경로 유지 |
| 2 | S3 | B 안(클라이언트 암호화 + presigned)만 후보. 채택하려면 ADR 을 새로 쓴다 |
| 3 | 키워드 검색 | **서버가 하지 않는다.** 로컬 인덱스가 한다 |
| 4 | 선행 조건 | 원본을 다시 볼 필요가 실제로 있는지부터 확인한다 — 지금 화면 어디도 원본 재열람을 요구하지 않는다 |

4번이 핵심이다. **저장할 이유를 먼저 찾고 저장 방법을 정하는 순서**여야 한다. 지금은 인식이 끝나면 수치만 쓰고 원본은 버리는데, 그것으로 화면이 다 돌아간다.
