# 와이어프레임 가이드

> 담당: 정다원(주도)
> 관련 문서: [01_requirements.md](01_requirements.md), [08_account_profile_policy.md](08_account_profile_policy.md), [ADR-001](adr/0001-web-local-first-architecture.md)
> 실제 Figma 산출물은 이 문서를 기준으로 갱신한다.

## 1. 디자인 원칙

- Shadcn/ui와 Tailwind CSS 기반 공통 컴포넌트를 사용한다.
- 데스크톱과 모바일에서 용어와 작업 순서를 동일하게 유지한다.
- `서비스 계정`과 `가족 구성원 로컬 프로필`을 시각적으로 구분한다.
- 건강정보 저장 위치를 작업 맥락에 맞게 표시한다.
- 공통 정책은 화면마다 반복하지 않고 최초 안내에서 설명한 뒤 주요 작업에는 짧은 상태 문구를 사용한다.
- 파괴적 작업과 병합에는 대상, 영향, 되돌리기 가능 여부를 명확히 표시한다.

## 2. 확정 용어

| 사용 | 사용하지 않음 |
|---|---|
| 서비스 계정 | 로컬 계정 |
| 가족 구성원 로컬 프로필 | 가족 구성원 계정(연결 전) |
| 기존 프로필에 계정 연결 | 계정이 건강정보를 소유 |
| 기존 프로필과 합치기 | 삭제 후 다시 연결 |

`대표 관리자`, `공동 관리자` 역할은 확정 전까지 화면에 추가하지 않는다.

## 3. 주요 내비게이션

- 홈·구성원
- 건강 대시보드
- 건강기록 작성
- 데이터 관리
- 계정·설정

## 4. 화면 목록

### 4.1 1순위 — 계정·로컬 프로필·건강기록

| 화면 | 목적 | 주요 상태·안내 |
|---|---|---|
| 서비스 시작 | 로그인·가입 진입 | 서비스 계정과 건강정보 보관 위치 구분 |
| 회원가입·로그인 | 서비스 계정 인증 | 계정 생성이 건강정보 업로드를 의미하지 않음을 안내 |
| 개인정보·로컬 보관 안내 | 서버·기기 데이터 경계 확인 | 기기 저장, 백업 책임, 계정 해지 영향 안내 |
| 가정 생성 | 로컬 가정 데이터 시작 | 가정이 현재 기기에 생성됨을 표시 |
| 홈·구성원 목록 | 가족 프로필 조회 | 로컬 프로필과 계정 연결 상태를 구분 |
| 구성원 등록·수정 | 로컬 프로필 관리 | 이름·관계·생년, `이 기기에 저장` |
| 구성원 상세 | 건강기록 진입 | 계정 연결 여부와 무관하게 로컬 기록 표시 |
| 건강기록 통합 작성 | 기록 유형별 입력 | 외부 전송 없음 |
| 건강 이력·상세·수정·삭제 | 기록 관리 | 삭제 영향과 로컬 변경 이력 안내 |
| 데이터 관리 | 백업·가져오기·복구 진입 | 마지막 백업 시각과 로컬 저장 상태 |
| 암호화 백업 내보내기·가져오기 | 데이터 이전·복구 | 비밀번호 분실, 포함 항목, 충돌 가능성 |

### 4.2 2순위 — 가족 초대·계정 연결·프로필 병합

| 화면 | 목적 | 주요 상태·안내 |
|---|---|---|
| 계정·구독 | 서비스 계정과 라이선스 확인 | 건강정보 미저장 안내 |
| 연결할 기존 프로필 선택 | 가족 초대 대상을 선택 | `새 구성원 추가`와 명확히 분리 |
| 가족 초대 발송 | 이메일로 서비스 계정 초대 | 초대만으로 건강정보가 공유되지 않음 |
| 초대 로그인·신규 가입 | 초대받은 사용자의 인증 | 새 로컬 프로필 자동 생성 금지 |
| 초대 수락 | 대상 프로필과 연결 확인 | 기존 프로필 요약, 초대 만료 상태 |
| 프로필 연결 완료 | 서비스 계정·로컬 프로필 연결 | 다음 단계인 접근 범위·암호화 이전 파일 안내 |
| 중복 프로필 감지 | 잘못 만든 새 프로필 발견 | 삭제보다 병합 권장 |
| 병합 대상 선택 | 유지할 기존 프로필 선택 | 다른 사람 병합 방지 정보 확인 |
| 프로필·기록 비교 | 기본정보와 데이터 비교 | 항목 수, 차이, 중복 표시 |
| 중복·충돌 검토 | 항목별 유지 값 선택 | 더 넓은 접근 범위 자동 적용 금지 |
| 병합 최종 확인 | 영향과 복구 지점 확인 | 원본 보존, 숨김 처리, 되돌리기 기한 |
| 병합 완료 | 계정 재연결과 처리 결과 확인 | 되돌리기 제공 |

### 4.3 3순위 — 접근 범위·선택 데이터 이전·WebRTC 기술검증

| 화면 | 목적 | 주요 상태·안내 |
|---|---|---|
| 건강정보 접근 범위 | 공유할 구성원·기록 유형 선택 | 기본 최소 범위, 사용자 동의 |
| 암호화 이전 파일 생성 | 허용 데이터만 파일로 내보내기 | 비밀번호, 만료 안내, 포함 항목 확인 |
| 암호화 이전 파일 가져오기 | 상대 사용자의 브라우저에 저장 | 무결성·버전·충돌 확인 |
| WebRTC 직접 전송 기술검증 | 브라우저 간 페어링과 전송 검증 | 후순위 실험 기능, 중계 가능성과 지원 환경 안내 |
| 직접 전송 충돌 검토 | 기술검증 채택 시 충돌 해결 | 항목별 유지·병합 선택 |

## 5. 핵심 유저플로우

### 5.1 첫 가족 기록 생성

```text
가입·로그인 → 로컬 보관 안내 → 가정 생성
→ 가족 구성원 로컬 프로필 생성 → 프로필별 건강기록 작성
```

### 5.2 기존 로컬 프로필에 가족 계정 연결

```text
기존 프로필 선택 → 초대 발송 → 로그인 또는 신규 가입
→ 초대 수락 → 기존 프로필과 서비스 계정 연결
→ 접근 범위 확인 → 암호화 이전 파일 생성
→ 초대받은 사용자가 파일 가져오기 → 브라우저 로컬 저장
```

### 5.3 잘못 만든 프로필에 데이터가 없는 경우

```text
중복 감지 → 새 프로필 연결 해제 → 기존 프로필 선택
→ 서비스 계정 재연결 → 빈 프로필 삭제
```

### 5.4 잘못 만든 프로필에 데이터가 있는 경우

```text
중복 감지 → 기존 프로필과 합치기 → 프로필·기록 비교
→ 충돌 검토 → 복구 지점 확인 → 병합
→ 잘못 만든 프로필 숨김 → 완료·되돌리기
```

## 6. 화면 문구 원칙

- `서비스 계정으로 건강정보를 저장합니다` 같은 표현을 사용하지 않는다.
- 초대·연결 완료 화면에서 건강정보 공유가 완료된 것처럼 표현하지 않는다.
- 계정 연결과 기기 간 건강정보 전송을 별개의 단계로 표시한다.
- 중복 프로필 발견 시 `삭제`보다 `기존 프로필과 합치기`를 기본 행동으로 강조한다.
- 병합 전후 항목 수와 원본 보존 여부를 표시한다.

## 7. 필수 예외 상태

- 초대 만료·거절·취소
- 이미 다른 프로필에 연결된 계정
- 중복 프로필 후보가 서로 다른 사람일 가능성
- 병합 중 저장공간 부족 또는 처리 실패
- 서버 연결 변경 실패 후 로컬 롤백 필요
- 암호화 이전 파일의 비밀번호 오류·손상·지원하지 않는 버전
- WebRTC 기술검증의 페어링 실패·네트워크 중단·중계 필요
- 직접 전송 기술을 채택한 경우의 동기화 충돌
- 병합 취소 기한 만료

## 8. Figma 반영 체크리스트

- [ ] 서비스 계정과 로컬 프로필 설명이 분리되어 있는가?
- [ ] 기존 프로필을 선택한 뒤 초대하는가?
- [ ] 초대 수락 시 새 프로필을 자동 생성하지 않는가?
- [ ] 계정 연결과 건강정보 전송이 별도 단계인가?
- [ ] 새 프로필 오등록 시 병합 흐름이 있는가?
- [ ] 병합 전에 비교·충돌 검토·복구 지점을 보여주는가?
- [ ] 병합 완료 후 되돌리기를 제공하는가?
- [ ] 초기 버전의 데이터 이전이 암호화 파일 내보내기·가져오기로 표현되어 있는가?
- [ ] Wi-Fi/WebRTC 직접 동기화가 확정 기능이 아닌 후순위 기술검증으로 표시되어 있는가?
