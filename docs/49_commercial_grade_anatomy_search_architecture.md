# 상용 서비스 수준의 3D 해부학 검색 아키텍처 및 체감 테스트 로드맵

> **관련 규칙 및 문서**: [34_project_rules_and_workflow.md](34_project_rules_and_workflow.md) · [48_depth_selection_gemini_instructions.md](48_depth_selection_gemini_instructions.md)
> **목적**: 3D 인체 모델에서 사용자가 일상적인 표현(부위명, 증상, 띄어쓰기 복합어)으로 검색했을 때 원하는 해부학 구조를 즉시 찾아 선택할 수 있도록, 상용 의료/해부학 서비스 수준의 다계층 검색 아키텍처를 정의하고 단계별 적용·검증 체계를 수립한다.

---

## 1. 배경 및 문제 의식

* **현상**:
  - 사용자가 `"어깨 회전근개"`, `"무릎 관절"`, `"허리 디스크"` 등 2개 이상의 단어로 이루어진 일상적 검색어를 입력했을 때, 기존 단순 부분 문자열 일치(`includes`) 방식에서는 단어의 순서나 조사가 달라 일치하는 결과가 0건으로 나오는 문제 발생.
  - 경추(C1~C7), 흉추(T1~T12), 요추(L1~L5) 등 세부 분절 번호가 있는 구조가 공통 라벨(`척추뼈`)로 뭉개져 검색 및 선택 구분이 불가능했던 문제 발생.
* **해결 목표**:
  - 전문 의학 라틴어("Supraspinatus")를 모르는 일반 사용자도 일상 한국어와 증상 표현만으로 3D 인체 내 해당 부위를 정확하게 탐색하고 선택할 수 있도록 검색 품질을 상용 서비스 수준으로 단계적 고도화.

## 2. 상용 서비스 벤치마킹 (Commercial Benchmarks)

글로벌 3D 의료/해부학 상용 소프트웨어(Complete Anatomy, Visible Body, BioDigital Human, WebMD)의 검색 엔진 분석 결과:

```
[사용자 질의] "어깨 회전근개", "허리 디스크", "ㅇㄲ"
        │
        ▼
┌──────────────────────────────────────────────────────────┐
│ Tier 1. 텍스트 정규화 & 다중 토큰 엔진 (Tokenization & Norm) │
│  - 공백 제거 정규화 ("회전 근개" ↔ "회전근개")           │
│  - 다중 토큰 AND/OR 결합 ("어깨" AND "회전근개")         │
└──────────────────────────────────────────────────────────┘
        │
        ▼
┌──────────────────────────────────────────────────────────┐
│ Tier 2. 해부학 표준 온톨로지 계층 트리 (FMA / SNOMED CT)    │
│  - Is-A / Part-Of 관계망 전개                            │
│  - "회전근개" ──(part-of)──> 극상근, 극하근, 견갑하근, 소원근 │
│  - "경추" ──(has-part)──> C1, C2, C3, C4, C5, C6, C7     │
└──────────────────────────────────────────────────────────┘
        │
        ▼
┌──────────────────────────────────────────────────────────┐
│ Tier 3. 임상 증상 ↔ 해부학 메쉬 교차 매핑 (Clinical Cross-Map)│
│  - 일상 질환/증상명 ──> 연관 해부학 부위 연결            │
│  - "오십견" ──> 어깨관절낭, 유착성 관절낭염              │
│  - "목/허리 디스크" ──> 경추/요추 추간판 및 신경근       │
└──────────────────────────────────────────────────────────┘
        │
        ▼
┌──────────────────────────────────────────────────────────┐
│ Tier 4. 한글 형태소·자모 분해 & 오타 허용 (Fuzzy & Choseong)│
│  - 초성 검색: "ㅎㅈㄱㄱ" ──> 회전근개                    │
│  - 편집 거리(Levenshtein): "회전근게" ──> "회전근개" 추천│
└──────────────────────────────────────────────────────────┘
        │
        ▼
┌──────────────────────────────────────────────────────────┐
│ Tier 5. 시맨틱 임베딩 & RAG (최신 AI 확장)               │
│  - 자연어 증상 서술: "팔 올릴 때 찌릿한 어깨 뒤쪽"      │
│  - 벡터 유사도(Vector Cosine) 기반 후보 메쉬 랭킹 추천   │
└──────────────────────────────────────────────────────────┘
```

## 3. 5계층 아키텍처 상세 설계

### Tier 1. 토큰화 및 공백 정규화 (1단계 - 즉시 적용 완료)
* **목표**: 띄어쓰기 차이, 단어 어순 차이 극복.
* **구현 원리**:
  - `tokens = query.trim().toLowerCase().split(/\s+/)`
  - `cleanQ = query.replace(/\s+/g, '')`
  - 모든 토큰이 대상 데이터(한글명, 영문명, 계통명, 설명문)에 포함되어 있는지 검사(AND).
  - 공백을 제거한 순수 문자열 간의 포함 관계도 함께 검사하여 `"회전 근개"`와 `"회전근개"` 상호 호환.

### Tier 2. 부위군 및 표준 온톨로지 그룹 매핑 (2단계 - 핵심 적용 완료)
* **목표**: 단일 메쉬가 아닌 '복합 구조군'을 검색했을 때 소속 메쉬들을 일괄 검색 결과로 추천.
* **주요 사전 매핑**:
  - **회전근개 (Rotator cuff)**: 극상근(Supraspinatus), 극하근(Infraspinatus), 견갑하근(Subscapularis), 소원근(Teres minor)
  - **햄스트링 (Hamstrings)**: 대퇴이두근(Biceps femoris), 반건양근(Semitendinosus), 반막양근(Semimembranosus)
  - **대퇴사두근 (Quadriceps)**: 대퇴직근, 외측광근, 내측광근, 중간광근
  - **경추 (Cervical vertebrae)**: 환추(C1), 축추(C2), C3~C7
  - **흉추 (Thoracic vertebrae)**: T1~T12
  - **요추 (Lumbar vertebrae)**: L1~L5

### Tier 3. 임상 증상 ↔ 해부학 교차 매핑 (3단계 로드맵)
* **개념**: 환자/일반인이 검색하는 병명이나 통증 표현을 3D 부위로 매핑.
* **데이터 사전 예시**:
  ```ts
  export const CLINICAL_SYMPTOM_MAP: Record<string, { targetKeys: string[]; description: string }> = {
    "오십견": {
      targetKeys: ["supraspinatus", "infraspinatus", "subscapularis", "glenohumeral"],
      description: "어깨 관절을 감싸는 관절낭의 염증과 회전근개 구축과 관련된 부위입니다.",
    },
    "허리 디스크": {
      targetKeys: ["vertebra-l4", "vertebra-l5", "sacrum"],
      description: "요추 4-5번 및 천추 사이 추간판 탈출과 관련된 주요 허리 척추 부위입니다.",
    },
    "테니스 엘보": {
      targetKeys: ["extensor carpi radialis brevis", "lateral epicondyle"],
      description: "팔꿈치 외측 상과 및 신전근 힘줄 부착부 통증과 관련된 부위입니다.",
    },
  };
  ```

### Tier 4. 한글 자모 분해 & 초성 검색 (4단계 로드맵)
* **목표**: 모바일/웹 입력 편의성 극대화 (`"ㅇㄲ"`만 쳐도 `"어깨"` 노출).
* **구현 방식**:
  - 유니코드 초성 분해(0xAC00 기반) 유틸리티 적용 (`"어깨"` → `"ㅇㄲ"`, `"승모근"` → `"ㅅㅁㄱ"`).
  - 인덱싱 시 사전에 초성 필드(`choseong: "ㅇㄲ"`)를 사전 생성하여 빠른 정규식 매칭.

### Tier 5. 시맨틱 벡터 임베딩 & RAG 질의 (5단계 로드맵)
* **목표**: 일상 문장형 질문("팔을 위로 뻗을 때 날개뼈 밑이 결려요") 지원.
* **스택**: 로컬 임베딩 모델(또는 Gemini 임베딩 API) + 3D 메쉬 설명 벡터 DB.
* **동작**: 사용자의 문장 벡터와 800개 메쉬 설명 벡터의 코사인 유사도를 계산하여 상위 5개 부위를 3D 뷰어에서 카메라 포커스와 함께 자동 하이라이트.

## 4. 단계별 적용 및 "체감 A/B 테스트" 방법론

기능을 한 번에 무겁게 넣지 않고, 사용자가 직접 체감하면서 효용성을 비교할 수 있도록 단계별 토글(Toggle) 플래그를 운영합니다.

| 단계 | 적용 모듈 | 검증 검색어 | 성공 판정 기준 (체감 테스트) |
|---|---|---|---|
| **Phase 1** (현재 적용) | 다중 토큰 AND + 공백 정규화 | `어깨 회전근개`, `회전 근개`, `갈비 뼈` | 0건 오류 탈출, 극상근·극하근 등 4개 근육 즉시 노출 |
| **Phase 2** (현재 적용) | 척추/갈비뼈 분절 번호 보존 | `경추 3번`, `C3`, `갈비뼈 8번` | 팝오버 및 선택창에서 C3, C4가 독립 번호로 명확히 분리 |
| **Phase 3** (차기) | 임상 질환 교차 매핑 | `오십견`, `목디스크`, `허리디스크` | 병명 입력 시 관련 척추/관절낭/근육 추천 칩 노출 |
| **Phase 4** (차기) | 한글 초성 검색 | `ㅇㄲ`, `ㅅㅁㄱ`, `ㅎㅈㄱㄱ` | 첫 글자 초성 입력 단계에서 자동완성 드롭다운 반응 |
| **Phase 5** (차기) | 자연어 시맨틱 RAG | *"고개 돌릴 때 뻐근한 목 뒤쪽"* | 흉쇄유돌근, 판상근, 승모근 상위 3개 추천 및 3D 카메라 줌인 |

## 5. 결론 및 유지보수 규칙

1. **`ANATOMY_DICTIONARY`의 지속적 확장**: 신규 메쉬가 Three.js 씬에 추가될 때마다 번호 및 좌우 방향성이 유지되는 규칙을 우선 적용한다.
2. **선택 판정 무결성**: 3D 부위 선택 상태(`isSelected`)는 절대 사용자 표시 문자열(`label`)로 비교하지 않고, `mesh.id` 또는 `mesh` 인스턴스 1:1 참조로만 판정한다.
