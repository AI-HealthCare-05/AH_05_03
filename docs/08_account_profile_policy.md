# 서비스 계정·가족 구성원 로컬 프로필 정책

> 상태: 초기 기준안
> 확정 범위: 서비스 계정, 가족 구성원 로컬 프로필, 초대·연결·병합 구조
> 미확정 범위: 대표 관리자·공동 관리자 등 별도 관리자 역할
> 웹 전환 아키텍처 기준: [ADR-001](adr/0001-web-local-first-architecture.md)

## 1. 선택한 제품 방향

이어봄은 **가족 계정 포함** 방향으로 설계한다. 서비스 계정을 통해 가족을 초대하고, 초대받은 가족의 서비스 계정을 기존 가족 구성원 로컬 프로필과 연결할 수 있다.

단, 서비스 계정과 건강정보는 분리한다. 서비스 계정이나 초대 관계만으로 다른 가족의 건강정보에 자동으로 접근할 수 없다.

## 2. 핵심 개념

### 2.1 서비스 계정

사용자가 직접 가입하고 로그인하는 서버 계정이다.

- 인증과 로그인
- 구독·라이선스 관리
- 가족 초대 및 수락 상태 관리
- 프로필 연결에 필요한 최소 식별정보 관리
- 연결 기기 상태 관리

서비스 계정은 건강기록의 저장 단위가 아니며, 계정 보유만으로 다른 가족의 건강정보 접근 권한을 얻지 않는다.

### 2.2 가족 구성원 로컬 프로필

건강기록의 대상을 구분하기 위해 사용자 기기에 저장하는 프로필이다.

- 별도의 로그인과 비밀번호가 없다.
- 이름, 관계, 생년 정보와 건강기록을 연결한다.
- 건강 관련 정보와 함께 기기에 로컬로 저장한다.
- 문서와 화면에서 `로컬 계정`이 아니라 `가족 구성원 로컬 프로필`로 표기한다.

## 3. 데이터 저장 경계

### 3.1 서버에서 처리할 수 있는 정보

- 서비스 계정 인증정보
- 구독·라이선스 상태
- 가족 초대 및 수락 상태
- 프로필 연결에 필요한 최소 식별정보
- 연결 기기 상태

### 3.2 사용자 기기에만 저장하는 정보

- 가족 구성원 프로필의 건강 관련 정보
- 건강기록과 통증 기록
- 가족력과 유전정보
- 원본 건강서류
- OCR 결과
- 예측 결과
- 로컬 변경 이력과 복구 지점

건강정보 공유는 사용자 동의 후 허용 데이터로 암호화 이전 파일을 만들고 상대 사용자가 직접 가져오는 방식으로 수행하며, 가져온 정보는 해당 브라우저의 로컬 저장소에 저장한다. 서비스 계정 초대나 프로필 연결만으로 건강정보가 서버에 업로드되거나 서버에서 내려받아지지 않는다. WebRTC 직접 전송은 후순위 기술검증을 통과한 뒤 채택 여부를 결정한다.

## 4. 가족 계정 초대와 프로필 연결

처음에는 서비스 계정 사용자가 가족 구성원 로컬 프로필을 대신 생성하고 건강기록을 관리할 수 있다. 해당 가족이 직접 서비스를 사용하게 되면 기존 로컬 프로필을 선택해 서비스 계정 초대를 보낸다.

초대받은 사용자는 로컬 프로필을 만든 경험이 없어도 된다. 기존 서비스 계정으로 로그인하거나 새 서비스 계정을 만든 뒤 초대를 수락한다. 수락 후 새 프로필을 자동 생성하지 않고 초대 대상인 기존 로컬 프로필에 서비스 계정을 연결한다.

1. 기존 가족 구성원 로컬 프로필 선택
2. 서비스 계정 초대 발송
3. 초대받은 사용자의 로그인 또는 신규 가입
4. 초대 수락
5. 기존 로컬 프로필과 서비스 계정 연결
6. 공유할 건강정보와 접근 범위 확인
7. 허용된 건강정보로 암호화 이전 파일 생성
8. 사용자가 선택한 외부 방법으로 이전 파일 전달
9. 초대받은 사용자가 파일을 가져와 브라우저 로컬 저장소에 저장

하나의 서비스 계정은 같은 가정 안에서 하나의 가족 구성원 로컬 프로필에만 연결할 수 있다.

## 5. 잘못 만든 새 프로필의 복구

초대받은 사용자가 기존 프로필에 연결하지 않고 새 구성원 프로필을 만든 경우 기본 복구 동작은 `삭제 후 다시 연결`이 아니라 `기존 프로필과 합치기`로 제공한다.

### 5.1 새 프로필에 건강정보가 없는 경우

1. 서비스 계정과 잘못 만든 프로필의 연결 해제
2. 연결할 기존 로컬 프로필 선택
3. 서비스 계정을 기존 프로필에 연결
4. 잘못 만든 빈 프로필 삭제

### 5.2 새 프로필에 건강정보가 있는 경우

1. `기존 프로필과 합치기` 선택
2. 병합할 기존 로컬 프로필 선택
3. 두 프로필의 기본정보와 건강기록 비교
4. 이름·생년·관계 및 중복 기록 충돌 검토
5. 건강기록·원본 서류·가족력·메모를 기존 프로필로 이전
6. 서비스 계정을 기존 프로필에 연결
7. 병합 결과 확인
8. 잘못 만든 프로필을 영구 삭제하지 않고 숨김 처리
9. 일정 기간 병합 취소 제공

병합 전 자동 복구 지점을 만들고 병합 성공을 확인하기 전까지 기존 데이터를 삭제하지 않는다.

## 6. 프로필 병합 규칙

| 충돌 항목 | 처리 원칙 |
|---|---|
| 이름·생년·관계 | 사용자가 유지할 값을 선택한다. |
| 동일 날짜·동일 건강지표 | 기존 기록, 새 기록 또는 둘 다 유지 중 선택한다. |
| 동일 원본 서류 | 파일 해시를 비교하고 중복 여부를 확인한다. |
| 가족력 | 동일 친족·질환 여부를 확인한 뒤 병합한다. |
| 접근 범위 | 더 넓은 권한을 자동 적용하지 않고 다시 확인한다. |

- 서로 다른 사람일 가능성이 있으면 병합을 중단한다.
- 병합 작업과 변경 전후 상태를 로컬 변경 이력에 기록한다.
- 병합된 프로필 식별자를 재사용하지 않는다.
- 다른 브라우저의 데이터를 가져올 때는 중복 프로필을 먼저 확인하고 필요한 경우 프로필 병합을 완료한다.

## 7. 필요한 화면

- 기존 프로필 연결 또는 새 구성원 추가 선택
- 초대 발송·수락
- 공유할 건강정보와 접근 범위 확인
- 암호화 이전 파일 생성·가져오기
- WebRTC 직접 전송 기술검증 화면(후순위)
- 중복 프로필 감지
- 병합할 기존 프로필 선택
- 프로필 및 건강기록 비교
- 중복·충돌 기록 검토
- 병합 최종 확인
- 병합 완료 및 되돌리기

## 8. 구현 우선순위

후순위 기능도 전체 제품 범위와 기능명세에 유지한다. 개발 속도가 계획보다 빠르면 선행조건 충족 후 즉시 앞당길 수 있다.

### 1순위

- 서비스 계정 가입과 로그인
- 구독·라이선스 관리
- 가족 구성원 로컬 프로필 생성
- 프로필별 건강정보 로컬 저장 및 관리

### 2순위

- 기존 로컬 프로필에 가족 서비스 계정 초대
- 신규 가입 또는 기존 계정으로 초대 수락
- 기존 로컬 프로필과 서비스 계정 연결
- 잘못 생성한 프로필의 재연결과 병합

### 3순위

- 구성원별 건강정보 접근 범위
- 선택 건강정보 암호화 이전 파일 생성·가져오기
- WebRTC 직접 전송과 충돌 처리 기술검증

## 9. 미확정 사항

`대표 관리자`, `공동 관리자` 등 별도의 관리자 역할과 권한 체계는 현재 단계에서 확정하거나 임의로 추가하지 않는다. 관련 요구가 구체화되면 이 문서에 별도 결정으로 추가한다.
