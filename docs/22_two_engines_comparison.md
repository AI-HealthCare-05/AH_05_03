# 규칙 엔진과 ML 모델 — 두 방식 비교

만성질환 위험을 판정하는 코드가 지금 이 저장소에 두 개 있다. 하나는 팀원(ts04042-cell)이
PR #4로 올린 **국내 지침 기반 규칙 엔진**이고, 다른 하나는 내가 NHANES로 학습한
**로지스틱 회귀 모델**이다. 어느 쪽을 쓸지 정하기 전에 같은 사람을 두 쪽에 넣어보고
결과가 어떻게 갈리는지 손으로 확인할 수 있게 만들어 두었다.

**화면은 하나다.** http://localhost/api/demo 에서 스위치로 엔진을 고른다.

| 스위치 | 무엇이 돌아가는가 |
|---|---|
| 내 ML 모델 | `POST /api/v1/predictions/risk` |
| 규칙 엔진 | `POST /api/v1/assessments/rules` |
| 둘 다 (기본) | 두 요청을 동시에 보내고 겹치는 질환을 한 표에 놓는다 |

`/api/demo?engine=ml|rules|both` 로 처음 고를 엔진을 지정할 수 있고,
`/api/demo/rules` 는 화면이 둘이던 시절의 주소라 규칙 엔진을 고른 상태로 열린다.

화면을 두 개로 나눴다가 하나로 합쳤다. 페이지를 새로 열면 입력값이 날아가서 **같은
사람으로 두 결과를 나란히 놓을 수가 없었다.** 지금은 입력을 한 번만 하고 엔진을 바꿔 돌린다.

두 엔진이 받는 입력이 다른데, 안 쓰는 항목을 **숨기지 않는다.** 숨기면 무엇이 빠졌는지
알 수 없다. 대신 연한 회색으로 눌러 두고 값도 지우지 않는다 — 엔진을 되돌리면 그대로
있어야 하고, 다음 엔진용으로 미리 채워 둘 수도 있어야 한다. 칸을 클릭하면 원래 색으로
돌아온다.

회색은 표시일 뿐이고 **실제로 쓰지 않는다.** 각 엔진에 보내는 요청 본문을 따로 만들어
자기 필드만 담는다(두 요청 모델 모두 `extra="forbid"`). 그리고 모델이 받고도 쓰지 않은
항목은 결과에 이름까지 적는다 — `GET /predictions/model-info` 의 입력 목록으로 계산하므로
재학습해서 입력이 바뀌면 화면도 따라 바뀐다. 예를 들어 혈압을 입력하면 **당뇨 모델은
쓰지만 고혈압 모델은 "수축기·이완기를 쓰지 않았다"고 적는다** — 혈압이 고혈압 라벨을
정의하는 값이라 학습에서 차단됐기 때문이다. 자세한 것은 §2.5.

| | 규칙 엔진 | ML 모델 |
|---|---|---|
| 코드 | `chronic_disease_engine/` (가져온 코드, 수정 금지) | `app/services/risk.py` + `modeling/` |

## 1. 무엇이 다른가

| | 규칙 엔진 (PR #4) | ML 모델 (`modeling/`) |
|---|---|---|
| 판정 방식 | 학회 지침 임계값 비교 | NHANES 8개 주기 48,895명 학습 |
| 근거 | 대한고혈압학회·대한비만학회·대한당뇨병학회·한국지질동맥경화학회 | 미국 NHANES 2005–2023 |
| 출력 | 5단계 등급 | 0~1 확률 + 동년배 백분위 |
| 대상 질환 | 고혈압·비만·이상지질혈증·당뇨 **4개** | 당뇨·고혈압 **2개** |
| 필요 입력 | 검사값 (혈압·혈당·지질) | 설문 4문항 (나이·성별·BMI·주관적 건강) |
| 검사값이 없으면 | `INSUFFICIENT_DATA` — 판정하지 않는다 | 중앙값으로 채우고 확률을 낸다 |
| 한국인 기준 | **예** | 아니오 (미보정) |
| 근거 제시 | 적용한 지침 조항과 임계값 | 로짓 기여도 상위 4개 |

핵심 차이는 마지막에서 두 번째 줄이다. **규칙 엔진은 모르면 모른다고 하고, ML 모델은
모르면 추측한다.** 어느 쪽이 맞는 태도인지는 화면에 따라 다르다. 검진 결과를 입력받는
화면이라면 규칙 엔진이 맞고, 가입 직후 아무 검사값이 없는 사용자에게 첫 화면을
보여줘야 한다면 ML 모델밖에 쓸 수 없다.

## 2. 같은 사람을 넣으면

2026-08-20 실측. **화면에서 "둘 다"로 돌린 결과 그대로다** — 아래 첫 사례는 화면
기본값이라 데모를 열고 버튼만 누르면 같은 숫자가 나온다.

### 54세 남 · 172cm / 82kg / 허리 94cm · 혈압 138/88 · 공복혈당 112 · HbA1c 6.1 · LDL 140 · 비흡연

| 질환 | 내 ML 모델 | 규칙 엔진 |
|---|---|---|
| 당뇨 | **18.5%** · 동년배 이하 (50%ile) | **주의** · 당뇨병전단계 범위 |
| 고혈압 | **45.0%** · 동년배 이하 (38%ile) | **주의** · 고혈압 전단계 |
| 이상지질혈증 | 모델 없음 | **주의** · 경계 3항목 (저위험군) |
| 비만 | 모델 없음 | **높음** · 1단계 비만 + 복부비만 |

경계값에 몰린 사람이다. 규칙 엔진은 네 영역 모두 "주의" 이상을 찍는데 ML 모델은
고혈압 45.0%를 내면서도 등급은 "동년배 이하"다 — 50대 남성의 절반이 이미 고혈압
기준을 넘기 때문에 **동년배 대비로는 평균 이하**라서 그렇다. 이 사람에게 "당신은
평균입니다"와 "네 영역 모두 주의입니다"는 둘 다 사실이고, 어느 쪽을 보여줄지는
제품 결정이다.

### 같은 사람, "검사값 비우기"를 누른 경우

| 질환 | 내 ML 모델 | 규칙 엔진 |
|---|---|---|
| 당뇨 | **19.5%** (53%ile) | **판정 불가** — `fasting_glucose`, `hba1c`, `ogtt_2h` 필요 |
| 고혈압 | **45.0%** (38%ile) | **판정 불가** — `systolic_bp`, `diastolic_bp` 필요 |
| 이상지질혈증 | 모델 없음 | **판정 불가** — `total_cholesterol`, `ldl_c`, `hdl_c` 필요 |
| 비만 | 모델 없음 | **높음** · 1단계 비만 + 복부비만 |

ML 모델은 확률이 1.0%p 움직였고 고혈압은 소수점까지 그대로다. 검사값 9개를 지웠는데도
답이 같다. 이게 이 모델의 설계 의도이자 한계다 — 설문 4문항이 예측력의 99.5%를 담당하고
(`20_prediction_inputs_and_levers.md` §2), 나머지는 실질적으로 무시한다.
규칙 엔진은 같은 상황에서 3개 영역을 포기하고 무엇이 필요한지(`missing_fields`)
돌려준다. 데모의 "검사값 비우기" 버튼이 이 대비를 보여주기 위한 것이다.

### 71세 남 · 168cm / 92kg · 혈압 162/96 · 공복혈당 148 · HbA1c 7.4 · LDL 178 · 흡연

| 질환 | 내 ML 모델 | 규칙 엔진 |
|---|---|---|
| 당뇨 | **47.5%** · 관심 (82%ile) | **매우 높음** · 여러 지표에서 당뇨병 범위 |
| 고혈압 | **83.8%** · 관심 (79%ile) | **매우 높음** · 고혈압 2기 |
| 이상지질혈증 | 모델 없음 | **높음** · 중등도 위험군 |
| 비만 | 모델 없음 | **높음** · 2단계 비만 + 복부비만 |

여기서는 두 엔진이 같은 방향을 가리킨다. 다만 ML 모델의 등급이 "관심"에 머무는 것에
주의해야 한다. 확률 83.8%는 절대적으로 높지만 **70대 이상 남성 중에서는 79%ile**이라
동년배 기준으로는 상위 4분의 1 수준이다. 이미 고혈압인 사람에게 위험을 알리는 것이
목적이라면 절대 확률로, 생활습관 개선 동기를 만드는 것이 목적이라면 백분위로 보여주는
편이 낫다.

젊고 건강한 사람에서는 두 엔진이 일치한다. 갈리는 구간은 경계값과 고령이다.

## 2.5 당뇨는 왜 상반돼 보이는가

첫 사례에서 ML은 당뇨 18.5%를 "동년배 이하"로, 규칙 엔진은 같은 사람을 "주의 ·
당뇨병전단계"로 판정했다. 고혈압은 45.0%와 "주의 · 전단계"라 얼추 맞는 것처럼 보인다.
**고혈압이 맞아서가 아니다.** 세 가지를 재 보면 원인이 나온다.

### (1) ML 모델은 혈당을 입력으로 받지 않는다

```
dm  모델 입력: age, sex, bmi, self_rated_health + waist_cm, smoking_status,
              difficulty_walking, alcohol, moderate, vigorous, sedentary, sleep, sbp, dbp
htn 모델 입력: 위와 같고 sbp·dbp 가 빠진다
```

공복혈당·HbA1c·OGTT는 **두 모델 어디에도 없다.** 당뇨 라벨을 정의하는 값이라
`modeling/features.py`의 `label_inputs`가 학습 단계에서 기계적으로 차단한다. 같은
이유로 혈압은 고혈압 모델에서 빠진다(당뇨 모델에서는 라벨과 무관하니 정당한 특징이다).

넣어 봐도 확률이 움직이지 않는다.

| 입력 | ML 당뇨 확률 | 규칙 엔진 |
|---|---|---|
| FPG 88 / HbA1c 5.1 | 18.46% | 정상 |
| FPG 112 / HbA1c 6.1 | 18.46% | 주의 · 당뇨병전단계 |
| FPG 150 / HbA1c 7.4 | 18.46% | 매우 높음 · 당뇨병 범위 |

**소수점까지 같다.** 규칙 엔진은 정상에서 당뇨까지 걸어가는데 ML 확률은 상수다.

### (2) 고혈압이 일치해 보이는 건 기저 유병률 때문이다

| 라벨 | NHANES 기저 유병률 | 평균적인 50대 남성의 ML 확률 | 등급 |
|---|---|---|---|
| 고혈압 | **0.419** | 45.0% | 동년배 이하 |
| 당뇨 | **0.174** | 18.5% | 동년배 이하 |

두 등급이 똑같이 "동년배 이하"다. **모델은 두 질환에 대해 같은 말을 하고 있다.**
다만 45.0%는 사람 눈에 "반반, 경계선"으로 읽혀 "전단계"와 맞아 보이고, 18.5%는
"낮음"으로 읽혀 "전단계"와 부딪힌다. 상반돼 보이는 건 **맨 확률을 보여준 탓**이고
질환마다 기저 유병률이 2.4배 차이나기 때문이다.

### (3) 진짜 위험한 경우 — 마른 당뇨 환자

45세 남 · 170cm 62kg (BMI 21.5) · 주관적 건강 "좋음" · 혈압 118/74 ·
**공복혈당 140 · HbA1c 7.0** (정의상 당뇨다)

| 엔진 | 결과 |
|---|---|
| ML 당뇨 | **3.4%** · 10%ile · 동년배 이하 |
| 규칙 당뇨 | **매우 높음** · 여러 지표에서 당뇨병 범위 |

생활습관만 보면 이 사람의 위험은 정말 낮다. ML 모델은 자기가 본 것에 대해 틀리지
않았다. 그런데 검사값은 이미 당뇨라고 말하고 있다. **검사값이 있는 순간 ML 확률은
정보가 없는 게 아니라 틀린 답을 자신 있게 말한다.** 이게 3.4%를 화면에 그대로
띄우면 안 되는 이유다.

### 그래서 정한 규칙

> **검사값이 있으면 규칙 엔진을 읽고, 없으면 ML 모델을 읽는다.**

데모의 비교표에 "읽을 쪽" 열을 넣어 이걸 계산해 보여준다. 그 질환을 정의하는 검사값이
입력돼 있으면 ML 칸에 취소선을 긋고 규칙 엔진 쪽을 굵게 표시한다. ML 카드에도
"이 모델은 혈당을 입력으로 받지 않습니다"라는 안내가 붙는다.

두 방식은 **경쟁이 아니라 순서**다. ML은 검사 전, 규칙은 검사 후.

### 하지 않을 것

| 방안 | 왜 안 되는가 |
|---|---|
| ML 모델에 공복혈당·HbA1c를 특징으로 추가 | **라벨 누출**이다. 당뇨 라벨이 `FPG≥126 or HbA1c≥6.5`로 정의되므로 모델은 사람에 대해 아무것도 배우지 않고 임계값만 다시 배운다. AUROC는 0.99로 뛰고 쓸모는 0이 된다 |
| 당뇨전단계 위험도 ML 모델을 따로 학습 | 이미 평가하고 접었다. 상위 5%에서도 lift 1.50에 그쳤다 ([21번](21_modeling_overview.md) §7.3) |
| 당뇨 등급 경계를 낮춰 18.5%를 "주의"로 만들기 | 18.5%는 50대 남성의 50%ile이다. 진짜로 평균이고, 등급은 제 일을 하고 있다. 경계를 낮추면 절반이 "주의"가 되어 등급이 정보를 잃는다 |

### 팀에 남는 결정

- 검사값이 있을 때 ML 확률을 **아예 숨길지**, "검사 전 선별값"으로 강등해 남길지.
  지금 데모는 취소선으로 남겨 두는 쪽인데 제품에서는 숨기는 편이 안전해 보인다
- 맨 확률을 보여줄지. 18.5% / 45.0%는 오해를 부른다. 백분위만 보여주면 오해는 줄지만
  "상위 45%"도 직관적이지 않다

## 3. 이식 방식

### 원본을 그대로 둔다

`chronic_disease_engine/` 8개 파일은 PR #4 커밋 `c6943b14`와 **바이트 단위로 동일**하다.
한 글자라도 고치면 "팀원의 엔진과 비교"가 아니라 "내가 고친 엔진과 비교"가 되어
비교 자체가 무의미해진다. 세 가지로 고정했다.

1. `chronic_disease_engine/PROVENANCE.md` — 출처·커밋·재수집 명령·파일별 SHA-256
2. `pyproject.toml` — `tool.ruff.extend-exclude`, `tool.mypy.exclude`에 등록.
   `ruff format`이 따옴표 하나만 바꿔도 체크섬이 깨진다
3. `test_vendored_engine_is_unmodified` — 8개 파일 해시를 코드에 박아두고 매 테스트마다 대조

개선점이 보이면 원 PR에 코멘트로 남기고 여기서는 손대지 않는다.

### 경계에만 코드를 쓴다

| 파일 | 역할 |
|---|---|
| `app/dtos/rule_assessment.py` | 요청·응답 DTO. 엔진의 `HealthProfileInput`을 베껴 쓰되 우리 API 규약(`extra="forbid"`)과 단위 설명을 붙였다 |
| `app/apis/v1/rule_assessment_routers.py` | `POST /assessments/rules`. 엔진 호출과 봉투 응답만 |
| `app/apis/demo_routers.py` | 데모 화면. 엔진 스위치와 두 결과 렌더링 |
| `app/apis/demo_style.py` | 화면 스타일. 두 엔진 결과가 같은 껍데기를 쓴다 |

DTO를 베껴 쓴 대가로 드리프트 위험이 생긴다. 엔진 스키마는 `extra="ignore"`라서 PR #4가
필드 이름을 바꾸면 **우리가 보낸 값이 조용히 무시되고 예외도 나지 않는다.**
`test_dto_fields_are_subset_of_engine_schema`가 양방향으로 필드 집합을 대조해 이걸 막는다.

요청 검증을 경계에서 한 번 더 하는 이유도 있다. 엔진도 `systolic_bp > diastolic_bp`를
검사하지만 그쪽 `ValueError`는 500으로 새어 나간다. DTO에서 먼저 막아 422 봉투로 돌려준다.

### 입력 하나를 두 필드명으로 갈라 보낸다

두 요청 모델 모두 정의되지 않은 필드를 거부하므로(`extra="forbid"`) 공유 폼이 각 엔진에
맞는 이름으로 나눠 보내야 한다.

| 폼 항목 | ML 모델 | 규칙 엔진 |
|---|---|---|
| 나이·성별·키·체중·허리둘레 | 그대로 | 그대로 |
| 수축기·이완기 | `sbp` / `dbp` | `systolic_bp` / `diastolic_bp` |
| 흡연 | `smoking_status` (never/former/current) | `smoking` (bool) — **현재 흡연만 참** |
| 전반적인 건강, 수면·운동·음주, 보행 불편 | 쓴다 | 받지 않는다 |
| 혈당·지질·공복 여부, 진단 이력 | 받지 않는다 | 쓴다 |

흡연 매핑은 정보를 잃는다. 규칙 엔진은 현재 흡연 여부만 위험인자로 세므로 "과거에 피움"이
비흡연으로 넘어간다. 손으로 쓴 대응표라 오타 하나면 값이 조용히 빠지거나 422가 되므로
`test_demo_form_field_names_exist_in_both_dtos`가 두 DTO에 대조한다.

## 5. 아직 정하지 않은 것

- **어느 쪽을 제품에 넣을지.** §2.5에서 읽는 순서는 정했다 — 검사값이 있으면 규칙,
  없으면 ML. 남은 것은 화면 설계다: 검사값이 있을 때 ML 확률을 숨길지 강등해 남길지,
  맨 확률을 보여줄지 백분위만 보여줄지
- **ML 모델의 한국인 미보정.** 규칙 엔진은 국내 지침을 쓰지만 ML 모델은 미국 인구
  데이터다. 국내 데이터가 확보되면 재학습이 필요하다 (`21_modeling_overview.md` §7)
- **두 엔드포인트 모두 무인증·무저장.** 레이트 리밋이 없다. `03_api_spec.md`에 반영해야 한다

   항목만 흐려진다. 흐린 칸에 마우스를 올리면 값이 보인다
