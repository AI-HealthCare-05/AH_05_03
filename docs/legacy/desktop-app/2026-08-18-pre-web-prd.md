# 데스크톱 앱·Wi-Fi 직접 동기화 구버전 PRD 백업

- 상태: 동결된 구버전, 현재 구현 기준으로 사용하지 않음
- 백업일: 2026-08-18
- 원본: Manyfast `ieobom` 프로젝트
- 원격 복구 지점: Manyfast 수동 버전 18
- 대체 결정: [ADR-001 웹 기반 로컬 우선 서비스 전환](../../adr/0001-web-local-first-architecture.md)

## 1. 백업 목적

이 문서는 데스크톱 앱의 파일 시스템·로컬 데이터베이스 접근을 전제로 검토했던 설계와, 이후 웹 화면에 남아 있던 같은 Wi-Fi 직접 동기화 설계를 보존한다. 웹 버전이 완성된 뒤 네이티브 데스크톱 앱, 로컬 네트워크 직접 전송 또는 자동 다중 기기 동기화를 다시 검토할 때 참고한다.

이 문서의 내용은 현재 요구사항, 수락 기준, 와이어프레임 또는 구현 우선순위로 사용하지 않는다. 현재 기준은 ADR-001과 `docs/01_requirements.md`, `docs/05_tech_architecture.md`이다.

## 2. 구버전 PRD 원문

### 주제

가족 건강 기록 관리 서비스

### 제품 목표

가정 단위로 흩어진 건강 기록을 가족 구성원별로 안전하게 정리하고, 승인한 같은 Wi-Fi 네트워크 안의 기기끼리 암호화해 직접 동기화하게 한다. 건강 기록과 원본 서류는 각 기기에 로컬로 보관하며, 서비스 계정은 인증·구독·라이선스·가족 초대와 기기 연결 상태 관리에만 사용한다.

### 배경

건강검진 결과, 예방접종 기록, 병원 검사서와 생활 기록은 종이와 파일로 흩어져 장기 추적이 어렵다. 개인 건강 정보의 외부 유출과 학습 활용에 대한 우려가 커, 건강 데이터는 기기에 보관하고 사용자가 직접 통제하되 가족 초대와 구독 관리는 서비스 계정으로 분리하는 방식이 필요하다.

### 사용자 문제

가족 구성원의 건강 정보를 한곳에서 시간순으로 확인하기 어렵고, 기기 분실·고장이나 브라우저 데이터 삭제로 기록을 잃을 위험이 있다. 건강 데이터가 외부 서버에 저장되거나 AI 학습에 사용될 수 있다는 불안도 서비스 이용의 장벽이 된다. 또한 서비스 계정이 있다는 이유만으로 다른 가족의 건강정보에 자동 접근하게 되면 가족 내 개인정보 통제가 약해질 수 있다.

### 해결 방안

서비스는 건강 기록과 원본 서류를 각 기기 로컬 환경에 보관하고, 사용자가 암호화된 백업 파일을 직접 내보내고 가져와 데이터를 복구하게 한다. 여러 기기를 함께 사용할 때는 같은 Wi-Fi 네트워크 안에서 승인한 기기끼리 직접 암호화 동기화를 제공한다. 사용자가 원격으로 선택 기록을 공유할 때에만 만료 시간이 있는 암호화 임시 링크를 제공하며, 서비스 계정은 인증, 구독, 라이선스, 가족 초대 및 기기 연결 상태만 관리하고 가족 구성원 로컬 프로필과 건강정보는 기기에 분리해 보관한다.

### 차별점

가정 단위 건강 기록을 가족 구성원 로컬 프로필별로 연결하면서도 건강 데이터를 기본적으로 클라우드에 보내지 않는다. 서비스 계정은 가족 초대와 구독을 지원하지만 계정 보유만으로 다른 구성원의 건강정보 접근 권한이 생기지 않는다. 선택적 원격 공유에만 암호화 임시 링크를 사용하고, 같은 Wi-Fi 네트워크 안에서는 기기 간 직접 암호화 동기화를 제공하며 고객 건강 데이터를 모델 학습에 사용하지 않는다.

### 대상 사용자

가족 구성원의 건강 기록을 함께 관리하려는 가정의 대표 사용자와 가족 구성원이다. 사용자는 서비스 계정으로 가입·로그인해 가족 초대, 구독, 라이선스와 연결 기기를 관리하지만, 건강 기록 대상은 로그인 없는 가족 구성원 로컬 프로필로도 등록할 수 있다. 데스크톱과 모바일에서 같은 핵심 건강 기록 기능을 사용하면서 건강 데이터를 클라우드에 보내지 않고 집 등 신뢰할 수 있는 Wi-Fi 네트워크 안에서만 기기 간 동기화를 사용하려는 사용자에게 적합하다.

### 사용자 시나리오

가정 관리자는 서비스 계정으로 로그인한 뒤 가족 구성원 로컬 프로필을 등록하고 건강 기록과 원본 서류를 기기에 저장한다. 성인 가족 구성원은 서비스 계정으로 초대를 수락해 가정에 참여할 수 있지만, 별도 권한을 받기 전에는 다른 구성원의 건강정보를 열람할 수 없다. 기기 이전이나 복구가 필요하면 암호화된 백업 파일을 직접 내보내고 다른 기기에서 가져오며, 집 등 같은 Wi-Fi 네트워크에 데스크톱과 모바일이 있을 때는 승인한 기기를 직접 연결해 암호화 동기화한다.

### 핵심 지표

가정별 등록 구성원 수, 구성원당 건강 기록 입력 건수, 월간 이력·차트 조회율, 암호화 백업 파일 내보내기 성공률과 가져오기 성공률, 로컬 네트워크 동기화 성공률을 추적한다. 외부 서버 저장 및 고객 데이터의 모델 학습 사용 건수는 0건을 유지한다.

### 리스크

백업 파일 비밀번호 분실, 기기 분실·고장, 브라우저 데이터 삭제와 잘못된 가져오기로 데이터가 손실되거나 접근하지 못할 수 있다. 로컬 네트워크 동기화에서는 기기 연결 승인, 동시 수정 충돌, Wi-Fi 연결 끊김과 신뢰할 수 없는 네트워크 접속을 명확히 처리해야 한다.

## 3. 구버전 개인정보·동기화 요구사항

### 개인정보 보호 및 로컬 데이터 관리

서비스는 가족 건강 기록과 원본 서류를 사용자의 기기 로컬 환경에 기본 저장하며, 클라우드 동기화를 제공하지 않는다. 여러 기기는 사용자가 승인한 같은 Wi-Fi 네트워크 안에서만 암호화된 데이터를 직접 동기화할 수 있다. 사용자가 명시적으로 원격 공유를 생성할 때에만 선택한 기록을 암호화 임시 링크로 제한된 기간 제공하며, 고객 데이터는 모델 학습에 사용하지 않는다.

구버전 수락 기준은 다음과 같았다.

- 가족 건강 기록과 원본 서류는 사용자의 기기 로컬 환경에 기본 저장한다.
- 사용자의 명시적 원격 공유 외에는 외부 서버로 전송하지 않는다.
- 클라우드 동기화는 제공하지 않는다.
- 승인한 같은 Wi-Fi 네트워크 안의 기기끼리만 암호화 동기화를 제공한다.
- 고객 건강 데이터는 모델 학습에 사용하지 않는다.

## 4. 구버전 주요 기능

### 4.1 로컬 데이터 보관 및 개인정보 안내

- 건강 기록과 원본 서류를 각 기기에 보관한다.
- 서비스 계정은 인증, 구독, 라이선스, 가족 초대 및 기기 연결 상태만 관리한다.
- 승인한 같은 Wi-Fi 네트워크의 기기 사이에서 직접 암호화 동기화를 제공한다.
- 기기 이전과 복구는 암호화 백업 파일 내보내기와 가져오기로도 제공한다.

### 4.2 로컬 백업 및 복구

- 가족 구성원 로컬 프로필, 건강 기록, 원본 건강 서류, OCR 결과와 변경 이력을 하나의 암호화 파일로 내보낸다.
- 다른 기기에서 파일을 가져와 복구한다.
- Wi-Fi 동기화를 사용할 수 없는 상황의 독립적인 복구 수단으로 사용한다.
- 자동 서버 전송과 클라우드 동기화는 제공하지 않는다.

### 4.3 기간 제한 건강 기록 공유

- 사용자가 선택한 건강 기록 또는 원본 건강 서류를 임시 링크와 QR 코드로 공유한다.
- 서버에는 복호화할 수 없는 암호문을 만료 기간 동안 보관한다.
- 사용자가 철회하거나 만료되면 임시 암호문을 삭제한다.
- 암호화 키 전달, 중계 서버, 삭제 검증과 접근 로그 정책은 확정하지 못했다.

### 4.4 가정 관리자와 공동 관리자

- 가정 관리자가 초대를 수락한 성인 계정에 공동 관리자 권한을 부여한다.
- 한 가정에 둘 이상의 공동 관리자를 둘 수 있다.
- 공동 관리자는 구성원별 권한 범위 안에서 건강정보에 접근한다.
- 백업·복구와 외부 공유는 가정 관리자 중심으로 설계했다.

현재 웹 버전에서는 관리자 역할을 확정하지 않았으므로 이 권한 체계를 사용하지 않는다.

## 5. 재검토 조건

웹 버전의 핵심 기능과 보안 검증이 완료된 뒤 다음 조건을 충족할 때 구버전 설계를 다시 검토한다.

1. IndexedDB·OPFS 저장과 암호화 백업·복구가 안정적으로 동작한다.
2. 브라우저 데이터 삭제, 저장 공간 부족, 키 분실과 파일 손상에 대한 복구 정책이 검증된다.
3. 네이티브 데스크톱 앱이 웹 버전보다 제공할 명확한 사용자 가치가 확인된다.
4. WebRTC 직접 전송의 시그널링, STUN·TURN, 모바일 백그라운드 종료와 브라우저 호환성 검증이 완료된다.
5. 중계 서버를 사용할 경우 암호문 통과·보관이 개인정보 원칙과 일치하는지 별도 ADR로 결정한다.
6. 기존 웹 데이터와 데스크톱 앱 데이터의 마이그레이션·충돌 해결 방식이 정의된다.

재검토 결과를 실제 제품에 반영할 때는 이 문서를 수정하지 않고 새로운 ADR을 작성한다.
