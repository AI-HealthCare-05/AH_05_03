# 공개 랜딩페이지 v2 — 대안 디자인 시안

> 최종 갱신: 2026-09-16
> 코드 위치: `frontend/src/features/landing-v2/`
> 관련 문서: [52 랜딩페이지(v1)](52_landing_page.md) · [DESIGN.md](../DESIGN.md) · [34번 규칙 문서](34_project_rules_and_workflow.md) · [17 Three.js 인체 컨텍스트](17_threejs_human_body_dashboard_context.md)

이 문서를 읽고 나면 **왜 소개 화면이 두 벌인지**, **v2 가 v1 에서 무엇을 그대로 쓰고 무엇만 바꿨는지**, 그리고 **하나를 고른 뒤 다른 하나를 어떻게 지우는지** 알 수 있다.

---

## 0. 세 문장 요약

`/landing-v2` 는 `/landing`(v1)과 **같은 이야기·같은 예시 데이터·같은 3D 장면**을 쓰고 **표현 계층만** 다른 화면이다. 다른 것은 디자인 시스템 한 벌이다 — 딥 오버진 단색 세계, 굵기 300~400 의 속삭이는 타이포, 모든 조작 요소가 캡슐(100px)인 기하학(Violet Capsule Minimal). 두 벌을 유지하는 목적은 **디자인을 견주는 것**이고, 그래서 문구와 숫자를 갈라 두지 않았다.

## 1. 왜 두 벌인가

소개 화면의 방향(따뜻한 아이보리·파랑 vs 오버진·라벤더)이 정해지지 않았다. 시안을 그림으로 그려 견주면 스크롤 연출·3D 인체·성능 같은 **실제로 판단이 갈리는 것**이 빠진다. 그래서 두 번째 시안을 **돌아가는 화면으로** 만들었다.

문구·수치·장면 순서를 같이 쓰는 것은 의도다. 이것이 갈리면 "어느 디자인이 나은가" 가 아니라 "어느 카피가 나은가" 를 보게 된다.

## 2. 디자인 시스템 — 무엇을 그대로 구현했고 무엇을 고쳤나

토큰은 `landingV2.css` 머리말에 있다. 원본 명세에서 **의도적으로 고친 것은 둘뿐이고 둘 다 대비다.**

| 원본 명세 | 이 구현 | 이유 |
|---|---|---|
| 보조 글자색 `Fog #86848d` | 글자에 쓰지 않는다. 테두리·아이콘 전용. 글자는 `#49454e`(시스템 자신의 토큰)와 `--v2-meta #605b6a` | Paper White 위에서 **3.67:1** — WCAG 1.4.3(4.5:1) 미달. 이 저장소는 같은 함정을 이미 밟았다(`styles.css` `--muted` 를 2026-09-10 에 어둡게 한 주석) |
| Mint Signal 배지 = `#2ec08b` 채움 + `#fdfcfe` 글자 | 파스텔 채움 + Obsidian 글자 | 원문 조합이 **2.29:1**. 파스텔 캡슐에 Obsidian 글자는 이미 이 시스템의 지배적 패턴("Pastel Multi-Action Set")이라 상태 배지 셋을 그 패턴으로 통일했다(7.3:1 이상) |

서체는 **DM Sans 를 이 페이지에서만** 받는다(`displayFont.ts`). 이 저장소에는 웹폰트가 한 장도 없어서 전역에 두면 앱 전체가 외부 요청 하나를 더 기다린다. 한글 서체는 받지 않는다 — DM Sans 에 한글 글리프가 없고, 한글이 앱과 같은 시스템 서체로 떨어져야 랜딩과 앱의 글이 같은 얼굴이다. **폰트가 안 와도 페이지는 완성이다**(타이포의 성격은 굵기 300~400 · 자간 -0.025em · 큰 디스플레이 크기에서 나오고, 그 셋은 fallback 스택에도 똑같이 걸린다).

상태 표기는 v1 과 같은 셋(`정상 / 주의 / 관리 필요`)이고, 숫자 옆에는 항상 참고 기준을 적는다. 금칙어("AI 진단"·"질환 확정"·"질병 예측"·"질환 발견")는 테스트가 렌더 결과에서 직접 찾는다.

## 3. 무엇을 재사용했나

**랜딩용 더미를 새로 만들지 않는다.** 랜딩에서 본 몸과 가입 뒤에 만나는 몸이 다르면 그 장면은 광고이지 데모가 아니다.

| 장면 | 어디서 가져왔나 | v2 가 새로 쓴 것 |
|---|---|---|
| 이야기·문구·예시 수치 | `features/landing/landingStory.ts` (**v1 과 같은 파일**) | — |
| 스크롤 엔진 | `features/landing/scrollProgress.ts` · `Reveal.tsx` | — |
| 3D 인체 | `features/landing/scene/LandingBodyScene.tsx` · `bodyScene.ts` (앱의 Vanatome 아틀라스·PBR 재질을 그대로 쓴다) | 표식 색 하나(`markerColor`) |
| 숫자 카운트업 | `features/landing/useCountUp.ts` | — |
| 정원 나무 | `features/challenge/GardenArt` 의 `Tree`·`TreeKey` | — |
| 챗봇 마스코트 | `features/health-assistant/assets/bomi-chick.png` | 런처·패널 껍데기 |
| 브랜드 마크 | `public/ieobom-icon.svg` 의 아치 좌표 | v2 색으로 다시 그린 인라인 SVG |

### 3-1. `LandingBodyScene` 에 더한 것은 색 하나뿐이다

그 컴포넌트는 470줄짜리 WebGL 장면이다. 복사해 두면 한쪽만 고쳐지고 테스트는 통과한다(AGENTS.md §2-5). 그래서 **선택 prop 하나(`markerColor`)** 만 더했고 기본값은 v1 이 쓰던 앱의 통증 팔레트다 — 주지 않으면 v1 의 동작이 한 픽셀도 바뀌지 않는다. v2 는 Periwinkle(`#ab9ff2`)을 넘긴다: 딥 오버진 배경 위에서 통증 팔레트의 주황은 보색에 가까워 표식만 따로 떠 보인다.

### 3-2. 런처 CSS 는 공유하지 않았다

v1 런처는 앱의 `globalHealthAssistant.css` 를 그대로 입는다. v2 에서 그러면 오버진·캡슐 페이지 한가운데에 앱의 파란 버튼 하나가 남는다. **마스코트 그림은 앱의 것을 그대로 쓰고 껍데기만** v2 로 짰다 — 마스코트는 브랜드이고 캡슐은 디자인 시스템이다.

### 3-3. 브랜드 마크를 다시 그린 이유

`ieobom-icon.svg` 는 인디고→블루→틸 그라데이션 라운드 사각형이다. CSS `filter` 로 돌려 봤더니 그라데이션이 뭉개져 검은 덩어리가 됐다. **모티프(세 점을 잇는 아치)의 좌표는 원본 그대로** 쓰고 색만 옮겼다. 원본 파일은 한 줄도 고치지 않는다(앱과 v1 이 쓴다).

## 4. 장면 구성과 스크롤

순서는 v1 과 같다. 고정 구간의 길이만 이 디자인에 맞춰 다시 쟀다.

| 2 | 검진표·OCR | 고정 4 화면 | 3.2 | 줄이 짚이고 숫자가 종이를 떠나 캡슐로 재배치 |

### 4-1. 히어로는 세 박자다

`--h-conv`(0.03→0.34 정렬) · `--h-out`(0.34→0.67 글이 비킨다) · `--h-exit`(0.58→1 퇴장). 처음에는 정렬과 페이드가 같은 구간에 겹쳐서, 캡슐이 줄을 맞추는 순간에 이미 투명도가 0.18 이었다 — **정렬의 보람이 화면에 남지 않았다.**

구현은 `--ln-progress` 하나로 돌아간다. 값은 JS 가 섹션 요소에 쓰고(`scrollProgress.ts`), 자식들이 `clamp()` 로 자기 구간만 떼어 쓴다 — 프레임마다 React 가 하는 일이 없다. 나머지는 [52번 §6](52_landing_page.md) 과 같다.

## 5. 밟은 함정

- **`position: sticky` 를 같은 특이도의 뒤쪽 규칙이 덮는다.** `.lnv2-body-stage` 에 `position: relative` 를 적었더니 그 요소가 달고 있는 `.lnv2-sticky` 의 `sticky` 를 이겨서 **3D 인체 섹션만 고정이 통째로 안 먹었다** — 5.5 화면을 스크롤하는 동안 몸이 위로 흘러가고 빈 오버진 화면만 지나갔다. 겉으로는 "3D 가 안 뜬다" 로 보인다. 테스트가 `-stage` 규칙의 `position` 선언을 금지한다.
- **애니메이션의 `transform` 이 절대 위치의 기준을 만든다.** 장면 글 묶음(`.lnv2-body-copy`)에 등장 애니메이션을 걸었더니 그 안의 부위 정보 패널이 오른쪽 가운데가 아니라 글 아래에 붙어 화면 밖으로 잘렸다. 이동은 `<p>` 에만 걸고 패널은 투명도만 바꾼다.
- **한글은 `word-break: keep-all` 없이 어절 가운데서 끊긴다.** "건강을 기록 / 하는 것에서," 처럼. 큰 글자에서 그 한 줄이 디자인을 통째로 망친다.
- **디스플레이 타이포와 2단 히어로는 같이 못 선다.** 1024px 에서 글 칼럼이 452px 이 되어 76px 문장이 네 줄로 접혔다. 이 문장의 가장 긴 줄은 한글 14자라 76px 로 세우려면 1,060px 이 필요하다 — 그림을 아래로 내리고 글을 전체 폭으로 폈다.
- **그릇은 내용과 같이 온다.** OCR 의 재배치 카드를 늘 켜 두었더니 숫자가 떠나기 전(섹션 앞 60%) 화면 절반이 빈 상자였다.
- **캡슐은 화면 폭의 절반을 넘는다.** 모바일에서 가로로 흩으면 이웃 캡슐과 글자가 겹쳐 읽힌다. 390px 에서는 기울기와 아주 작은 어긋남만 남긴다.
- **SVG 축 라벨의 실제 크기는 축소 비율을 곱한 값이다.** 390px 에서 차트가 0.5 배로 줄어 13px 라벨이 6.7px 로 찍혔다.
- **떠 있는 내비 뒤로 정수리가 들어간다.** 카메라 키프레임은 v1 과 공유하는 정본이라 거기서 고치면 v1 구도가 같이 바뀐다 — 카메라가 아니라 **그리는 자리**(캔버스 `inset`)를 내린다.
- **`overflow-x: hidden` 은 `position: sticky` 를 죽인다**(v1 과 같은 함정). `clip` 은 스크롤 컨테이너를 만들지 않아 sticky 가 산다.
- **배경색 전환은 글자가 없는 자리에서 한다**(v1 과 같은 함정). 전환 전용 빈 구간(`.lnv2-fade`)을 둔다.

## 6. 접근성·성능

v1 과 같은 선을 지킨다. `prefers-reduced-motion: reduce` 에서는 고정이 풀리고 모든 장면이 위에서 아래로 한 번에 선다 — **기능을 빼지 않고 움직임만 뺀다.** 실측(390×844): 문서 높이 20,652px → 8,673px, 3D 인체 다섯 장면이 전부 글로 남고, 좁은 화면에서 겹쳐 두던 종이/데이터 카드는 겹치기가 풀려 위아래로 선다(이것을 안 풀면 글자 위에 글자가 찍힌다).

연출로만 전달되는 내용(OCR 이 읽은 값 8개, 몸에 쌓인 기록, 4주 추이)은 같은 내용의 글을 `.lnv2-sr-only` 로 함께 둔다. 3D 자산(7 MiB)은 섹션이 한 화면 앞에 올 때 받고, 데이터 절약 모드에서는 버튼을 눌러야 받는다. rAF 렌더 루프는 섹션이 보이는 동안에만 돈다. 터치 타깃 44px, 목차 앵커에 `scroll-margin-top`.

## 7. 경계 — 관문 밖에 서도 되는 이유

조건은 `/signup`·`/landing` 과 같다: **기기 안·서버의 건강기록을 읽지 않을 것.** `features/landing-v2` 는 `useLocalDomain`·`localDomainContext`·`serverApiClient`·`shared/local/*`·`local-domain/*`·`react-query` 를 import 하지 않으며, 화면의 수치는 `landingStory.ts` 의 예시 시나리오다. 재사용하는 `features/landing/*` 쪽은 v1 의 테스트가 같은 방식으로 훑는다 — 두 폴더 합쳐 빈틈이 없다.

로그아웃 상태의 `/` 는 **여전히 `/landing`(v1)로 간다.** 어느 쪽을 정본으로 세울지는 디자인 결정이고, 그 결정 전에 기본 동작을 바꾸지 않는다.

## 8. 하나를 고른 뒤

**두 시스템을 오래 같이 두지 않는다.**

- **v2 를 고르면**: `landingV2.css` 의 `--v2-*` 를 `DESIGN.md` 로 올리고, `/landing-v2` 를 `/landing` 으로 옮기고, `features/landing/` 의 섹션·CSS 를 지운다. 공유 자산(`landingStory`·`scrollProgress`·`scene/*`·`useCountUp`·`Reveal`)은 그대로 남는다.
- **v1 을 고르면**: `features/landing-v2/` 폴더와 `/landing-v2` 라우트, `DESIGN.md` 의 "랜딩 v2" 절을 지운다. `LandingBodyScene` 의 `markerColor` prop 도 같이 지운다(쓰는 곳이 없어진다).
