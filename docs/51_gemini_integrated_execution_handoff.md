## 3. 실행 순서 — 기존 3개 로드맵을 언제 진행하는가

우선순위는 모든 작업을 완전히 직렬로 기다리게 한다는 뜻이 아니다. 데이터 안전성이 가장 우선이며, 독립적인 조사·측정은 초기에 진행한다. 여러 AI/작업 폴더를 동시에 실행하려면 사용자의 별도 위임과 파일 경계를 확인한다.

| 시점 | 작업 | 종료 게이트 |
|---|---|---|
| 즉시 | 가족 데이터 읽기 전용 조사, ② 이벤트 결함 재현, ③ 기존 구현 목록화 | 현재 상태·실패 사례·미확인 범위 제출 |
| 즉시 | ① iPhone 성능 기준선, #106 재현 정보 확보, 배포 위험 조사 | 수치 또는 실기기 미확보 표시, 이슈 추측 금지 |
| 첫 수정 단계 | 가족 데이터 안전 경로와 ② 의미/검증 계약 보강 | 잘못된 대상·좌우·단위·ID·복수 부위 손실 방지 |
| 같은 개발 단계 | ③ 선택 정확성·취소·치아·검색·투시 회귀 보완 | 실물/fixture 기준 오선택 평가 |
| 정확성 기준 확보 후 | ① 측정된 병목 개선, ②·③ 회귀 재검증 | 전후 동일 조건 측정과 의미 보존 |

모바일 사용성, 기존 선택 기능 정확성, 배포 안정화는 배포 전 대상이다. ‘후속’은 큰 재구축·검증되지 않은 추론 확장을 뜻하며, 기존 3개 로드맵을 무기한 연기하라는 뜻이 아니다. 모든 수정이 9/14까지 가능하다고 미리 약속하지 말고, 측정 결과로 최소 안전 배포 범위를 보고한다.

## 4. 선행 결함 상세 — 과거 발견 사항을 현재와 대조

### P0-1. 가족 프로필·건강기록 무결성

과거 사용자 지정 한글 이름 대신 `evophygene`, `fabxoe.usa`가 표시됐다. 당시 LocalDomainProvider.tsx는 활성 프로필이 0개이면 membership에서 새 UUID 프로필을 생성했고, 특정 계정의 이름·생일·성별을 하드코딩하고 나머지는 이메일 앞부분을 이름으로 저장했다.

당시 두 프로필은 2026-09-09 18:18:48 KST 생성, row_version=1이었다. 이것은 신규 생성 정황이지 기존 프로필 삭제/변경의 확정 증거가 아니다. 이후 account_email·별칭 변경만으로 원본 복원이 입증되지 않는다.

수행:

- 원본 프로필의 다른 가정 소속/숨김/계정 연결, 필요 시 레거시 로컬 저장소 존재 여부를 확인한다.
- 기존·신규 ID, 가정, 생성 시각, 연결된 기록 수를 비교한다. 건강기록 본문을 불필요하게 출력하지 않는다.
- 조회 오류·권한 실패·잘못 선택한 가정·실제 빈 결과를 구분한다. 빈 결과만으로 ‘복원’이라 부르는 자동 생성을 하지 않는다.
- 특정인 개인정보 하드코딩을 제거한다. 이메일/동명이인/표시 이름만으로 자동 병합하지 않는다.
- 이름 기반 중복 정리가 실제 다른 가족을 숨기는지 확인한다.
- 실제 데이터 수정은 정확한 대상·원본·복구 계획을 제시하고 별도 승인받는다. 소스 수정 권한을 실제 기록 재연결 권한으로 확대하지 않는다.

완료: 재로그인/새로고침/계정 전환/가정 전환에 중복 생성·기록 혼합·정보 노출 없음. 원본 미발견이면 복원 완료로 처리하지 않는다. 단지 이름만 바꾸는 임시 해결 금지.

### P0-2. 좌우 계약 불일치

발견: app/dtos/anatomy_event.py는 `concept.side`, health_assistant.py는 `body.side`·`body.region`을 읽었다.

수행: 생성→저장→조회→비서 컨텍스트의 단일 계약을 정한다. 신체 기준 left/right/midline/bilateral/unknown, 회전·반사·남녀 atlas를 검증한다. 과거 형식은 명시적 호환 reader로 처리한다. 미상은 추측하지 않는다.

완료: 전 구간 같은 의미, 구버전 읽기 보존, 좌우 입력 변화가 실제 출력에 반영되는 테스트.

### P0-3. 반경의 잘못된 mm 표기

발견: 모델 좌표계 brush radius를 변환 없이 `확산범위 …mm`로 요약했다.

수행: coordinate frame·단위·스케일·값의 의미를 정의한다. 환자별 물리 변환 근거 없으면 mm 표기를 제거한다. 모델 영역을 실제 병변 크기/손상 범위로 설명하지 않는다.

완료: 모델 교체·스케일 변경에도 근거 없는 물리 단위나 손상 추정 없음.

### P0-4. canonical ID와 mesh 이름 혼동

발견: canonicalConceptId=primary.mesh.name인데 mappingStatus='canonical'이었다.

수행: source mesh 식별자와 검증된 해부학 개념 ID를 분리한다. 매핑 없으면 source_fallback/unmapped. 표준 ID를 창작하지 않는다. source/atlas/version/asset hash/topology·매핑 출처를 관리한다. 동일 개념의 다중 mesh와 동명이 mesh를 다룬다.

완료: 검증되지 않은 이름이 표준 ID로 위장되지 않음. topology/LOD 변경 시 대응표 없는 정확 좌표 복원을 보장하지 않고 저하·미지원 표시.

### P0-5. 복수 선택 정보 손실

발견: 여러 선택의 label을 합쳤지만 대표 구조 하나의 ID만 저장했다.

수행: 개별 구조 ID와 선택 범위를 보존한다. 표면 보고/기하 후보/사용자 확정을 구분한다. legacy 단일 이벤트 reader 유지. 합쳐진 문자열을 다시 파싱해 의미를 복원하지 않는다.

완료: 탭·brush·depth·dental·search 각각 다중 선택 저장/조회/비서 전달 후 누락 없음.

### P0-6. 임의 피복률

발견: hitRatio=min(1, 샘플 수/20).

수행: 측정량·분모·샘플링 방법·한계를 정한다. 정의할 수 없으면 피복률 필드를 제거/비활성화하고 호환 처리한다. 이벤트 수와 면적을 혼동하지 않는다. geodesic/표면 연결성을 고려해 인접 손가락·팔과 몸통 간 brush 번짐을 막는다.

완료: 동일 경로를 촘촘히 샘플링했다는 이유로 통증 범위/질병 확률/손상 정도가 커지지 않음. 근사치를 실제 환자 면적·부피로 표현하지 않음.

### P0-7. DTO와 실제 저장 검증 연결

발견: AnatomyEvent DTO/테스트는 있으나 건강기록 저장은 일반 dict payload를 받았다. DTO 파일 존재는 API 검증 증거가 아니다.

수행: create/update/sync 등 모든 진입점에서 해부학 이벤트가 있을 때 검증한다. finite 좌표, 허용 값·반경·샘플·본문 크기, 버전, ID·mapping, profile 권한을 확인한다. label/system/side를 클라이언트 주장만으로 신뢰하지 않는다. 중복 재전송과 변경 충돌을 처리한다. 일반 기록과 기존 이벤트 호환성을 유지한다.

완료: 실제 API 무효 payload 거부/명시 처리 테스트, 권한·재시도·구버전 테스트. 일반 dict 사용 자체가 문제라는 뜻이 아니라 검증되지 않는 실경로를 확인·수정하라는 뜻이다.

### P0-8. 깊이 선택 안정성

발견: 고정 관통 거리, mesh.name 중복 제거, 보이는 mesh 중심 필터링. 이것만으로 신체 반대편 차단이나 안정적 ID가 보장되지 않는다.

수행: all-hit 입출구 중복·동명 구조·region 경계·스케일·열린 mesh·겹친 팔/몸통·앞뒤를 평가한다. 카메라 광선과 표면 법선 안쪽 방향을 구분한다. 상대 hit 순서가 해부학적 층의 확정값은 아니다. rendered/loaded/selectable/selected를 분리하고 미로드를 없음으로 해석하지 않는다.

완료: 반대편·다른 사지 오확정 방지, 불확실한 결과는 후보 표시, pinch/pointercancel 후 자동 확정 없음. 고정 거리 숫자만 조정하고 해결로 보고하지 않는다.

## 5. 기존 로드맵별 잔여 검증 — 원문 전체와 추적표 작성

### ① 모바일 성능 — 기준선은 지금

사용자는 iPhone 12 Pro Max에서 기존 앱의 회전·확대가 느리고 Human Atlas Vercel 앱은 매끄럽다고 직접 확인했다. Human Atlas UI는 불편했다고 했다. 이것은 기기 관찰이지 동일 조건 수치 비교는 아니다.

- 로딩/압축 해제/파싱/GPU 업로드와 조작 프레임 비용을 분리한다. AWS 이동만으로 회전 FPS가 해결된다고 하지 않는다.
- 같은 기기·OS·브라우저·production build·viewport·DPR·자산·계통·카메라 조건, 콜드/웜 각각 기록한다.
- 최소 3회 반복: 30초 회전, 확대, 계통 변경, 선택·depth·brush. frame p50/p95/p99, draw calls/triangles, 입력 지연·전송량·메모리 추정 구분.
- 기존 on-demand 렌더 경로를 확인하고 중복 invalidate, interaction DPR, 미로드 계통, dispose/컨텍스트 복구를 측정한다.
- Human Atlas의 batching/partIndex/렌더-picking 분리/재질/압축은 고정 소스 버전·라이선스를 확인한 후 선택 적용한다. 투명·스키닝·여성 손 애니메이션 예외 보존.
- 큰 renderer 교체는 별도 단계. 모바일 DPR 저하로 치아/신경 선택 품질을 버리지 않는다.
- 실기기 없으면 미검증으로 남긴다. 50 FPS·100ms 등 원문 제안 목표는 측정 실적이 아니다.

### ② 이벤트·일일 기록·비서 — 지금 정확성 보강

- 위 P0-2~7을 먼저 해결한다. 단순 JSON 예제/독립 DTO 작성으로 끝내지 않는다.
- 기존 3D→일기 저장→비서 컨텍스트 경로를 재사용하고 진입점·실제 소비자를 추적한다.
- 연속 brush mask와 전체 구조 하이라이트를 구분하고 저장/재편집/undo/모델 교체/복원 검증.
- LLM은 서버가 검증한 의미·허용된 기록·결정적 통계만 받는다. GLB/실제 문서 전체를 불필요하게 전송하지 않는다.
- 기록 ID·관찰 시점·반대 근거·결측·질문·한계가 있는 설명. 운동 후 호전을 인과관계로 단정하지 않는다.
- 단일 탭 E2E→복수 부위/brush→시계열 요약 순서. 비서→3D 역선택은 ID/의도 검증 후 연결한다.

### ③ 깊이·정밀 선택 — 기존 구현을 지금 평가

다음 여덟 항목 각각 성공/실패/취소/권한 또는 미지원 경로와 테스트를 연결한다.

1. 깊이 다중 후보, 확정·해제, 피부/장기 후보 분리.
2. 계통 필터: 표시와 선택 허용 분리.
3. X-ray: 투명 피부가 선택을 가로채지 않음, 의료 영상으로 오인시키지 않음.
4. 자동 확대/주변 분리: 화면 가용 영역 고려, 기존 카메라·필터 복원, 표시 변환과 원본 좌표 분리.
5. 치아: 실제 자산의 FDI 매핑과 누락·합쳐진 mesh 검증. 28개 정밀 매칭이라는 문구만 믿지 말고 좌우·번호·사랑니/유치 지원 범위를 검증.
6. 넓은 터치 허용: screen-space 후보와 정확 hit 분리, 겹치면 선택 목록, 임의 점수를 의학적 신뢰도로 표현하지 않음.
7. 텍스트+3D: 부정·좌우·모호함·기존 선택 충돌 처리. ‘어금니’를 특정 번호로 조용히 확정하지 않음.
8. 검색 역선택: 한영/동의어/ID, 숨김·미로드 로드, 검색 취소 후 stale 응답 차단.

모바일 pinch/drag/tap, 키보드·스크린리더, 세로/가로, 하단 시트 가림, 스프레이 지우기 후 투명도, 모델 교체를 평가한다. 자동화 통과와 사용자 실기기 과제 성공을 별도로 기록한다.
