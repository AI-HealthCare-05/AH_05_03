# ADR-006: 연결 생명주기 단위의 일회용 프로필 참조값

- 상태: 승인
- 결정일: 2026-08-19
- 적용 대상: 가족 초대, 서비스 계정·로컬 프로필 연결, 연결 해제·재연결, 프로필 병합과 백업 복구
- 관련 결정: [ADR-001](0001-web-local-first-architecture.md), [ADR-002](0002-separate-server-api-and-local-domain-contract.md), [ADR-004](0004-family-invitation-state-and-redis-boundary.md)

## 배경

서버는 가족 구성원 로컬 프로필의 내용과 로컬 `profileId`를 알 수 없어야 하지만, 초대 대상과 서비스 계정의 연결을 확인할 불투명 참조값은 필요하다. 이 값을 프로필의 영구 식별자로 사용하면 연결 해제 뒤 남은 값이 재연결에 악용되거나, 병합된 프로필이 잘못 다시 연결되고, 서버가 장기간 같은 프로필을 연관 지을 수 있다.

반대로 HTTP 요청마다 값을 바꾸면 재시도와 멱등 처리가 불가능해진다. 따라서 일회성의 범위를 요청 한 번이 아니라 논리적인 연결 한 번으로 정한다.

## 결정

- 브라우저의 로컬 `profileId`는 프로필 수명 동안 유지하며 서버에 보내지 않는다.
- 서버용 `opaqueServerRef`는 32바이트 이상의 CSPRNG로 만들고 한 번의 연결 생명주기에서만 사용한다.
- 초대 생성부터 수락·프로필 연결 완료까지 같은 참조값을 사용한다. 동일 작업의 네트워크 재시도에서도 값을 바꾸지 않는다.
- 초대가 거절·취소·만료되거나, 연결이 해제되거나, 대상 계정이 바뀌거나, 프로필이 병합되면 해당 참조값을 폐기한다.
- 재초대·재연결에는 새로운 참조값을 만든다. 백업에 남은 폐기 참조값도 다시 활성화하지 않는다.
- 단순 기기 연결 해제나 동기화 일시 중지는 프로필 연결 종료와 구분하며, 논리적 연결이 유지되는 동안에는 참조값을 폐기하지 않는다.
- PostgreSQL이 활성·폐기 참조값의 정본이다. 종료 행을 보존하고 가정 범위에서 참조값의 생애 전체 재사용을 유일 제약으로 막는다.
- Redis는 초대 원문 토큰, 소비 마커, 속도 제한과 워커 인계처럼 만료 가능한 상태에만 사용한다. 참조값 재사용 금지의 정본이나 분산 잠금으로 사용하지 않는다.

## 검토한 대안

### 프로필마다 영구적으로 고정된 참조값

기각한다. 재연결은 단순하지만 연결 해제가 참조값의 실질적 폐기가 되지 않고, 오래된 초대·백업·다른 기기의 값이 재사용될 수 있다. 서버가 동일 프로필을 장기간 연관 지을 가능성도 커진다.

### HTTP 요청마다 새 참조값 발급

기각한다. 타임아웃 재시도와 멱등 요청이 다른 연결로 해석되어 중복·불일치가 발생한다. 참조값은 요청이 아니라 연결 생명주기에 묶어야 한다.

### Redis TTL로 폐기 참조값 기억

기각한다. TTL 만료, eviction 또는 Redis 데이터 유실 뒤 참조값이 다시 허용될 수 있다. 영구적인 재사용 금지는 PostgreSQL 제약과 종료 이력으로 보장한다.

### 영구 프로필 참조값과 연결별 nonce를 함께 사용

현재는 기각한다. 연결 취소는 명확해지지만 서버가 영구 참조값으로 프로필을 계속 연관 지을 수 있고 식별자·제약·API가 이중화된다. 장기 다중 기기 동기화가 영구 서버 식별자를 요구할 때 새 ADR로 재검토한다.

### 연결 해제 시 행을 물리 삭제

기각한다. 과거 참조값의 재사용을 막을 근거와 감사 가능한 상태 전이가 사라진다.

## 결과와 감수할 단점

### 장점

- 연결 해제가 참조값 폐기까지 포함하므로 오래된 값의 재사용과 잘못된 재연결을 차단한다.
- 병합된 원본 프로필과 이전 계정의 참조값을 새 연결에 사용할 수 없다.
- 연결별 감사 이력이 분리되고 서버의 장기 연관 가능성이 줄어든다.
- Redis 만료 정책과 무관하게 PostgreSQL 제약으로 재사용 금지를 유지한다.

### 단점

- 브라우저는 참조값의 `pending`, `active`, `retired` 상태와 서버 성공 후 로컬 저장 실패에 대한 보상 처리를 관리해야 한다.
- 다른 기기와 오래된 백업에는 폐기된 값이 남을 수 있으므로 가져오기·재연결 때 새 값을 발급해야 한다.
- 종료된 연결 행을 보존하므로 데이터가 누적되고 보존·삭제 정책이 필요하다.
- 사용자가 단순 동기화 중지와 계정·프로필 연결 해제를 혼동하지 않도록 UI를 구분해야 한다.

## 재검토 조건

다중 기기 암호화 동기화가 영구 장치 키나 안정적인 프로필 식별자를 요구하거나, 법적 삭제 요구로 폐기 참조값 원문을 보존할 수 없게 되면 해시 기반 tombstone 또는 별도 연결 식별자를 새 ADR에서 비교한다.

## 한 문장 요약

> 로컬 프로필 ID는 고정하되 서버용 불투명 참조값은 한 번의 연결 생명주기에만 쓰고, 폐기 이력과 재사용 금지는 PostgreSQL이 보장한다.
