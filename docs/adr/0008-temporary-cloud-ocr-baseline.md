# ADR-008: 개발 검증용 클라우드 OCR 기준선 허용

- 상태: 부분 대체됨 — 제3자 OCR 통제는 유지하며 서버 비저장·로컬 보관 조항은 [ADR-011](0011-postgresql-health-data-and-server-ai.md) 참조
- 결정일: 2026-08-20
- 적용 대상: 한국어 건강문서 OCR 개발·데모, Naver CLOVA OCR 연동, OCR 결과의 로컬 저장 경계
- 관련 결정: [ADR-001](0001-web-local-first-architecture.md), [ADR-002](0002-separate-server-api-and-local-domain-contract.md), [ADR-005](0005-vite-spa-local-first-frontend-foundation.md)
- 실행 계획: [OCR 클라우드 기준선·로컬 대체 챌린지](../16_ocr_cloud_baseline_local_replacement_challenge.md)

## 배경

이어봄은 실제 건강정보를 사용자 기기에서 처리하는 로컬 우선 제품을 목표로 한다. 그러나 프로젝트 기간 안에 한국어 건강검진표의 OCR 입력·검토·구조화·차트 반영 흐름을 검증하려면 비교 가능한 인식 기준선이 필요하다. 브라우저 OCR만으로 정확도 개선과 제품 흐름 구현을 동시에 진행하면 어느 쪽도 검증하지 못할 위험이 있다.

Naver CLOVA OCR은 문서 파일을 외부 사업자에게 전송하므로 기존 로컬 처리 원칙의 일반 경로로 사용할 수 없다. 프로젝트의 합성·비식별 검증 경로에 한정한 명시적 예외와 최종 로컬 대체 목표를 구분한다.

## 결정

- Naver CLOVA OCR을 프로젝트 기간의 **임시 클라우드 기준선**으로 허용한다.
- Naver OCR에는 합성 문서와 재식별할 수 없도록 비식별 처리한 검증 문서만 전송한다.
- 개인정보가 포함된 실제 건강문서는 별도의 동의·개인정보 처리 검토와 새 결정 없이는 Naver OCR로 전송하지 않는다.
- 클라우드 OCR은 사용자가 직접 선택한 경우에만 실행한다. 로컬 OCR 실패 후 조용히 외부 OCR로 전환하지 않는다.
- 화면은 실행 전에 외부 사업자 전송 사실을 알리고 현재 사용 엔진을 표시한다.
- Naver 인증 비밀값은 서버에만 두며 브라우저에 제공하지 않는다.
- FastAPI는 요청을 중계하고 결과를 반환할 수 있지만 원본 문서와 OCR 결과를 PostgreSQL, Redis, 서버 파일시스템, 요청 로그, APM payload에 저장하지 않는다.
- OCR 결과는 자동으로 건강기록·예측·차트의 확정값이 되지 않는다. 사용자가 검토·수정하고 확정한 구조화 결과만 브라우저 암호화 보관함에 저장한다.
- 제품 코드는 공통 OCR 엔진 계약을 사용하고 Naver 전용 요청·응답 형식을 UI와 Local Domain에 노출하지 않는다.
- 기본 제품 목표는 브라우저 또는 사용자 기기에서 실행되는 로컬 OCR이다. 후보 비교·평가지표·일정은 변경 가능한 챌린지 문서에서 관리한다.

## 검토한 대안

### 프로젝트에서도 외부 OCR을 전면 금지

기각한다. 데이터 경계는 가장 단순하지만 한국어 건강문서 제품 흐름과 로컬 후보의 상대 성능을 프로젝트 기간 안에 검증하기 어렵다. 합성·비식별 입력으로 제한한 기준선은 최종 로컬 대체 판단에 유용하다.

### Naver OCR을 제품의 기본 엔진으로 사용

기각한다. 외부 전송이 예외가 아니라 기본 동작이 되고 로컬 우선 제품 설명과 충돌한다. 공급자 장애·비용·약관과 네트워크에도 종속된다.

### 로컬 OCR 실패 시 사용자에게 알리지 않고 Naver로 전환

기각한다. 사용자가 건강문서의 외부 전송 여부를 통제할 수 없으며 로컬 처리라고 오인하게 만든다.

### 원본이나 결과를 Redis에 짧은 TTL로 저장

기각한다. TTL과 삭제는 외부 전송을 없애지 않으며 persistence, 복제, 백업과 운영 로그에 사본이 남을 수 있다. 비동기 상태가 필요하면 문서 내용이 없는 작업 식별자·상태·만료 시각만 저장한다.

### 브라우저에서 Naver OCR을 직접 호출

기각한다. Naver 인증 비밀값이 사용자에게 노출되고 호출 제어·감사·남용 방지가 불가능해진다.

### 지금 하나의 로컬 OCR·VLM을 최종 엔진으로 확정

보류한다. 한국어 건강문서 정확도, 브라우저 성능, 모델 크기와 지원 범위를 동일한 데이터로 비교한 결과가 없다. 챌린지 결과가 채택 기준을 충족한 뒤 새 결정 또는 본 ADR의 후속 ADR로 확정한다.

## 결과와 감수할 단점

- 한국어 OCR 제품 흐름과 로컬 후보의 품질을 같은 기준선으로 비교할 수 있다.
- 클라우드 경로가 별도 어댑터로 격리되어 최종 로컬 엔진으로 교체하기 쉽다.
- 개발·데모 입력을 합성·비식별 문서로 준비해야 하며 실제 사용자 문서로 간편하게 시험할 수 없다.
- FastAPI 중계 경로의 로그·오류 추적·메모리 처리까지 민감정보 비저장 검증이 필요하다.
- 클라우드 기준선의 정확도가 높더라도 외부 전송 제한 때문에 그대로 기본 제품 엔진으로 채택할 수 없다.

## 재검토 조건

- 로컬 엔진이 합의한 한국어 건강문서 정확도·성능 기준을 충족한다.
- 실제 개인정보 문서의 외부 OCR 사용이 제품 요구가 되어 동의, 위수탁 관계, 보관 정책과 삭제 보증을 검토해야 한다.
- 클라우드 OCR이 제품의 기본 경로가 되어야 한다는 요구가 생긴다.
- Naver API·약관·리전·처리 정책 또는 비용 구조가 변경된다.

## 한 문장 요약

> Naver OCR은 합성·비식별 한국어 건강문서의 임시 개발 기준선으로만 허용하고, 결과는 사용자 검토 후 브라우저에만 저장하며 최종 제품은 로컬 OCR 대체를 목표로 한다.
