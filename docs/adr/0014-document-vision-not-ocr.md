# ADR-0014: 건강서류 판독은 OCR이 아니라 멀티모달 LLM Vision이다

- 상태: 기준안
- 결정일: 2026-09-20
- 적용 대상: 요구사항·아키텍처·발표 용어, 건강서류 판독 엔진
- 대체 대상:
  - [ADR-0008](0008-temporary-cloud-ocr-baseline.md)의 **기본 인식 엔진** 자리(Naver CLOVA를 임시 클라우드 OCR 기준선으로 두는 조항)
  - [ADR-0010](0010-checkup-document-ocr-path.md)의 **기본 엔진** 조항(OCR+도메인 규칙 파이프라인을 기본으로 두고 멀티모달 직송을 기본이 아니라고 한 결정)
- 유지하는 조항:
  - ADR-0008의 합성·비식별 입력, 사용자 선택·고지, 비밀값은 서버만, 자동 확정 금지
  - ADR-0011의 PostgreSQL 건강정보 정본, 외부 전송 고지·최소 필드
  - ADR-0010이 가른 “건강문서 이해”와 영상 질환 분류의 구분
- 관련 결정: [ADR-0011](0011-postgresql-health-data-and-server-ai.md)
- 구현 기록: [44 기술 선택](../44_tech_choices_ocr_and_storage.md) (2026-09-18 현재 모델 정책)
- 용어 정본: [00_terminology.md](../00_terminology.md)

## 배경

ADR-0008은 프로젝트 기간의 인식 기준선으로 Naver CLOVA OCR을 허용했다. ADR-0010은 RapidOCR(PP-OCR)+항목 사전을 기본 엔진으로 두고, 멀티모달 직송은 좌표·위험 오류 검사 때문에 기본이 아니라고 적었다. 둘 다 **제안 또는 당시 기준선**이며, 이후 구현은 전용 OCR 엔진 없이 이미지·PDF를 멀티모달 LLM Vision에 넣는 경로로 고정됐다.

코드·큐·에러 식별자는 `ocr`로 남아 있다. 설계·발표에서 이를 OCR 엔진으로 부르면 RapidOCR/CLOVA 구현을 찾거나, 에이전트가 서류를 연속 읽는다고 오해한다.

건강정보 정본은 ADR-0011에 따라 PostgreSQL이다. 이 ADR은 ADR-0011의 서버 정본·서버 AI 처리 결정을 변경하지 않으며, 문서 판독 엔진과 외부 Vision 전송 범위만 결정한다.

## 결정

- 설계·발표·평가 답변에서 이 기능을 **OCR**이라고 부르지 않는다.
- 정식 명칭은 **문서 Vision 판독**(멀티모달 LLM Vision으로 이미지·PDF를 구조화)이다.
- 전용 OCR 엔진(Tesseract, RapidOCR/PP-OCR, CLOVA 등)은 현재 제품 기본 경로가 아니다.
- 기본 호출은 Gemini Vision이다. 예비 모델은 설정으로만 둔다. 수치 매핑 관문은 `ocr_measurements`가 유지한다.
- 판독 결과는 초안이다. 사용자가 수정·확정한 값만 건강기록이 되며, 정본은 서버(ADR-0011)에 저장한다.
- 코드·API의 `ocr` 식별자는 역사적 이름이다. 의미는 이 ADR을 따른다.
- 이 경로는 에이전트 루프가 아니다. 챗봇 도구로 원본 서류를 연속 호출하지 않는다([ADR-0015](0015-bounded-agent-on-policy-and-evidence.md)).
- 로컬 픽셀 마스킹이 끝나기 전에는 합성·비식별 문서만 외부 Vision에 보낸다. `document_id`만 넘기는 것은 원본 전송을 숨기지 않는다.
- 프롬프트로 개인정보를 무시하라고 하는 것은 마스킹이 아니다.

## 검토한 대안

### 설계에도 OCR이라고 계속 쓴다

기각. 엔진과 기능이 다른데 같은 말을 쓰면 RapidOCR·CLOVA 구현을 찾거나 Vision을 OCR 엔진으로 오해한다.

### ADR-0010대로 RapidOCR 파이프라인을 기본으로 되돌린다

현재 릴리스에서 기각. 병원마다 다른 표·한글 검사명·다중 페이지 PDF에 Vision이 맞다는 팀 합의와 [44번 문서](../44_tech_choices_ocr_and_storage.md)의 현재 모델 정책을 따른다. 좌표 기반 하이브리드는 후속 검토다.

### 코드의 `ocr` 식별자를 즉시 전부 개명한다

보류. 문서 혼동을 줄이는 일과 API 호환을 깨는 일은 별개다.

## 결과와 감수할 단점

- 발표·에이전트 설계에서 “OCR 엔진을 만들었다”는 오해가 줄어든다.
- 원본이 외부 모델 공급자에게 나간다. 합성·비식별과 이후 픽셀 마스킹이 그 대가를 제한한다.
- ADR-0008·0010 본문은 역사로 남는다. 엔진 조항만 이 ADR이 대체한다.

## 재검토 조건

- 오프라인·기기 내 전용 OCR을 다시 기본 경로로 둘 때
- 로컬 비식별화 후 Vision 전송 정책을 바꿀 때
- 코드 식별자를 `document_vision` 등으로 일괄 개명할 때

## 한 문장 요약

> 이어봄의 건강서류 입력은 OCR 엔진이 아니라 멀티모달 LLM Vision 판독이며, 설계 문서에서는 OCR이라고 부르지 않는다. ADR-0008·0010의 엔진 자리는 이 결정이 대체한다.
