# ADR-012: 구성원 위임 PIN은 인가 층이며 보관함 DEK가 아니다

- 상태: 승인
- 결정일: 2026-09-19
- 승인일: 2026-09-19
- 적용 대상: 공용 가구 화면(벽·키오스크)의 구성원 전환, 임시 PIN 발급·재발급, 숨김·가족 공유 제외·프로필 삭제 구분
- 관련 결정: [ADR-006](0006-lifecycle-scoped-profile-reference.md), [ADR-007](0007-account-scoped-encrypted-local-vault.md), [ADR-011](0011-postgresql-health-data-and-server-ai.md)
- 관련 문서: [08 계정·프로필 정책](../08_account_profile_policy.md), Epic [#187](https://github.com/AI-HealthCare-05/AH_05_03/issues/187), 문서 정합성 [#188](https://github.com/AI-HealthCare-05/AH_05_03/issues/188)
- 구현 후속: 소유권·capability [#189](https://github.com/AI-HealthCare-05/AH_05_03/issues/189), 벽 기기 [#190](https://github.com/AI-HealthCare-05/AH_05_03/issues/190), 서버 PIN [#191](https://github.com/AI-HealthCare-05/AH_05_03/issues/191), 미성년 보호자 [#194](https://github.com/AI-HealthCare-05/AH_05_03/issues/194)

## 배경

ADR-007은 보관함 DEK의 잠금 수단을 계정 비밀번호와 분리하고, PIN·패스키 조합은 별도 결정으로 미뤄 두었다. ADR-011은 건강정보 정본을 PostgreSQL로 옮겼다. 그 위에서 공용 벽 기기를 쓰려면, 마스터가 연 가구 세션 안에서 **지금 누구 권한으로 화면을 쓰는지**를 가르는 층이 필요하다.

08번 문서는 가족 구성원 프로필에 “로그인 비밀번호가 없다”고 적혀 있다. 이는 **서비스 계정 비밀번호가 없다**는 뜻으로 유지한다. 6자리 PIN으로 건강정보를 암호화하거나 계정 복구를 하면 ADR-002·007·011과 충돌한다.

현재 가족 홈은 브라우저 `localStorage`에 PIN 해시(PBKDF2)를 두는 임시 경로다. 이 ADR이 묶는 것은 저장 위치가 아니라 **용도 분리**다. 서버 자격 증명·기기 바인딩은 #191이 옮긴다.

## 결정

### 1. 두 개의 열쇠

| 층 | 하는 일 | 하지 않는 일 |
|---|---|---|
| 마스터 패스키·복구키·서비스 계정 재인증 | 가구 보관함·서버 세션·새 벽 기기 등록 | 구성원 카드 전환 |
| 구성원 위임 PIN | 이미 열린 가구 기기에서 행위자(`profileId`)와 역할만 확인 | DEK 파생, 계정 로그인, 새 기기 등록, 관리자 재인증 |

PIN 원문은 한 번만 보여주고 해시만 보관한다. 마스터는 재조회하지 못하고 폐기·재발급만 한다. 미성년 관리형 프로필의 재설정은 허용된 보호자가 한다.

### 2. 역할은 PIN 위에 붙는다

관계는 기본 역할만 고른다. 세부 권한은 capability 묶음으로 서버가 평가한다(#189).

| 관계 예 | 기본 역할 | 의도 |
|---|---|---|
| 본인·배우자·부모·형제·자매 | `adult_member` | 자기 기록과 위임된 돌봄 |
| 자녀 | `self_only` | 자기 기록만 |
| 기타 | `restricted` | 보기·챌린지 수준 |

이메일로 계정을 나중에 붙여도 프로필 ID는 유지한다(ADR-006).

### 3. 숨김 · 공유 제외 · 삭제는 다른 동작이다

| 용어 | 의미 | 지금 구현 |
|---|---|---|
| 벽에서 숨기기 | 소속·기록 유지, 목록에서만 가림 | `PATCH` `status=hidden` |
| 프로필 보관 | 일반 목록 제외, 쓰기 차단, 복구 가능 | `POST /profiles/{id}/archives` |
| 가족 공유에서 제외 | 이 집 구성원에서 뺌. 상대 계정·개인 기록은 지우지 않음 | `POST /profiles/{id}/household-unshares` (#192) |
| 빈 슬롯 파기 / 휴지통 | 기록 0건은 즉시, 있으면 30일 후 파기 | `POST /profiles/{id}/deletion-requests` → `POST /profile-purge-jobs` (#193) |
| 회원탈퇴 | 서비스 계정 종료 | 기존 #64. PIN·프로필 삭제와 섞지 않음 |

만 14세 미만 연결 프로필의 삭제 **요청**은 법정대리인 확인 절차가 필요하며, 제품 보호자 체크만으로는 완료하지 않는다. 확인 공급자 선정은 아직 미확정이며 기본 구현은 `pending`만 만든다. 만 14세 개인정보 자기결정과 만 19세 민법상 성년은 [ADR-013](0013-privacy-self-determination-and-civil-majority.md)이 가른다.

### 4. 관리자 재인증이 필요한 일

구성원 PIN만으로는 다음을 하지 않는다.

- 새 벽 기기 등록·철회(#190)
- 가정 폐쇄
- 연결된 성인의 서버 멤버십 강제 해제(`POST /profiles/{id}/household-unshares`, 비밀번호 재인증)
- 마스터 복구키·패스키 변경
- 만 14세 개인정보 자기결정 표시, 만 19세 성년 전환, 생년월일 정정(ADR-013)

프로필 이름 수정과 빈 슬롯 숨김은 마스터가 연 가구 화면의 관리 ⋯에서 할 수 있다. 레일에서 그 사람으로 **전환**할 때만 PIN을 묻는다.

### 5. 시도 제한

연속 실패 잠금, 세션 만료, 자리 비움(가족 개요로 복귀)을 둔다. PIN을 아는 사람까지의 감사이지 법적 본인 확인이 아니다.

## 검토한 대안

### 구성원 PIN으로 DEK를 파생

기각한다. 6자리는 추측·어깨 너머에 약하고, 분실 시 서버가 건강정보를 복구할 수 없다. ADR-007이 계정 비밀번호로 DEK를 만드는 길을 이미 기각한 이유와 같다.

### 이메일 없는 구성원에게 서비스 계정 비밀번호를 만든다

기각한다. 08번의 로컬 프로필 정의와 초대·claim 흐름을  Twin 로그인으로 만든다.

### 마스터 PIN 하나를 가족에게 나눠 준다

기각한다. 행위자 감사와 개별 폐기·재발급이 불가능하다.

### 마스터가 활성 멤버를 바로 LEFT로 내리는 API를 이번 결정에 넣는다

보류했던 강제 퇴장은 #192 `POST /profiles/{id}/household-unshares`로 열었다. 계정 삭제·기록 파기와 같은 API가 아니다.

### 벽 기기 PIN·보호자 체크로 성년 전환을 끝낸다

기각한다. PIN은 행위자만 가른다. 성년 전환은 당사자 서비스 계정 재인증과 Profile Claim이 필요하다(ADR-013).

## 결과와 감수할 단점

- 공용 벽에서 이메일 없이 구성원을 가를 수 있다.
- PIN 유출은 그 역할로 오인된 기록만 만든다. 다른 기기에서 가구 전체를 열지는 못한다.
- 브라우저 로컬 해시는 기기 이전·말소에 약하다. #191 이전에는 이 기기 한정 인가로만 취급한다.

## 재검토 조건

- 서버 `member_pin_credentials`와 등록 기기 바인딩이 생긴다.
- 관리자 역할(#62)이 확정되어 강제 퇴장 API를 연다.
- 패스키 PRF로 벽 기기 등록 재인증을 바꾼다.
- 법정대리인 확인 공급자를 고른다. 연령 경계는 ADR-013 정책 버전을 따른다.

## 한 문장 요약

> 구성원 PIN은 열린 가구 기기에서 누구로 쓰는지만 가르고, 건강정보 암호·계정 비밀번호·새 기기 등록 열쇠가 아니다.
