# 38. 챌린지 정원 — 초기 구현

> 작성일: 2026-08-26
> 선행 결정: [37 챌린지 아이디어](37_challenge_design_ideas.md) §14~§16 (측정 챌린지 + 가정 협동)
> 성격: 이 문서는 **구현 기록**이다. 게임 형태는 팀 논의로 정했고 그 결과만 적는다.

Talos 필수 셋 중 마지막으로 비어 있던 칸을 채웠다. 에셋은 코드로 그린 임시 형태이고, 정밀한 일러스트는 나중에 갈아 끼운다.

## 0. 세 줄

1. **점수 식에 건강 수치가 없다.** 입력이 `(challenge_id, 날짜)` 뿐이라 당뇨 `HIGH` 인 사람과 `NORMAL` 인 사람이 같은 행동을 하면 같은 점수를 받는다. 가족 랭킹이 건강 랭킹으로 변할 수 없다.
2. **`challenge_checks` 에 값 칼럼이 없다.** 정책을 문서가 아니라 스키마가 강제한다.
3. **누적값을 저장하지 않는다.** 점수·나무 단계·영양 단계를 매 요청마다 이력에서 다시 계산한다. 규칙을 고치면 과거도 같이 새 규칙으로 계산된다.

## 1. 게임 루프

```
매일   4종 전부 체크 → 물 1회
매주   물 5일 이상 + 측정 1회 → 그 주 완주 → 흙(영양) 한 칸 ↑
장기   연속 기록으로 동물이 온다. 한번 오면 떠나지 않는다
```

| 층 | 무엇을 세나 | 오르내림 |
|---|---|---|
| 나무 크기 | 누적 점수 | **절대 안 줄어든다** |
| 흙(영양) | 지금 몇 주 연속인가 | 한 주마다 ±1칸. 0으로 리셋하지 않는다 |
| 동물 | 최고 기록 · 처음 한 일 | **영구** |

셋을 가른 이유는 "한번 오면 떠나지 않는다"를 지키려면 동물을 연속 상태에 직접 걸 수 없기 때문이다. 8주 연속을 한 번 달성하면 부엉이가 오고, 다음 주에 끊겨도 흙만 내려간다.

### 물주기는 전부 채웠을 때만

부분 달성도 점수는 들어간다. 다만 물주기는 4/4일 때만 일어나고 그 순간만 연출이 붙는다. 3개 하고 아무것도 못 받으면 다음 날 안 온다.

### 시들지 않는다

안 하면 그냥 안 자란다. 벌칙 문구도, 시드는 연출도 없다.

## 2. 카탈로그

`app/services/challenge_catalog.py` 에 있다. DB 테이블로 두지 않았다 — 전원에게 같은 표이고 사용자가 만들지 않는다.

### 매일 (각 1점)

`walk` 걸음 7,000보 · `exercise` 운동 20분 · `diet` 채소 한 접시·절주 · `sedentary` 한 시간에 한 번 일어나기

### 재기

| id | 점수 | 여는 판정 칸 |
|---|---:|---|
| `weight` 체중·허리둘레 | 5 | `obesity` · `mets` |
| `bp` 혈압 | 10 | `htn` |
| `lab` 검사값·검진 결과지 | 20 | `dm` · `dlp` · `ckd` · `liver` |

**부정하기 어려운 쪽에 점수를 몰아 뒀다.** 매일 만점을 받아도 주 28점인데 검진 결과지 한 번이 20점이다. 걸음 7,000보는 안 걷고도 누를 수 있지만 측정은 값을 넣어야 완료되고, 거짓 값을 넣으면 자기 판정이 틀어진다. **부정의 이득이 자기기만뿐인 쪽이 무겁다.**

### 나무 여섯 단계

`seed` 0 → `sprout` 12 → `sapling` 30 → `young` 70 → `tree` 130 → `fruiting` 380

앞을 촘촘히 뒀다. 성실한 사용자 기준 실측 진행은 이렇다.

| 주차 | 점수 | 단계 | 흙 | 동물 |
|---:|---:|---|---|---|
| 1 | 29 | 새싹 | 물 ×1.2 | 나비 · 벌 |
| 2 | 64 | 묘목 | 거름 ×1.5 | + 새 |
| 3 | 108 | 어린나무 | 좋은 흙 ×2.0 | |
| 4 | 166 | **나무** | 뿌리내림 ×2.5 | + 다람쥐 |
| 8 | 454 | **열매나무** | | + 부엉이 |

4주 시연에서 다섯 번째 단계까지 자란다. 마지막 단계(380)는 부엉이(8주 연속)와 맞춰 뒀다 — 220으로 뒀다가 6주에 만렙이 되어 뒤가 비었다.

### 동물 일곱 = 눈에 보이는 배지

| 동물 | 조건 |
|---|---|
| 나비 | 첫 물주기 |
| 벌 | 처음 재본 날 |
| 새 | 2주 연속 완주 |
| 다람쥐 | 4주 연속 완주 |
| 고양이 | 온 가족이 같은 주에 완주 |
| 사슴 | 측정 12번 누적 |
| 부엉이 | 8주 연속 완주 |

배지 UI를 따로 만들지 않았다. 동물이 배지의 시각적 형태다.

**앞의 둘을 아주 쉽게 뒀다.** 늦게 시작한 사람이 가족 화면에서 텅 빈 나무만 보면 접는다. 첫날 4종을 채우고 한 번 재면 그 자리에서 둘이 온다.

**사슴 조건을 바꿨다.** 논의에서는 "판정 칸 절반 개방"이었는데 **서버는 판정 결과를 모른다** — 판정은 브라우저에서 일어난다. 그래서 서버가 아는 것(측정 횟수)으로 옮겼다.

| 아는 것 | 모르는 것 |

| `account_id` · `challenge_id` · `checked_on` | 잰 값 |

## 5. 에셋 — 임시라고 적어 둔다

**나무와 동물이 전부 코드다.** 나무는 줄기 높이·잎 반지름·겹수·열매 수를 파라미터로 여섯 단계를 만들고, 동물은 24×24 좌표계의 단색 실루엣 일곱이다.

3주 안에 넣기 위한 선택이다. 실루엣은 여러 사람이 손대도 스타일이 안 튀고, 무엇보다 **정밀한 일러스트로 갈아 끼울 때 `GardenArt.tsx` 만 바꾸면 된다** — 화면 쪽은 `stage` 와 `animalId` 만 알고 있으므로 계약이 안 깨진다.

### 색은 새로 세웠다

`styles.css` 에 `--garden-leaf` · `--garden-leaf-deep` · `--garden-trunk` · `--garden-soil` · `--garden-fruit` 다섯을 신설했다.

**DESIGN.md §2 가 상태 색 3종을 "위험도 표기·차트·뱃지에서만" 으로 묶어 뒀기 때문이다.** 나무에 `--safe` 초록을 쓰면 나무가 저위험 뱃지로 읽히는데, 나무는 건강 상태가 아니라 행동 점수로 자란다. **색이 설계 원칙을 배신하는 자리**라 채도를 낮춰 상태 초록과 의도적으로 갈랐다. 갈색·흙색은 디자인 시스템에 아예 없어서 기존 역할과 충돌하지 않는다.

근거는 `.omd/preferences.md` 의 `garden-illustration-palette-intentional` 에 남겼다. 이 다섯은 일러스트에만 쓰고 버튼·링크·내비게이션·뱃지에 쓰지 않는다.

## 6. 구현하면서 잡은 것 넷

**하나 — 결석한 주가 세어지지 않았다.** 기록이 있는 주만 순회하면 빈 주가 조회에 안 잡혀서 **한 달 사라졌다 돌아온 사용자의 연속이 그대로 이어졌다.** 첫 주부터 이번 주까지 한 주도 빠뜨리지 않고 걸어야 결석이 결석으로 세어진다. 검사로 못 박았다(`test_a_skipped_week_breaks_the_streak`).

**둘 — 일요일에 채웠는데 보상이 월요일에 왔다.** 진행 중인 주를 판정에서 통째로 제외했더니 일요일 저녁에 마지막 칸을 채운 순간이 비었다. **깎지만 않고, 조건을 이미 채웠으면 그 자리에서 준다** 로 갈랐다.

**셋 — 열매나무가 6주에 만렙이었다.** 흙 배수 때문에 점수가 가속되는 것을 계산에 안 넣었다. 마지막 단계를 380으로 올려 부엉이와 맞췄다.

**넷 — `ZoneInfo("Asia/Seoul")` 가 Windows 에서 임포트 시점에 터진다.** `tzdata` 패키지가 없으면 `ZoneInfoNotFoundError` 다. 도커에서는 되고 호스트에서는 안 되는 모듈을 또 만들 이유가 없어서(36번 §7-5 4-1 과 같은 부류) 고정 오프셋 `UTC+9` 로 바꿨다. 한국은 1988년 이후 서머타임이 없어 항상 맞다.

## 7. 대시보드 연동

`features/challenge/ChallengeDashboardCard.tsx` 를 가족 홈(`HomePage`) 구성원 목록 위에 얹었다. 나무 · 오늘 남은 개수 · 점수 · 흙 · 연속 주 · 이번 주 측정 여부를 요약하고 `/challenge` 로 보낸다.

**로그인 전이거나 서버가 안 붙으면 아무것도 그리지 않는다.** 대시보드는 로컬 우선 화면이라 서버가 없어도 나머지가 그대로 동작해야 하고, 여기서 오류 배너를 띄우면 로그인 안 한 사용자에게 매번 빨간 줄이 뜬다. 검사로 못 박았다(`test 로그인 전에는 아무것도 그리지 않는다`).

`HomePage.test.tsx` 의 렌더 하네스에 `QueryClientProvider` 를 더했다. 운영에서는 `AppProviders` 가 항상 감싸는데 그 하네스에만 빠져 있었고, 서버 상태를 읽는 카드가 붙으면서 드러났다.

### 백엔드 전체에서 5건이 빨갛다 — 전부 환경 의존이고 이번 변경과 무관하다

`pytest app` 전체는 **222 통과 · 5 실패 · 47 스킵**이다. 다섯을 파 보니 원인이 둘뿐이고 챌린지 코드를 하나도 안 지난다.

**하나 — `test_login_sets_hardened_refresh_cookie`.** 테스트가 `Secure` 를 기대하는데 `docker-compose.yml` 이 로컬 HTTP 실험용으로 `REFRESH_COOKIE_SECURE: "false"` 를 넣는다. 컨테이너에서 돌리면 반드시 깨진다.

**둘 — 예측 4건.** 테스트가 `MODEL_DIR = parents[3] / "modeling" / "artifacts" / "models"` 를 보는데 **컨테이너에 `/app/modeling` 이 없다.** 모델은 `/app/models` 에만 마운트된다(compose 가 그렇게 건다). 그래서 `ALL_BUNDLES` 가 빈 목록이 되고 `assert 20 == 0` 이 난다 — 서버는 20개를 정상 적재하고 있는데 테스트만 못 찾는다.

**추측이 아니라 실측이다.** 같은 파일을 호스트에서 돌리면 **83건 전부 통과한다**(9분 1초). 같은 코드·같은 커밋인데 경로 하나로 갈린다.

```
컨테이너  pytest app/tests/prediction_apis/  →  4 failed   (/app/modeling 없음)
호스트    pytest app/tests/prediction_apis/  →  83 passed  (modeling/ 있음)
```

**둘 다 36번 §7-5 4-2 가 지적한 "환경 의존 테스트" 와 같은 부류다.** 그 문서가 적은 대로 "그런 테스트는 아무도 믿지 않게 되므로" 고치는 편이 낫다. 이번 변경 범위 밖이라 손대지 않았고, 고친다면 둘 중 하나다 — compose 에 `./modeling:/app/modeling:ro` 를 더하거나, `MODEL_DIR` 이 `/app/models` 로 떨어지게 하는 것. **§9 에 항목으로 올린다.**

## 9. 최적화 — 2026-08-26 2차

§8 에서 "지연은 기준 안"이라고 확인한 뒤, 재 보고 나서 고칠 곳을 골랐다. 넷을 고쳤고 넷 다 실측으로 확인했다.

### 9-1. 체크 한 번에 쿼리 6개가 나갔다

`check()` 가 이력 전량을 **두 번** 읽고, 수여 목록을 **세 번째로** 또 읽고 있었다.

| 수여 목록 재조회 | 방금 준 것을 반영하려고 | 무엇을 줬는지 이미 알고 있다. 메모리에서 얹는다 |

### 9-2. 고양이 조건이 무조건 가정 전체를 훑었다

`_family_week_completed` 는 가정 구성원 수만큼 쿼리가 는다. 그런데 매 체크마다 무조건 돌고 있었다. 두 갈래를 앞에 세웠다.

- 이미 고양이를 받았으면 답은 정해져 있다
- **내 주가 아직 안 닫혔으면** 무조건 거짓이다 — "온 가족" 에는 나도 들어간다

주중 대부분의 체크가 두 번째 갈래로 빠진다.

### 9-3. 세션에 안 붙은 ORM 객체를 응답에 섞고 있었다

9-1 을 고치면서 방금 준 동물을 `ChallengeAward(...)` 로 만들어 목록에 얹었다. 지금은 커밋이 그 앞에 있어 안전하지만, **커밋 위치가 바뀌면 autoflush 가 그것을 저장 대상으로 본다** — 중복 삽입이 조용히 날 자리다. `animal_id -> 받은 날` 맵으로 좁혀 그 여지를 없앴다.

### 9-4. 프런트가 체크마다 왕복을 두 번 했다

응답에 갱신된 정원이 통째로 실려 오는데 곧바로 재조회를 걸고 있었다. 체크 표시는 방금 무엇을 눌렀는지 알고 있으므로 그 자리에서 뒤집는다. 대시보드 카드가 같은 캐시 키를 보므로 재조회는 두 화면을 동시에 흔들기까지 했다.

가정 화면은 남의 점수도 바뀌었을 수 있어 재조회를 남겼다.

### 9-5. 쓰기 경로에 레이트리밋이 없었다

조회는 싸지만 `POST /checks` 는 쓰기다. 예측·판정 라우터가 이미 계정별 고정창 제한을 쓰고 있어 같은 방식으로 붙였다(`CHALLENGE_CHECK_RATE_LIMIT` 분당 60). 해제도 같은 창을 쓴다 — 켰다 껐다를 반복하면 쓰기 비용은 똑같이 든다.

### 9-6. 라우트가 전부 정적 임포트였다

페이지 일곱이 한 청크에 뭉쳐 있어서 **홈만 보는 사용자도 판정 폼 36필드와 개발용 화면까지 받아 갔다.** 홈만 즉시 로드하고 나머지를 `lazy` 로 쪼갰다. `RootLayout` 의 `<Outlet />` 을 `Suspense` 로 감쌌다.

## 10. 3차 점검 — 2026-08-26

§9 이후 아직 안 본 곳을 팠다. 셋을 고쳤고, 하나는 챌린지 밖에서 나왔다.

### 10-1. `alembic check` 가 실패한다 — 그런데 코드 문제가 아니다

모델과 마이그레이션의 드리프트를 검사했다. **챌린지 테이블은 한 줄도 안 나온다** — 손으로 쓴 마이그레이션이 모델과 정확히 일치한다.

대신 `profile_links` 와 `family_invitations` 에서 잔뜩 나왔다. 원인을 가르려고 깨끗한 DB 를 만들어 마이그레이션을 처음부터 돌려 봤다.

```
개발 DB(ai_health)   alembic check  →  FAILED, 11개 작업 감지
새 DB(drift_probe)   alembic check  →  No new upgrade operations detected.
```

**코드는 완전히 일관된다. 개발 볼륨이 낡았다.** 지금 DB 에 있는 인덱스는 `ix_profile_links_account_status` · `uq_profile_links_one_active_account_per_profile` 인데, 현재 마이그레이션 파일은 `ix_profile_links_account_id` · `uq_profile_links_active_household_account` 를 만든다. 볼륨이 그 파일의 **옛 버전**으로 만들어졌고 `alembic_version` 만 앞으로 스탬프돼 있다.

**그냥 두면 안 되는 이유가 있다.** 두 서비스가 제약 이름으로 분기한다.

| 파일 | 분기하는 이름 | 개발 DB 에 있나 |
|---|---|---|
| `services/profile_links.py:73` | `uq_profile_links_active_household_account` | **없다** |
| `services/family_invitations.py:98` | `uq_family_invitations_profile_ref_lifetime` | **없다** |

그래서 개발 환경에서 계정 충돌이 나면 `ProfileLinkAccountConflictError` 대신 `ProfileRefAlreadyClaimedError` 로 폴백한다 — **사용자에게 틀린 오류 코드가 나간다.** 새로 배포한 환경에서는 정상이다.

고치는 방법은 개발 DB 볼륨을 다시 만드는 것뿐인데 **개발 데이터가 날아가므로 팀 결정이다.** §11 에 올린다.

### 10-2. 서로 다른 항목을 연타하면 응답 순서가 뒤집힌다

진행 중인 항목만 잠그고 있어서, 걸음을 누르고 곧바로 운동을 누르면 두 요청이 동시에 난다. 늦게 도착한 응답이 먼저 계산된 정원으로 캐시를 덮으면 점수가 한 칸 뒤처진다. 체크 한 번이 13 ms 라 **전부 잠가도 눈에 안 띄고** 순서가 보장된다. 검사로 못 박았다.

### 10-3. 탭을 켜 둔 채 자정을 넘기면 표시와 기록이 갈린다

화면은 어제를 보고 있는데 서버는 오늘로 기록한다. 그대로 기우면 어제 목록에 오늘 체크가 얹힌다. 응답의 `checked_on` 이 화면의 날짜와 다르면 캐시를 기우지 않고 다시 받는다.

**이 수정을 처음에 틀리게 짰고 검사가 잡았다.** `setQueryData` 의 updater 가 `undefined` 를 돌려주면 TanStack v5 는 캐시를 지우는 게 아니라 **갱신을 건너뛴다.** 안에서 거르니 어제 목록이 그대로 남았다. 날짜 비교를 밖으로 뺐다.

## 11. 사용해 보고 나온 것 셋 — 2026-08-26 4차

실제로 화면을 써 본 피드백이다. 하나는 진짜 버그였다.

### 11-1. 체크를 눌러도 아무 일이 없었다 — 세션 만료가 안 보였다

**증상.** 화면은 멀쩡히 뜨는데 체크박스를 눌러도 반응이 없다.

**원인.** 서버 로그가 답을 줬다. 08:14:50~57 사이에 `POST /auth/refresh → 401` 이 **네 번** 찍혔고 그 사이에 `POST /challenges/checks` 가 **하나도 없다.**

```
08:14:50  POST /api/v1/auth/refresh  401
08:14:53  POST /api/v1/auth/refresh  401
08:14:55  POST /api/v1/auth/refresh  401
08:14:57  POST /api/v1/auth/refresh  401
```

세션이 끊긴 상태였다. 클라이언트는 인증 요청 전에 액세스 토큰이 없으면 먼저 `refresh()` 를 부르는데, 리프레시 쿠키도 만료돼서 401 이 나고 **체크 요청 자체가 나가지 않았다.** 네 번 클릭 = 네 번의 실패한 갱신이다.

**왜 안 보였나.** 실패는 처리되고 있었다. 다만 `<p class="challenge-error">` 한 줄로 **1487 px 짜리 페이지 맨 아래**에 그려져서 화면 밖이었다. 캐시된 조회 결과가 위쪽을 멀쩡하게 채우고 있으니 살아 있는 화면으로 보인다.

**고친 것.** 401 을 따로 갈라내 **페이지 맨 위에 배너**로 띄우고 로그인 화면으로 보낸다. 그 외 실패는 기존 문구를 유지한다.

> **로그인이 만료됐습니다.** 다시 로그인하면 방금 누른 체크부터 이어서 기록됩니다.  〔로그인하러 가기〕

**교훈 하나.** 오류를 "처리했다" 와 "사용자가 봤다" 는 다른 일이다. 긴 페이지에서 하단 문구는 없는 것과 같다.

### 11-2. 리더보드가 아예 안 보였다

구성원이 둘 이상일 때만 그리고 있었다. 혼자 쓰는 사용자에게는 **기능이 있다는 사실조차 안 보인다.** 빈 카드를 피하려던 것이 기능을 숨겨 버렸다.

이제 **항상 보인다.** 가정이 없으면 "가정 만들고 초대하기", 혼자면 자기 줄을 보여 주고 "가족 초대하기" 를 붙인다.

### 11-3. 이번 주가 숫자 한 줄뿐이었다

`물 0/5일 · 측정 0/1회` 로는 어느 날을 빠뜨렸는지 알 수 없다. 월~일 일곱 칸 달력을 넣었다.

| 상태 | 색 | 언제 |
|---|---|---|
| 물을 준 날 | 초록 | 4/4 완료 |
| 일부만 한 날 | 노랑기 | 1~3개 |
| 못 한 날 | 붉은기 | 지나간 날, 0개 |
| **오늘** | 노란 테두리 2px | 실시간 판정 |
| 아직 오지 않은 날 | 무색 | — |

**"아직 오지 않은 날" 을 "못 한 날" 과 갈라 칠하는 것이 중요하다.** 목요일에 금·토·일이 빨갛게 보이면 하지도 않은 날을 실패로 세는 셈이 된다. 검사로 못 박았다.

칸마다 체크 개수를 점으로 보여 주고, 측정한 날에는 ◆ 를 붙인다. **색만으로 뜻을 전달하지 않도록** `aria-label` 에 "월요일 24일, 물을 준 날, 4/4 완료, 측정함" 처럼 말로도 적었다 — DESIGN.md 접근성 강령이 요구하는 것이고, 주 사용자가 30~60대다.

서버는 `week.days` 로 사실만 낸다(날짜·요일·체크 수·물·측정·오늘·미래). **색은 화면이 정한다.**

### 붉은색에 대해 한 가지

§1 에서 "시들지 않는다 · 벌칙 문구를 쓰지 않는다" 로 잡았는데, 못 한 날을 붉게 칠하는 것은 그 결의 반대편에 있다. 요청대로 넣었고 채도를 낮춰 경고가 아니라 기록으로 읽히게 했다. 더 부드럽게 가려면 **붉은기 대신 회색**으로 두고 초록·노랑만 쓰는 변형이 있다 — `styles.css` 의 `.week-day.is-missed` 한 블록만 바꾸면 된다.
