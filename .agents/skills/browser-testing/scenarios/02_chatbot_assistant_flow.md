# 시나리오 02: 봄이 건강비서 플로팅 위젯 대화 & API 호출 감사

```gherkin
Feature: 봄이 건강비서 플로팅 런처, 대화 인터랙션, 스켈레톤 UI 및 API 호출수 감사

  Scenario: 비서 런처를 클릭하여 팝오버를 열고 질문을 전송했을 때 API 중복 호출 없이 정상 응답하는지 확인한다
    Given 사용자가 "http://127.0.0.1/" 홈 화면에 접속해 있다
    
    # 1. 플로팅 런처 클릭 및 반응성 검증 (데드 클릭 방지)
    When 화면 우하단의 "봄이 건강비서" 런처 플로팅 버튼(ID 또는 클래스 ".bom-chat-launcher")을 클릭한다
    Then 300ms 이내에 비서 팝오버 창이 부드럽게 열려야 한다
    And 팝오버 헤더에 "봄이 건강비서" 타이틀과 닫기 버튼이 렌더링되어야 한다

    # 2. 메시지 전송 & 스켈레톤 로딩 감사
    When 채팅 입력창에 "오늘 야외 운동하기에 미세먼지랑 날씨 어때?" 를 입력하고 전송 버튼(또는 Enter)을 누른다
    Then 즉시 전송 버튼이 비활성화되거나 중복 클릭이 방지되어야 한다
    And 입력 직후 메시지 목록 하단에 스켈레톤 로딩 UI("<ChatLoadingSkeleton />" 또는 ".chat-skeleton")가 렌더링되어야 한다

    # 3. 네트워크 감사 (오버페칭 방지)
    Then 백엔드 채팅 엔드포인트("/api/v1/health-assistant/chat" 또는 동등 경로)로 요청이 정확히 1회만 발생해야 한다
    And 동일한 질문에 대해 2회 이상 중복 API 요청이 발생하면 안 된다
    And 응답 상태 코드가 200 OK 여야 한다
    And 응답 헤더에 "X-Request-ID" 추적 ID가 포함되어야 한다

    # 4. 답변 렌더링 및 콘솔 감사
    Then 10초 이내에 스켈레톤이 사라지고 최종 답변 말풍선이 렌더링되어야 한다
    And 답변 말풍선에 날씨/미세먼지/공기질 관련 내용이 포함되어야 한다
    And 전체 대화 흐름 중 콘솔 에러(console.error)가 0건이어야 한다

    # 5. 최종 증적 수집
    Then 답변이 완료된 팝오버 상태의 스크린샷을 캡처한다
```
